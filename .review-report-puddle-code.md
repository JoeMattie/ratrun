## Decisions

1. **Pen choice.** I could not edit `render/lighting/*`, so I used the existing `render::lighting::pool_pen()` — `MaterialKind::Water`, the same tag acid pools wear, i.e. the wet-floor material with the strongest env reflection (`gloss 160, env 200`). That is what makes a lamp reflect in a puddle.
2. **Puddles are not clipped to the floor.** A blob's rim spills over wall cells on purpose: the wall layers are drawn *after* the water, so a big Sewer blob reads as water running along a corridor. Consequence, stated plainly: a rim can overlap a trap pad or a door face even though the **centre** (the contract's rule) never can.
3. **Placement** is rejection sampling, not a shuffled cell list: no allocation per map, the draws are all on the stage's own stream, and a bounded unbiased fallback guarantees the floor's count. Bias is 4:1 to corridors/wall-adjacent cells (Sewer, Laundry) and props (Kitchen).
4. **Sizes are top-heavy in the Sewer** (64–90 × 44–60) because the count is fixed at 26–34 and the brief's ~18 % wet area can only come from size. *I could not measure it* — `cargo test puddle_coverage_by_theme -- --ignored --nocapture` prints the real table; if the Sewer lands short, raise `ry`'s ceiling to 60 everywhere (it is already there) or the count band.
5. **The dash latch** is `dash_splashed`, re-armed when `dash_active` returns to 0 — so one dash is one `SplashBig` however long it stays in water and however many puddles it crosses, and the *next* dash can splash again. Entering water while dashing gives the big slosh only (not a second small one).
6. **Ground bodies** for the horde's rings = the roster's slot B (the floor's flying fodder) and the `MurderHornet` archetype excluded; everything else counts. Keyed by `SpawnId` order in a 6-slot table in the resource (no component), and a slot that changes owner starts with a fresh clock.
7. **Library FIELD GUIDE: not added.** A `Key` row is *not* small here: `ObjectKind::Puddle` would need the variant + `ALL` + 8 further match arms (`library.rs` ×4, `render/library.rs`, `render/library/scene.rs`, plus the survey hook that discovers an `Object` by sight), and two of those are render files another worker is in. Left alone, per the task's own instruction.
8. **Bot/fog/minimap:** nothing to do — puddles are not tiles and are read by no navigation, sight or bot code.

## Goldens and the map pin

* **The map pin cannot move and does not need regenerating.** `map_hash` folds every tile (kind + neighbour mask) and every entry of `LevelObjects`; `Level::puddles` is not in it. The stage is also last and on a salted stream, so no earlier draw moves. `puddles_leave_the_tiles_and_objects_alone` asserts the tile grid and the object lists are identical with and without the stage's output.
* **The determinism goldens must not move.** `harness::fold_state` folds `elapsed`, the rat's position/velocity/hp/timers/level/xp, kills, score, entity counts (enemies/bullets/gems/pickups/pools/particles/damage numbers) and a per-enemy hash. It does **not** fold `SfxQueue` and knows nothing about `PuddleSteps`. The system draws no rng, spawns/despawns nothing, writes no simulated number and does not slow the rat, so no row should move. `puddle_steps_change_no_simulated_state` proves it directly (same seed with and without the level's puddles → identical rat, counters and rng stream).
* **If a golden row does move**, the only candidate is that something now reads `SfxQueue` or the resource into a simulated value — it does not exist in my diff; treat a moved row as a real bug, not a regeneration.
