# CLAUDE.md

Guidance for coding agents working in this repository: the architecture, the commands, the rules that bind every change, and how to test. Where this file and the code disagree, **trust the code** and fix this file.

Rat Run is a terminal **bullet-hell horde survivor** (Vampire-Survivors-shaped) in Rust on `ratatui`. The player only moves; weapons auto-fire; kills drop XP that pays a 1-of-3 upgrade loop; a floor builds from a fifteen-minute difficulty curve into a boss fight. The simulation is a `bevy_ecs` world behind a `World` facade; the world is drawn into a half-block pixel buffer, lit in 2D, and composited under ratatui HUDs and menus. Read `STYLE.md` before writing any player-visible string.

## Commands

```sh
cargo run --release                 # play (needs a real TTY)
cargo run --release -- --ai 16      # wall of 16 self-playing games
cargo run --release -- --testbed --floor sewer   # interactive testbed (floor defaults to sewer)
cargo run --release -- --bot-batch 30 --seed 1000 --json > batch.json
cargo run --release -- --tuning-dump defaults.toml
cargo run --release -- --tuning defaults.toml
cargo build
cargo test                          # full suite (see Testing strategy)
cargo test <name>
cargo clippy --all-targets          # lint (keep clean)
cargo run --release -- --caps       # resolved terminal caps, then exit
cargo run --release -- --probe      # caps + this terminal's keyboard-protocol answer
cargo run --release -- --glyph-card # test card: half / quadrant / sextant / octant blocks, then exit
cargo run --release -- --prof-bench --color truecolor --floor sewer --at 300 \
    --mode app --cfg 120x40:1.0:full:600   # dev only: headless frame-cost benchmark
cargo run --release -- --music-render sewer 60 /tmp/sewer.wav --intensity 3   # dev only: a floor's song as a WAV
```

**Profiling (dev only):** `--prof-bench` (`src/profbench.rs`, stage timers in `src/prof.rs`) plays one floor forward with the bot and prints one JSON line per `--cfg COLSxROWS:ZOOM:TIER:FRAMES`. `--mode direct` times `World::draw` stage by stage and prints a `frame_hash` of every pixel (the proof that a render change is bit-identical); `--mode app` runs the real update/render/present path against a counting sink (frame p50, present cost, bytes and `write` calls per frame); `--mode title` / `--mode paused` measure the idle screens; `--mode encode` and `--mode audio` are micro-benchmarks. `--still`, `--horde N`, `--nolight` and `--sample FILE:SECS` shape a run. The stage scopes cost one relaxed atomic load when the bench is off. `RATRUN_PROF_NO_AUDIO=1` keeps a PTY harness from opening an audio device. Not a player-facing flag: it never touches the terminal or the save.

**Toolchain:** `rust-toolchain.toml` pins `1.100.0` (`bevy_ecs` 0.20 declares `rust-version = 1.95` and the machine default is older). rustup installs it on demand — never touch the global default.

**Build prerequisites:** `rodio`/`cpal` link ALSA, so Linux needs `libasound2-dev` (the runtime `libasound.so.2` alone is not enough). The default `gamepad` feature pulls `gilrs`, which links `libudev` on Linux (`libudev-dev`); `--no-default-features` builds without gamepad *and* without the console.

**Features** (`Cargo.toml`): `default = ["console", "gamepad"]`. `console` is the backtick admin console (also switchable off at runtime with `RATRUN_CONSOLE=0`).

## Web build

`src/web.rs` hosts the same App, simulation and frame pacer in Wasm.
`web/game.js` supplies keyboard, pointer, focus and resize events through a
60 Hz animation loop. Rust packs changed cells for the two canvas layers
in `web/canvas.js`, which draw block art and text. The browser stores the save
in local storage and starts Web Audio on a key press or click. The shipped
web build uses default balance tuning and omits tuning files, native terminal
setup, worker threads, the spectator wall, bot batch, gamepad and the console.

```sh
rustup target add wasm32-unknown-unknown
cargo clippy --locked --target wasm32-unknown-unknown --no-default-features --features web -- -D warnings
./web/build.sh
python3 -m http.server 8000 --directory web/dist
```

Smoke-test a run with movement, zoom, resize and focus changes. For browser
regression checks, append `?debug-frames` and use `window.ratrunDebugFrame` to
compare the canvas with the intended cells. Collect frame timings with
`?profile=full` and `window.ratrunProfile()`.

## Worker rules (this repo, all agents)

- **No compiling and no running.** Feature workers do not build, test, clippy, fmt or run the game. The coordinator or a designated integration worker merges and verifies the batch in the integration checkout. Write the code and the tests you would have run, and report what is unverified.
- **Integration builds bump the patch version.** Every integration build bumps the third octet of `version` in `Cargo.toml` (`0.4.3` → `0.4.4` → …; `render::BUILD_VERSION` shows `env!("CARGO_PKG_VERSION")` in the top-left corner of every screen), moves the `Unreleased` entries in `CHANGELOG.md` under `## <version> (<YYYY-MM-DD>, playtest build)` with a fresh empty `## Unreleased` above, names that build number in its commit message and report, and installs the built release executable as `/Users/joe/dev/ratrun/target/playtest/ratrun`. Releases are tagged or published only when the owner asks.
- **Finished workers are cleared from Orca.** Subtasks are deleted once they report, so do not leave work un-reported and do not start new work after reporting.

## Architecture

`main.rs` selects the native or web host. Both drive `app.rs` (state machine) → `game/world.rs` (facade) → `game/ecs/` (one chained schedule) → `render/` (pixels, HUD).

| path | owns |
| --- | --- |
| `main.rs`, `native.rs` | entry point, terminal lifecycle, input thread, native frame loop |
| `web.rs`, `web/` | browser input, animation loop, canvas presentation |
| `app.rs` | screen state machine, run/overlay state, audio bridge |
| `present.rs` | the frame writer, the cell diff + escape encoder, frame pacing |
| `term.rs` | capability detection, colour folding, glyph sanitising |
| `prof.rs`, `profbench.rs` | dev-only stage timers and the `--prof-bench` harness |
| `input.rs`, `controls.rs`, `gamepad.rs` | keys → actions, remapping, pad |
| `scores.rs`, `meta.rs`, `config.rs` | save file, the nest, data paths |
| `lore.rs`, `titleart.rs`, `console.rs` | story text, the rat plate, admin console |
| `audio.rs` | procedural SFX, the classic music synth, the engine |
| `music/` | the seven hand-arranged floor songs, `SongSynth`, `--music-render` |
| `autoplay/`, `spectate.rs` | bot, batch runner, `--ai` wall |
| `game/world.rs` | facade: fields, one tick, one frame |
| `game/ecs/` | schedules, resources, components, `systems/`, behaviour tests |
| `game/levelgen/` | the map generator and its validator |
| `game/` (rest) | data + rules: `level`, `enemy`, `weapon`, `loadout`, `director`, `shop`, `campaign`, `library`, `bot`, `nav`, `collision`, `fog`, `hazards`, `particle`, `smoke`, `vfx`, `art_*` |
| `render/` | framebuffer, lighting, HUD, menus, minimap, overlays, ink |

- **`native.rs`** enables raw mode first (then arms a `TerminalGuard` drop guard), enters the alternate screen with mouse capture + focus reporting, asks the terminal for its keyboard protocol (`term::query_keyboard_enhancement`, a 300 ms budget; crossterm's own helper waits 2 s), pushes `REPORT_EVENT_TYPES | REPORT_ALL_KEYS_AS_ESCAPE_CODES` when it answers, and re-queries to learn whether a **lone** Ctrl reports (that decides Ctrl-dash vs Space-dash). It reads crossterm events on a joined reader thread, coalesces mouse motion, caps work at `MAX_EVENTS_PER_FRAME`, computes `dt` (capped at 50 ms), calls `app.update(dt)` every iteration (60 Hz), and hands the frame to `present::FrameLoop`, which presents inside a DEC 2026 synchronized update. `FocusLost` releases every held key. Restore is idempotent and runs on every exit path including panics. On Windows, setup disables line wrap in the alternate screen so filling the bottom-right cell cannot scroll the frame. Restore re-enables wrap before leaving that screen.
- **`present.rs`** owns everything between a rendered `Buffer` and the terminal:
  - `FrameOut` — the backend's writer. A frame is collected in memory and sent in **one** `write`; it never flushes on drop, so a panic mid-frame cannot spill cells onto the restored terminal. Setup and restore write straight to stdout.
  - `Presenter` — `Terminal::draw` taken apart. It owns the previous frame, so an unchanged frame sends **zero bytes**, and `invalidate()` (focus regained) or a new size clears and repaints everything. `PresentMode::Direct` (the default) diffs the two buffers in one pass and writes cursor moves, SGR and glyph bytes by hand — a run of adjacent cells in the same colours is one move and one SGR; `RATRUN_PRESENT=ratatui` (and `NO_COLOR`, which crossterm honours) selects ratatui's `Buffer::diff` + crossterm's `Backend::draw` instead. A frame holding a wide glyph or a cell with a diff option goes through ratatui's diff (its trailing-cell rules) with the direct encoder. The two paths are pinned equal by `present::tests::a_scripted_session_looks_the_same_through_both_paths_at_every_colour_depth`, which replays both byte streams into a small VT cell model across play, pause, level-up, map, options, console and resizes at truecolor, 256 and 16 colours. The presenter runs **after** `term::sanitize`, so colour folding stays in `term.rs`.
  - `FramePacer` — whether to render at all. `Screen::Playing` renders every frame (`App::frame_demand`). Every other screen renders at 30 Hz, and at once when `App::repaint_urgent` says so (any input event incl. pointer motion and pad, a resize, focus, a screen change, an open console, the zoom ease, the volume/zoom read-outs, auto-pick spacing). A screen whose last 45 rendered frames changed no cell is treated as still and only probed every 250 ms; a probe that changes a cell returns it to 30 Hz. So stillness is measured, not declared per screen — but **a new animation on a menu screen that can start without input after 1.5 s of stillness should be added to `repaint_urgent`**, or it starts up to 250 ms late.
  - `SizePoll` — the terminal's size is asked for on `Event::Resize` and once a second, not every frame (`crossterm::terminal::size` opens `/dev/tty`).
  - The `--ai` wall keeps `present::synchronized_frame` (ratatui's own draw through `FrameOut`).
- **`app.rs`** is the only module that knows about screens. The real `Screen` enum: `Title`, `SectorSelect`, `Story`, `MapIntro`, `LevelIntro`, `Playing`, `LevelUp`, `Paused`, `Options`, `LevelComplete`, `KeepThree`, `Victory`, `End`, `Chest`, `Shop`, `Library`, `Controls`, `Graphics`, `Nest`. The six title rows are START RUN, the sector row, OPTIONS, LIBRARY, THE NEST and QUIT. It drives the world during `Playing`, freezes it under overlays (an open map pauses too), owns menu/level-up/shop/keep state, finalizes scores, banks the nest and bridges audio.
- **`game/world.rs`** keeps the legacy public fields as real fields (`player`, `level`, `elapsed`, `kills`, `score`, `gold`, `pending_levelups`, `pending_chests`, `pending_shop`, `game_over`, `won`, `level_complete`, `sfx`, `rng`, `cam`, `viewport`, `particles`, `damage_numbers`, `fog`, …) so callers between ticks keep working, plus read-only HUD accessors (`boss_hp`, `boss_offset`, `enemy_count`, `last_pickups`) that walk the ECS world for `&self`, and allocating `SpawnId`-ordered snapshots (`enemies()`, `bullets()`, `gems()`, `pickups()`, `pools()`) for tests only. `update()` runs one tick; `draw(&mut PixelBuffer)` runs one frame.

### The facade round-trip (`game/ecs/resources.rs`)

Singleton state is authoritative on `World` *between* ticks and in the ECS world *during* one:

1. `begin_tick` inserts the per-tick resources (`TickInput` — `dt`, `move_dir`, `dash`, `active`, `aim`, the dash hold edges `dash_down`/`dash_held`/`dash_released` and a scripted `charge` —, `Viewport`, `NukeTick`, `LevelIndex`, `DifficultyLevel`, `DebugFlags`, `Cvars`, `BossOverride`, `RunCounters`, `Shake`, `SfxQueue`, `NextEnemyId`, `LastPickups`) and **moves** `rng` (via `RngRes`), `level`, `player`, `particles`, `damage_numbers`, `director`, `flow` and `fog` in with `swap_in`. Every round-tripped type has a spare twin built at `World::new`, so the round trip allocates nothing.
2. `schedule.run(&mut world.ecs)` — one thread, one chain.
3. `end_tick` swaps them back with `swap_out` and copies the counters out.

Nothing is copied out per tick: entity components live in the ECS world for the whole run, so `Entity`/`SpawnId` are stable. Writes between ticks (`world.player.hp = …`, `world.pending_levelups = 1`, app tests) reach the next tick, and reads right after `update()` see its results. `begin_tick`/`end_tick` are public — that *is* the per-system test harness. Never touch a facade singleton while a tick is open; use `world.ecs.resource_mut::<T>()`.

### Components and resources

- Components are **coarse**: one legacy struct per component (`Enemy`, `Bullet`, `Gem`, `Pickup`, `Gold`, `Chest`, `Pool`, `Boss`) plus `SpawnId(u64)`, a monotonic spawn-order tag, and wave-3/4 markers (`Miniboss`, `Infection`, `Wick`, `AcidDrop`, `MilkTooth`, `CheeseString`, `FairyRing`, `CorrosiveChannel`, `DeadLetterPacket`, `EchoSpoke`, `Lash`, `TrapSlow`, `InkSlow`, … — see `game/ecs/components.rs`). Do **not** split them into Position/Health: art and behaviour take `&Enemy` and friends.
- Resources are the per-tick singletons above plus permanent scratch (`NextSpawnId`, `SpatialGrid`, `EnemyIndex`, `GridScratch`, `NeighborScratch`, `PickupScratch`, `DamageLedger`, `ActiveFx`, `LaserFx`, `LaserCopy`, `DashTrack`, `EvoRuntime`, `MeleeNudge`, `XpBank`, `BossDue`, `BossVirus`) and the wave-3 runtimes (`TrapRuntime`, `GateRuntime`, `MinibossSchedule`, `ShopBook`, …).
- `EnemyIndex` caches the `SpawnId`-ordered enemy list the spatial grid's buckets address (the legacy `self.enemies[j]`). It is valid only while no enemy has spawned or despawned since the grid was built; every reader calls `resources::debug_assert_enemy_index` (compiled out in release). See *Determinism*.
- `Enemy::id` (damage-number identity) comes from `NextEnemyId`, never a `Vec` index. Systems push `Sfx` into `SfxQueue`; **there is no audio system** — the App drains and plays.
- Systems spawn with `commands.spawn((component, next_id.take()))` and despawn with `commands.entity(e).despawn()`. `World::spawn_*`/`clear_*` are for tests and setup only.

### The tick schedule — order *is* behaviour (`game/ecs/schedule.rs`)

ONE `Schedule`, one thread, `multi_threaded` off. `chain()` inserts `ApplyDeferred` after any system that took `Commands`, so an entity spawned by one system exists for the next. The real order (the module doc carries the full table):

```text
powerups → traps → hazards → floor_sewer_slow → player → outfall_motion → record_rat_track → puddles → fog::reveal
  → [gates: passage, cache, door, shop::threshold]
  → flow_refresh → director → sewer_opening → outfall_snuff → miniboss → boss_spawn → boss::megarat::boss_summon
  → crab::spawn_crabs → enemy_steering → enemy_fire → grid_build → separation (`enemies.separation_passes`)
  → wall_resolve → [separation_after_walls + wall re-eject] → grid_refresh → fire_weapons → active_weapons
  → [spiked_tail] → [laser_eyes, super_dash, melee_nudge]
  → acid_rain → lava → [glass_bead, plumb_bob] → droppings → hantavirus → bullets → pools
  → boss_damage → boss_update → lantern_gape → [cobra::coil_block]
  → player_bullet_hits → enemy_bullet_hits → contact
  → [giant_stomp, milk_teeth, fondue_tines, fondue_string] → fairy_ring → drain_cleaner
  → roll_call → dead_letter → ripcord → wave3 → wave4
  → [floor_sewer, drake, crab, floor_kitchen, floor_lab, floor_laundry, floor_printworks, floor_flatbed, floor_outfall]
  → approach_sfx → trailer → outfall_falls
  → hantavirus_death → reap_enemies → gems → gem_merge → treasure → pickups
  → nuke_reap → particles → damage_numbers → shake → outcome
```

Load-bearing adjacencies (each is commented in the file):

- `separation` plays `[enemies] separation_passes` (3 shipped) passes over the grid built this tick, each starting where the previous one left and each clamping one body's nudge to `separation_max_push_px` (10 shipped). Every pass is swept: a body's shove is anchored at its own pre-pass position and refused if the straight path would take its centre across a wall face (`shove_crosses_wall`), so no pass can push a body through a wall — the sweep runs when `separation_passes > 1` or the clamp is above 6 px, so the legacy triple below stays bit-for-bit. `separation_after_walls` (on) runs one more swept pass after `wall_resolve` and re-ejects just the bodies it moved (the graze such a shove can still leave). `separation_passes = 1` with `separation_max_push_px = 6.0` and `separation_after_walls = false` is the old single-pass crowd exactly. Nothing spawns or despawns in any of them, so the `EnemyIndex` window is unchanged and `grid_refresh` still runs last.
- `traps`/`hazards` run **before** `player` so a glue/ink slow folds into this tick's `TickInput` throttle, and their damage lands before the reap (a trap kill takes the normal loot path).
- `outfall_motion` recovers the rat and applies the surge after `player`. It releases Congers before the director and grid. `record_rat_track` then samples the post-move position into `RatTrack`, a permanent two-second ring buffer at 30 Hz. Wake freezes a recent path at the tell lock. Drip takes three positions across the tracking half. The recorder draws no rng.
- `gates`/`shop::threshold` sit after the fog reveal and before the flow refresh, so all three see the rat's post-move cell.
- `outfall_snuff` resolves the elite-held fixture before a named attack locks. `lantern_gape` moves only the rat and gems after the boss update. `outfall_falls` resolves body and loot crossings after spatial grid readers and before death jumps and loot.
- Boss spawns are before `grid_build`; `megarat::boss_summon` exists because a boss controller cannot take `Commands` and may only add `Enemy`s in that slot.
- Every weapon/melee/area damage pass sits between `grid_build` and `reap_enemies`, so a kill this tick is reaped this tick (and loots this tick).
- The seven per-floor roster systems (`systems/floor_<floor>.rs`, one per `Theme`, each a no-op off its own floor) run right after `wave4`, then `approach::approach_sfx_system` (writes only `SfxQueue`); `floor_sewer_slow` sits with `hazards` before `player` so the Sump Leech's tongue slow folds into this tick's throttle. Their tells are drawn on the hostile layer from the same geometry the hit tests read (`World::floor_tell_reach`/`draw_floor_tell`, `art_roster_*.rs`).
- `powerups::giant_stomp_system` (the Growth Serum) heads the nested chain right after `contact`: a body touching the giant is stomped on the same tick, before every evolved-weapon pass, the Hantavirus death jump and the reap, so a crushed body jumps, is reaped and loots this tick. It spawns nothing and draws no rng.
- `reap_enemies` right before `gems` (drops collect the same tick); `pickups` right before `nuke_reap` (a Nuke re-reaps); `outcome` last (loss beats win).
- `gem_merge` follows `gems` so collected drops are gone and magnetized gems are protected. Every 2 s it combines gems in 96 px cells beyond 1.5 times the widest view's half-diagonal. Above 400 live gems it also checks the farthest cells each tick. A merge keeps the oldest `SpawnId`, adds the XP with saturation and moves the survivor to the XP-weighted centre. This can move a scripted run's trace when two gems in that run are left far enough away to merge, or when their new position changes later pickups. It draws no rng and leaves level generation alone.
- The chain is split into several tuples only because `IntoScheduleConfigs` stops at 20 entries; later groups are explicitly anchored `.after(...)`. Keep the module-doc order map in sync.
- `build_settle_schedule()` is the legacy `finished()` path: particles and damage numbers only. `damage_numbers_system` lives in `schedule.rs` because that file owns tick order.

## Determinism rules

Single-threaded, and **query iteration order must never decide anything**. Wherever the old code meant "first / next / in-`Vec`-order", iterate sorted by `SpawnId`:

```rust
for (id, mut e) in enemies.iter_mut().sort_by_key::<&SpawnId, _>(|id| id.0) { … }
```

That covers nearest-enemy ties, separation nudges, per-enemy rng draws, drop order, bullet spawn order and draw order. The **number and order of rng draws** are part of the spec: draw only where the old code drew. A boss owns its own stream (`BossRng`, seeded from the run seed + a per-kind salt) so boss behaviour never perturbs the main one; the shop rolls its shelf from its own `StdRng`, never the simulation's.

**The simulation viewport is App state, not a render side effect.** `App::render` writes `world.viewport` on a resize because the viewport drives spawn rings and offscreen placement; `World::draw` never touches it (it sets its own `render_viewport`). So a run drawn at a resized terminal — or at any zoom, or never drawn at all — simulates identically; pinned by `world::zoom_tests::the_same_seed_plays_out_identically_at_every_zoom`. Everything render-only (zoom, lighting, smoke, fog reveal, the ink pass, the Library survey) must stay render-only.

**Spawns land out of sight at every zoom** (`systems/spawn.rs`). "Out of sight" is the **widest** view: the simulation viewport × `MAX_ZOOM_OUT` (2.0, a plain number pinned equal to `render::zoom::MAX`; the current zoom is never read, so every zoom still simulates identically). The ring is that view's half-diagonal + 16 px (157 px at 120×74, 195 px at 160×80; it was 120), and `off_screen`, the flank members, the room waves and the miniboss arrival all test the same rectangle. `sample_ring` is a fixed four-pass ladder (ring → 1.5× outward → the 1.0-view ring → any legal ring point), then a staging room outside the 1.0 view, any staging room, the nearest clear cell, and finally a skip; `SpawnScratch::fallbacks` counts the rungs. Measured in bot play (six floors × two viewports, 4 min each): 57 % of placements were inside the 2× view before, 0 of 5,870 after (5 through the arena-clamped camera, on a large terminal near a map edge), no skips. **The approach boost** pays the longer walk back: an ordinary body outside the *unzoomed* view moves at `APPROACH_BOOST_GROUND` ×2.0 (flyers ×1.3; never a named body, an elite, or a kind at ≥ 40 px/s) and is restored to exactly its spawn scale on entering it (`Director::approach` is the registry; no rng). **The opening pulse** is ×0.7 the interval for the first 12 s (`director::OPENING_SECS`/`OPENING_INTERVAL_MULT`: ten single bodies instead of seven), because bodies now die further from the rat and the first card came ~3 s late. Two ignored measurement tests print the tables: `spawns_inside_the_widest_view_in_bot_play` and `opening_pace_in_bot_play` (`cargo test <name> -- --ignored --nocapture`).

**`EnemyIndex` validity window.** `enemy_move::grid_build_system` and `grid_refresh_system` build the `SpawnId`-ordered cache once per tick with the `SpatialGrid`. It may be read *instead of* sorting only while nothing has spawned or despawned since the build: `separation`, `wall_resolve`, `separation_after_walls`, `grid_refresh`, then (after the refresh) `fire_weapons`, the active, wave-3 and wave-5 weapon passes, `bullets`/`pools`, the boss passes, `player_bullet_hits`, `enemy_bullet_hits` and `contact` — nothing at or after `reap_enemies`. It is stale in `enemy_steering`/`enemy_fire` (the director may have queued spawns) and after `reap_enemies`/`nuke_reap`/`clear_enemies`. `debug_assert_enemy_index` compares the cache with a fresh `SpawnId` sort *including contents*, so `cargo test` verifies the window on every tick of a full run.

**Determinism.** There is no scripted-trace golden and no seeded replay suite: the six 60 s scripted cases that used to be played twice on every `cargo test` (and, before that, the pinned hash table they grew out of) are gone, because they cost minutes of every run and the property is covered by narrower tests. What proves the simulation is a pure function of its input now: `world::zoom_tests::the_same_seed_plays_out_identically_at_every_zoom` and `..._outfall_surge_and_lure_...` (one seed at z = 0.5/1/2 and never drawn, compared value by value), `systems::fog::tests::fog_never_moves_the_simulation` (same seed with the reveal on and off for 30 s, rng state included), the map pin for generated maps, and the narrow per-system tests — which are also where a new *number* gets pinned. The rules below still hold (`SpawnId` order, draw only where the old code drew, no hash-map iteration), and `crate::detmath` stays so a run is reproducible on every platform.

**The map pin (`game/levelgen/mod.rs` `TRACE_HASHES`).** Pins the output of `generate_once` — every tile's kind and neighbour mask plus the pinned placement records — for 20 seeds × the five legacy generated themes. Outfall has separate seed invariant tests. Regenerate only when a layout/maze/placement stage changes output on purpose: `RATRUN_LEVEL_TRACE=1 cargo test map_trace_pin -- --nocapture` prints the new table.

## Rendering

`render/framebuffer.rs`: `PixelBuffer` is a `width × (height*2)` RGB grid, blitted into ratatui one `▀` per cell (foreground = top pixel, background = bottom). World coordinates are world-pixel `Vec2`; `world.cam` + `w2s()` map to screen. The camera follows the rat clamped to the arena, plus a decaying shake offset, of which the camera takes `World::shake_scale` (`world::SHAKE_SCALE`, 0.65, is the default; the Graphics page's SCREEN SHAKE row sets it to 0 / 50 / 65 / 100 %). Every effect's amplitude is cut in that one place, durations are untouched, and nothing simulated reads the camera.

**`World::draw_scene` order (real):** floor → floor marks → floor stains → puddles → clothes piles → Outfall pit edges and lure bases → overhead shadows → boss ground layer → wall ground layer → boss thresholds → object ground layer → wall bodies → props → seabed plants → light fixtures + ambience → pools (including lava) → evolved ground effects (channels, fairy rings) → Acid Rain drops → gems → gold → chests → pickups (with halos) → the Wind-up Mouse decoy → enemies (crowd LOD by visible count) → boss bodies (ground) → friendly bullets → Glass Bead and Plumb Bob → lava globs and breath → cheese strings and milk teeth → the rat → airborne boss bodies → wall overhangs + thresholds + object foreground layer (lintels over the rat) → the Lantern's hull and lure → smoke → particles/shockwaves → Super Dash comb → Roll Call quotes → **the lighting pass** → Outfall surge crests → Laser Eyes bars → foreground → **the hostile layer** → (debug) hitboxes.

Sprite art lives in `game/art_*.rs`, one module per subject (`art_floor`, `art_walls`, `art_props`, `art_enemy`, `art_miniboss`, `art_traps`, `art_rat`, `art_trailer`, `art_wave3a`, `art_icons`, one `art_boss_*` per boss). **Do not edit art modules to fix gameplay**: their view structs and documented constants are the spec where art and gameplay disagree (`CONTENT_PLAN.md` §9).

**Zoom** (`render/zoom.rs`): ladder `0.5, 0.75, 1.0, 1.25, 1.5, 2.0`, eased over ~0.15 s, stepped by wheel, `Z`/`X`, the options row, or middle click/`R3` to reset. `z > 1` shows more world. Zoomed out, each screen pixel owns a box of world pixels and `PixelBuffer::resample_to` writes **one** source pixel per box, unblended — the most salient pixel if the box holds a feature, else the first — so thin things survive at full contrast instead of blurring; zoomed in the box is a single source pixel (nearest neighbour). Integer arithmetic throughout, so 1:1 is bit-identical.

**Sub-cell detail** (`render/subcell.rs`; **always on** where the terminal has the glyphs — there is no option and nothing is saved; `subcell::resolve(env, term::block_set())`). Zoomed out (eased zoom > 1.05), `World::draw` resamples the world buffer a second time onto a `2·cols × k·rows` grid and `App::draw_game` blits `World::detail()` instead of the half-block buffer: quadrants (k = 2) at 1.25×, sextants (k = 3) from 1.375×, octants (k = 4) from 1.75× — at 2× the octant grid is the world buffer 1:1. `subcell::encode` gives each cell two colours by a two-means split (integer, salient sub-pixels weighted up) and the pattern glyph between them; a cell without contrast (`FLAT_SPREAD`) is the plain `▀` it always was. The half-block picture is still drawn in full, because the damage digits and the ink pass stamp it: `DetailFrame::overlay` carries every pixel they changed onto the sub-pixels that half covers and flags it, so a mark is never smaller than today and its colour is exact. The pattern → glyph tables (`subcell/tables.rs`) are **generated** from Unicode character names by `subcell/gen_tables.py`; do not hand-edit them. Which set may be used is `term::BlockSet` (`--glyphs quad|sextant|octant|half`, `RATRUN_GLYPHS`, else Ghostty/Kitty/WezTerm → sextant and everything else, a multiplexer and the safe glyph set → half); `RATRUN_SUBCELL=off|quad|sextant|octant|auto` pins a set for a session (captures), and octants are only ever reached by asking. The resolved set is in `PictureKey`. Render-only.

**1× smoothing** (`subcell::Smooth { Off, Xbr, XbrCrisp }`, labels `OFF` / `SMOOTH` / `CRISP`, default `Off`; `RATRUN_SMOOTH=off|xbr|crisp`, console `smooth [off|xbr|crisp]`, Graphics `SMOOTHING` row and `S` cycling `Off → SMOOTH → CRISP`, read-only). At zoom ≤ 1.0 the sub-cell frame is built from the half-block picture. **Xbr** (`SMOOTH`; `subcell/xbr.rs`, `DetailFrame::xbr_from`) ports FFmpeg's `xbr=2` (`FILT2`) to integers: each pixel corner weighs the two diagonals over a radius-two neighbourhood (YUV distances), gated at `GATE` (6) channel difference against both adjacent neighbours, and leans toward its nearer axial neighbour; each cell's 2 × 4 blended block is fitted by two-means (`xbr::split`) onto quadrants, sextants or octants (`subcell::grid_for_frame` picks the terminal's own set while the underlying ink-carrier frame stays `Grid::Quad`), with the original `▀` winning ties and untouched cells. **XbrCrisp** (`CRISP`) reads the same filter conservatively (`EDGE` contrast test, stairs only so rectangles keep their corners, majority coverage fit in exact source colours). Both freeze isolated bright/saturated marks and 1 px strokes (`xbr::View::feature`), and `DetailFrame::overlay` carries digits and ink pass stamps exact afterwards; `xbr_sim.py` models both passes on a `RATRUN_DUMP` PPM. `App.smooth` → `World.smooth` is in `PictureKey`, and with `Off` a 1× frame is byte-identical to the plain half-block blit. Render-only.

**Lighting** (`render/lighting.rs` + `render/lighting/`): world-resolution, render-only, applied over world pixels before the resample so lights line up at every zoom. `engine` (`LightMap`, `Light`, `LightShape`, falloff, flicker, layer masks, `LightingMode`); `fixtures` (per-theme palette/housing for `LightFixture`s: Pendant, Passage, Arena, Broken, Sun, Sconce); `sources` (`LightZone`s — Corridor, Room, Start, Arena, Blackout, Maze — decide ambient and add the rat's aura and dynamic emitters); `shadow` (occluder outlines, prop height → shadow profiles, static vs moving bodies, softness); `ambience` (analytic emitters: Fire, Steam, Drip, Cable, Dust, Fog, Exhaust, Pilot, Fumes, Insects, reconstructed from `(seed, elapsed)`, never from a particle pool); `gallery`/`tests` (captures, assertions). Fixtures are placed by `game/levelgen/lights.rs` by room role; prop/pool/pickup art marks emissive rects so they stay bright. **Small lights** (`Falloff::Small`: every point light of radius ≤ 52 that is not a hard-pool theme light, the `emit` halos, Passage and Broken fixtures off the hard-pool themes, Fire/Pilot/Cable embers) keep the smooth core and add a faint tail (`TAIL_SHARE` 0.19) out to `TAIL_REACH` 1.7 × the stated radius; the tail is not flickered and is painted in flat steps of `MIN_GAIN` (7.0 `Q8.8` units, chosen by measured bytes a frame — its doc comment carries the table), so a dim halo keeps its old size and only the brighter ones throw a skirt. Every consumer of a light's size reads `Light::extent()`. The base level of every floor and zone is `AMBIENT_SCALE` 0.60 of the theme tint (never under `AMBIENT_FLOOR`), and every living enemy takes a 1 px self-lit rim glint in its own colour (`gather_rim`, at most 512 a frame) so a body cannot vanish on the darker floor. The lighting tier is fixed for the session unless the player changes it (`LightingMode::LIVE = [Full, Hard, Coarse, Compact]`, defaulted from colour depth: Truecolor→Full, Ansi256→Hard, Ansi16→Coarse, or stepped via the Graphics page / `lights` console command); per-frame dynamic light caps evict by priority and proximity with a four-slot fade skirt past the cap so lights do not pop. Lighting only shades the playfield: a distant lamp cannot reveal a route (fog and the minimap keep their own rules).

**The lighting effects** (batch 13; `render/lighting/{fx,material,upsample,air,surface,specular,softshadow,motes,overhead}.rs`, contract in `.review/handoff/lighting/CONTRACT.md`; on by default, `RATRUN_FX=0`, console `fx [on|off]`, `World::lighting_fx`). With them **off the lighting pass is byte-identical to batch 12's**. With them on the grid keeps a `fx::LightInfo` beside every sample (the dominant light's direction, colour and contribution, the specular energy, air and fog) and the composite becomes a chain of pixel stages: `surface` (bump relief from the art's own luminance, per material) → `upsample::composite` (a tone curve and a **bilinear** shade instead of 4 px blocks, never blended across a wall face; `upsample::bounce` adds coloured bounce light on the grid first) → `softshadow::entity_shadows` (bodies shadowed by the two strongest lamps that can see them) → `specular` (sheen by material and a directional rim on creatures) → `softshadow::reflections` (lamp streaks on wet floors) → `air::composite` (shafts from fixtures, a small bloom, distance fog) → `motes` (dust in beams at 8 Hz, caustics). `overhead` is rasterised in the scene draw and multiplied into the **lit** picture right after the body shadows (`overhead::draw_deferred` → `apply_lit`; Coarse still darkens the albedo in place): an elliptical ground shadow under every body from an imaginary light over the map's centre, about the body's own width, core 42 % (`OVERHEAD_DARKEN`), kept attached (a ground body's shadow slides at most `GROUND_SLIDE` 0.8 of its half-width + 2 px away from the centre, a flyer's up to 20 px). In the albedo it moved a dark floor by a few levels and its edge was embossed by the bump stage. **Standing water** (`water.rs`, after the reflections, `fx::strength::WATER` 1.0 is its master and every other knob is a constant at the top of the file): on Full, every Water pixel within `MIRROR_REACH` 14 px below a creature pixel shows that body mirrored about its foot line, darkened, tinted and fading (`BODY_MIRROR` 0.58); on Full and Hard each fixture is mirrored as a bright soft ellipse `MIRROR_K` × its height below it, rows offset ±1 px by a fixed world-row hash, replacing the streak on water; and a sparse glint pass (a fixed set of world-position candidates and two-octave normals, a `cos^GLINT_POWER` lobe against the sample's dominant light and — Full only — the rat's aura evaluated directly, a view term that slides with the camera) replaces `specular`'s flat sheen on water. Live `PuddleSteps` rings tilt and brighten glints and distort lamp and body reflections locally as they spread. The water stage reads no clock. Laser Eyes and Carbon Copy also mirror their stopped beam segments on Full and Hard: rays up to 10 px above the waterline or crossing the water paint a bright red-white image with fixed row wobble, glints and local displacement from passing splash rings. The lighting pass gives the water stage the same segments it uses for its line lights, each with up to 16 moving small lights of radius 14 px spaced about 12 px apart. `water::owns_water` is the switch and `RATRUN_FX_SKIP=water` hands the water back to `specular`/`reflections` for an A/B. `softshadow::bake`/`visibility` give Full a soft penumbra. **Materials** ride a second plane of the pixel buffer (`PixelBuffer::set_pen`; `specular::{enemy,boss,rat,giant_rat,prop,pool}_pen`): a pen is a `MaterialKind`, a creature bit and a height class, and an untagged pixel resolves to the theme's floor or wall material (`material::resolve`); a sprite's own cast shadow is stamped with pen 0. Every strength is one constant in `fx::strength`, in units of the concept plates' bold. **Batch 13b brought the faint ones up**: tone, bounce, fog and soft shadow 0.5, rim 0.5, bloom 0.30 (the one the owner wants kept low), long shadow 0.7, specular 0.75, bump, shafts, reflections and motes 1.0. With them: shafts weigh `core²` (the scatter gathers at the lens) and are banded by still, per-lamp rays (`air::rays`); a slime's glint is pulled to white (`specular::WET_WHITE`); motes (30–80 levels, 40 in a 120×80 view) retry two other homes when theirs is dark, so most float in a beam; reflections mirror **fixtures only** (never the rat's aura or a halo); bump normals are steeper (`surface::SLOPE_FULL` 112). Full runs everything, Hard drops the penumbra and the matte materials' sheen, Coarse/Compact keep only the tone and the flat composite. Rules that keep it quiet: a moving halo (gem, projectile, spark: `Falloff::Small` + `LightTag::Moving`) is never a sample's dominant light and casts no body shadow; a flat untagged face takes no sheen; nothing flickers air or bloom (`FxLight::steady`); nothing but the motes reads the clock, and with the effects on the rat's aura breathes in 4 Hz steps. Stationary per-frame emitters such as Hantavirus droppings and lava pools use `LightMap::push_ground` and `LightTag::Ground`. They can dominate samples for floor relief, sheen and water glints. They skip body shadows and fixture mirrors. **Bytes are the budget**: a smooth gradient gives every cell its own colour, so `upsample::PAIR_X` shares one horizontal weight per cell pair (only where the two taps are within `PAIR_STEEP` 28: a steep gradient, the aura's rim, showed 2-cell columns), taps within `NEAR_MUL` 20 shade as flat blocks, and air and fog are stepped (the table is on `NEAR_MUL`'s doc comment). Measured at 120×40 in bot play **before batch 13b**: +0.25–0.35 ms a frame, bytes +29 % (Sewer) and +21 % (Kitchen); on Apple M4 in release mode Full holds ~1.0–1.9 ms frame p50 at 120×40 (1×) and ~1.5–2.6 ms at 160×50 (1×) even under late-floor surges, 8 rank-5 droppings and Outfall caustics, so there is no runtime quality controller or wall-clock tier switching. `RATRUN_DUMP=lit-<sconce|pendant|wet|corner>-<floor>` stages a frozen scene for judging them, and in test builds `RATRUN_FX_SKIP=overhead,body,bump,spec,reflect,air,motes` leaves stages out of a dump. Known: zoomed out to 2×, grout glints under a pendant resample into thin lines. Render-only; `lighting_fx` is in `PictureKey`.

**Global light** (`render/lighting/gi.rs`, `GlobalLight { Off, AoOnly, AoGi }`, labels `OFF` / `AO ONLY` / `AO + GI`, default `Off`; `RATRUN_GI=off|ao|gi`, console `gi [off|ao|gi]`, the Graphics page's GLOBAL LIGHT row, saved as `graphics.global_light`). `Off` is a complete no-op, so the lighting pass is byte-identical to a build without the module. Ambient occlusion runs on Full and Hard: a per-level cache (two slots, keyed by the level's theme, seeds, palette and prop/puddle/pile counts) holds 2 px wall and collider horizons, corner occlusion and prop skirts by height class, and grounded bodies (the rat and up to 64 enemies in `SpawnId` order, never flyers, airborne bosses or Outfall swimmers) add contact shade. The coloured bounce runs on Full only: a padded 4 px grid carries surface albedo, steady fixtures, the Flatbed sun and Outfall water are propagated once per snapped view into a cache, and dynamic emitters (lava, droppings, moving lights) are propagated each frame. A bounce never crosses a wall, and the fixture share dims with a blackout. It is layered after `upsample::bounce`, which is unchanged. `World::global_light` is in `PictureKey`. Render-only.

**Cast-shadow edges and Outfall water**. With effects enabled, Full retains fractional depth-atlas angles for the penumbra and interpolates shadow boundaries across grid samples. Hard, Coarse and Compact reconstruct cast-shadow coverage at pixel resolution in the narrow band where lit and blocked taps meet. Outfall applies blue-green absorption and depth haze, an animated caustic net and headlamp-lit marine snow. Its matte sand and salted plant stage draw under the bodies. The diver and pelagic swimmers lift above detached shadows while the rat and enemy colliders remain on the seabed.

**Graphics settings are a menu page** (`Screen::Graphics`, `render/graphics.rs`, opened from Options or with `G` in play or pause): LIGHTING, LIGHT EFFECTS, GLOBAL LIGHT (cycles `GlobalLight::ALL`), SMOOTHING (cycles `Smooth::ALL`), FOREGROUND, GLYPH PARTICLES and SCREEN SHAKE (`World::shake_scale`, render-only, in `PictureKey`). `S` cycles smoothing from any row and redraws the frozen field. The Graphics action (`G` by default), Back and right click return to the screen that opened the page. The settings are saved in the save file's `graphics` object (`scores.rs` `GraphicsFile`, serde defaults). A graphics object with `graphics_version` below 2 resets smoothing to Off. Version 2 and later keep explicit smoothing choices. An object below version 3 migrates FOREGROUND to On once, and version 3 and later keep the saved choice. The console commands set and persist the same values; an environment pin (`RATRUN_FX`, `RATRUN_GI`, `RATRUN_SMOOTH`, `RATRUN_FOREGROUND`, `RATRUN_GLYPHFX`) wins for the session and is not written back until the player changes that row.

**The foreground layer** (`render/foreground.rs`, art in `game/art_foreground.rs` and `game/art_foreground_reach.rs`) defaults to On in the App. Switch it with the Graphics page, `foreground on|off`, or `RATRUN_FOREGROUND=0|1`. It is keyed in `PictureKey` and disabled on Library plates. A separate level-seeded stream selects 2–4 items per generated floor — mixing full-span bands and off-screen-anchored reaches (`ForeShape::Reach`, driven by `reach_spec` and `ReachKind::allowed_sides`) — from eligible corridor runs and rooms, favouring long corridors and wide rooms and spreading the anchors across the map. No band or reach ray crosses the start room or comes within 96 world pixels of the start. Allowed entry edges come from `reach_spec`: `LightPole` rises from `Bottom` only, `HangingLamp` and `CraneHook` drop from `Top` only, and `TreeCanopy`, `SignArm`, `VineTendril`, `KelpFrond` and `PipeElbow` may enter from any edge; man-made kinds and `TreeCanopy` stay axis-aligned while organic strip kinds (`VineTendril`, `KelpFrond`) and organic bands (`Kelp`, `BubbleChain`) take diagonal angles. Each full-span band extends at least 24 screen pixels beyond both ends of the view; each strip reach (`ReachShape::Strip`) extends its repeating stem at least 24 screen pixels past its anchor screen edge at every camera position and zoom so the base is never seen, ending at a world-fixed free tip inside the playfield; `TreeCanopy` (`ReachShape::Canopy`) is a 2D semicircular crown (`CANOPY_RADIUS = 36` art px, trunk off-screen at `x < 0`, at most one on screen at a time) whose block scale adapts so its radius covers ~0.8–1.0 of the view's short axis and its flat side clamps flush to the anchor edge while sliding off-screen in one direction. Parallax of 1.8–3.0 acts only across the band or ray, and the art follows the world 1:1 along it. Parallel lines share a canonical upright normal and stay at least 160 world pixels apart at placement and 48 screen pixels apart on screen. The two closest visible items win. The closer layer clears a wider disc around the rat when crossing another item there. The kept raster filters the body in premultiplied colour (preserving `EMISSIVE_PEN` lamp lenses) with a separable 2–4 screen-pixel tent radius that grows nearer the lens. Alpha and colour are quantized. The slightly muted body takes a lift from floor ambient colour, and the sharper shadow follows the floor with a cross-axis offset and leads reach tips into the frame from every edge. Rat and threat fades (ray- and half-disc-bounded) and the coverage budget apply at composition. Body and shadow draw after lighting and before the hostile layer. The Flatbed keeps timed sky items and no static placements: centre-pinned power lines, a drifting cloud shadow, and roadside reaches (`TreeCanopy`, `LightPole`, `SignArm`) sweeping tailward from the highway shoulders every 5–9 s, held at 30 Hz. Use `RATRUN_DUMP=floor-<name>` with `RATRUN_DUMP_FORE=n` and optionally `RATRUN_DUMP_FORE_KIND=band|reach|horizontal|vertical|room-span|corridor-span|<KindName>`, `RATRUN_DUMP_FORE_RAT=dx,dy`, or `RATRUN_DUMP_FORE_HORDE=n`. `RATRUN_DUMP_SKY=canopy|branch|lightpole|signarm|wires|cloud` stages the Flatbed items. An explicit environment pin still takes precedence.

**Round-glyph particles** (`render/glyphfx.rs`; on by default, the Graphics page's GLYPH PARTICLES row and the console `glyphfx [on|off]` (both persisted), `RATRUN_GLYPHFX=0` pins a session, **not** in `PictureKey`). The owner's mock-up (`.review/glyphs/`) found three round glyphs worth drawing inside a half-block picture, and this is exactly those three in the restrained strength: dust motes (`·` `∙` `◦`) on lit floor cells, hit sparks and cooling embers (`✦` `✧` `•`) for 0.35 s around a `damage_numbers` hit, and bubbles/drips/steam (`°` `◦` `○` `◌`) rising from the level's `EmitterKind` Steam/Drip/Fumes emitters and from a steam grate mid-plume. Glyph pickups and stippled light-pool edges are **not** built: the mock showed both lose to the pixel art. It writes **whole cells** (`cell.set_char`, fg = the cell's mean colour mixed toward the particle's tint, bg = the mean of the two colours the cell already had) into the ratatui `Buffer` in `App::draw_game` *after* the world picture is blitted and *before* the overlays, HUD, minimap and cursor. The guard is the mock's: only a cell still showing the plain `▀`, whose two pixels are within `EDGE_GUARD` 40 summed RGB, no cell within 2 of the rat's, and for motes a mean luma over 70 — a wall border, a plank seam or a digit is never collapsed into one flat cell. Motion is analytic in [`STEP_HZ`] 8 held steps off `World::elapsed` (motes are anchored to world cells and drift one cell sideways every 1.5 s and at most one up every 4 s; sparks move outward; bubbles rise a cell every 2 steps), from a hash of `(level seed, slot, step)`: no rng, no pool, no per-frame allocation, and exactly `MAX_GLYPHS` 48 cells a frame at most (`20` motes + `16` sparks + `12` bubbles, halved past 1.5× zoom). Nothing here touches the simulation, so no simulated number moves and the map pin cannot see it; a frozen plate is bit-identical frame to frame. Drawn over the live or frozen playfield only — never over the Library, the title, or the `--ai` wall (which never comes through `draw_game`). Render-only.

**Hostile layer + ink pass.** Hostile pellets, telegraphs, tells, miniboss shapes and status pips are drawn **after** the lighting pass (self-lit, above every friendly effect) by `draw_hostile_layer`. Then `render/ink.rs` re-stamps gameplay-critical geometry **in screen space after the resample** with a minimum on-screen size: hostile marks only when zoomed out (`scale > 1.05`), loot markers at every zoom (square = coin, diamond = gem, bracket = pocket find, halo = chest), never doubled at 1×. Damage digits sit between the resample and the ink pass so they keep their pixel size. Both are render-only.

**The world picture is cached.** `App::draw_game` keys the pixel buffer with `PictureKey` (the run, `World::ticks`, the buffer size, the eased zoom and its target, the lighting setting/depth, the hitbox and smoke toggles, the subcell set, the 1× smoothing, the foreground and light-effects switches and the camera's shake share) and calls `World::draw` only when the key moved or `picture_dirty` is set (discrete input, an open console, a screen change — things the key cannot see). The frozen field under the pause, level-up, options, Library, chest, shop and open-map plates is therefore drawn once, not once per frame. **Anything new that `World::draw` reads and that can change while the world is not ticking must go in `PictureKey` (or set `picture_dirty`)**; `app::tests::everything_that_changes_the_frozen_picture_redraws_it` is where to pin it. `World::ticks` is render-side bookkeeping: no system reads it.

`render/hud.rs`, `render/overlay.rs` (boss bar/warning/compass, low-health cue, callouts), `render/menu.rs` and the other screen modules are ratatui widgets drawn over/around the pixel viewport. Each screen's `layout()` is the single source of truth for its pointer hit rectangles.

## Levels

A level is a **200 × 160** lattice of 16 px tiles (3200 × 2560 world px) plus rooms, maze sections, level objects (traps, doors, rat-holes, shop holes, maze rewards, light fixtures, ambient emitters) and legacy props. `Level::tiles` is the **only** wall geometry: player, enemies, bullets, lobs, spawn checks and `art_walls::wall_colliders` all query the tile grid, so what is drawn and what blocks cannot disagree (`game/collision.rs::TileMap`). `game/nav.rs` keeps the fine window field and coarse block graph per size class.

**Seven floors** (`Theme`): Sewer, Kitchen, Lab (the original route), Laundry and Outfall at sector two, Printworks at sector three, and the Flatbed trailer, the getaway ride, which is the campaign's **fourth and last level** (and always open as a practice floor). `Theme::all()` lists six generated floors. `Theme::playable()` lists all seven in route order.

`game/levelgen/`: `layout::build_layout` (rooms, corridors, halls, the far hall, start room) → `layout::furnish` (props) → `maze::carve_mazes` (at most one, ~1 map in 8, reward + one-way door at the end) → `placement::place_rat_holes` → `placement::place_traps` → `placement::place_shop_holes` → lights/emitters → puddles → seabed plants (Outfall) → clothes piles (Laundry) → `validate` proves the map playable, and `generate` retries with a salted seed if it is not (a safety net, not a routine path). The render stages read the finished tiles on independent salted streams. Deterministic from `(theme, seed, attempt)`, ~3 ms median in the dev profile (`RATRUN_LEVEL_TIMINGS=100 cargo test level_stage_timings`); distributions under `RATRUN_LEVEL_STATS`.

**There are no boss arenas** (batch twelve). The room the arena used to take is an ordinary far `Hall` (`FAR_HALL_*`), `strip_boss_arena` normalises the Flatbed's cab hold the same way, and `Level::boss_room()` is always `None` on a generated level (`BossArena`, `RoomKind::Boss`, `LightZoneKind::Arena` and the minimap's bearing art survive as inert seams). `Level::largest_hall()` is the "big open room" tests and captures use instead. The retry net still matters: about 1 first attempt in 3,000 fails validation (a furnishing over a two-cell corridor; it was 5 in 3,000 before).

- **Hazards**: `systems/traps.rs` — sticky glue boards (20 % speed, a limited glue budget, `Used` when spent; a body the board lets go is immune until it has walked off the pad — `StickySlot::freed` — so a crowd jamming it there cannot spend the budget twice) and baited mousetraps (`Armed` → `Triggered` 0.18 s → `Snapping` 0.20 s → `Sprung`; a **hair trigger** skips the warning and resolves on the touch tick). `systems/hazards.rs` — steam grates (Resting 4.0 s → Warning 1.0 s → Plume 0.7 s) in the Laundry, ink pads (permanent 75 % ground speed) in the Printworks.
- **Crab pots** (`systems/traps.rs`, Outfall only) replace the glued and baited traps at their settled placement sites. The 18 px square warns for 0.35 s, then cages the rat for up to 0.8 s and up to four eligible enemies for 3 s. A dash can break the rat free after 0.25 s. A giant crushes the cage. An empty snap can release a Shore Crab at the mouth if spawn limits and the named-fight gate permit it. An open pot resets after 20 s.
- **Laundry dressing** (`art_props.rs`, `art_laundry.rs`). Each bank pairs a washer and dryer with different porthole animation and light colour. Piles and baskets hug walls and machines, with an independent placement stream.
- **Light fixtures** (`LightFixtureKind`) and ambient emitters (`EmitterKind`) are placed by `levelgen/lights.rs`; the renderer reads the same structs. **Sconces** (`LightFixtureKind::Sconce`, `place_wall_lamps`, run after every earlier draw of the stage so the hanging lamps and emitters are unmoved) are wall lamps: each sits half a pixel inside the floor cell in front of a `WallKind::Solid` face with at least two cells of floor before it, never on a rat-hole, door, shop hole or within three cells of a doorway or a hanging lamp, four cells from another sconce. `LightFixture::wall_facing` re-derives the mount from the grid (no stored facing), and the light is a 150° fan (`SCONCE_HALF_ANGLE` 1.31 rad) of 110 px into the room at `SCONCE_ENERGY` 2.35 (three times batch nine's) on the cached static path, so the wall behind it stays dark; a second small radial **wash** (`fixtures::sconce_wash`, `SCONCE_WASH_RADIUS` 26, sharing the fan's baked shadow, without the fan's flicker) lights the face it hangs on so the lamp reads as the source. `SCONCE_CAP` is 40; the order is the budget: the start room, corridors (their own rule: a straight wall of `SCONCE_CORRIDOR_RUN` 4 cells, two cells from a doorway), every other room/hall, then the rooms between. There is no arena ring any more. One in eight is spent (dark, sputtering); the rest flicker 3 % in held steps (`SCONCE_FLICKER_HZ` 3) because a continuous flicker repainted the pool every frame. The Flatbed gets up to `RAIL_LAMP_CAP` (8) rail markers instead. The map pin does not fold fixtures.
- **Shop holes**: two per level in structural wall faces; touching a threshold raises `pending_shop` and opens the shop screen.
- **Interactive objects** (`systems/gates.rs`): rat-holes (an 8 px gap the rat fits and a Cat/Brute does not; the rat is centred laterally), the maze cache (one free level-up + the fog/minimap claim), one-way doors and the exit slam. Enemies never pass a gate.
- **The Flatbed** (`systems/trailer.rs`, `levelgen::trailer`, `art_trailer`): pits in the bed (rat: 8 damage, i-frames, replaced on the nearest plank; horde: 35 % of max HP + stun), sliding cargo, the slipstream that drags small bodies and gems tailward, expansion-joint bumps, and the Magpie's gust wind.
- **The Outfall** (`systems/outfall.rs`): tidal drops, six lure traps and a surge every 9 s. A one-second warning precedes a 1.1 s eased push of up to 64 px. Crests drift across open floor after lighting and share the motion system’s Lantern arrival gate. Each streak follows the push direction, with a bright downstream tip and a fading upstream tail. Outfall fixture snuffs are gameplay state shared by the elite Grouper, The Lantern, the Fry School and lighting.
- **Fog** (`game/fog.rs`, `systems/fog.rs`): a `Fog` resource round-tripped like the rest, flooded from the rat's cell through open floor and open doorways, stopped by solid walls, maze partitions, closed one-way doors and rat-hole faces (a hole is revealed by sight or by having stood in it). The minimap draws only seen cells; never-seen territory is the dim **red veil**.
- **Standing water** (`Level::puddles`, `levelgen::puddles`, `systems/puddles.rs`, `art_puddle`): the owner's "the sewer especially should be very wet, and the rat should make little splashing sounds when walking over". A `Puddle` is decoration with one gameplay hook — `Level::wet_at` — and never a tile: it cannot block, slow, route or be seen by the bot, the fog or the minimap. `Puddle::contains` is one shared irregular blob (`(dx/rx)² + (dy/ry)² <= edge(angle)²`, `edge = 0.78 + 0.22 ×` an eight-lobe integer-hash wobble) read by gameplay, art and lighting alike; `depth` ramps 0→1 over the outer 6 px for the soft edge. `levelgen::puddles` runs after the lights and emitters and before seabed plants and clothes piles, on its own salted rng (`level_seed ^ PUDDLE_SALT`) over the finished grid, and writes only `Level::puddles` — which the map pin does not fold — so no earlier stage can move. Counts a map: Sewer 26–34 (large, biased 4:1 to corridors and wall edges, so a run of them merges into one long wet stretch; coverage is measured, aimed at ~18 % of the floor), Laundry 10–14, Kitchen 4–6 small spills; the Outfall has 240–265 centres tuned to about 36% wet coverage. The Lab, the Printworks and the Flatbed have none. A centre is always an open floor cell, 40 px clear of the start and off every rat-hole face, door, shop threshold and trap pad. `systems/puddles.rs` (`puddle_steps_system`, chained right after `player`) pushes one `Sfx::Splash` per `STEP_PX` 11 px of **wet** travel plus one on entering water from dry, one `Sfx::SplashBig` per dash that touches water, nothing while standing still, and starts the ripples (life 0.45 s, at most eight) the renderer draws; the first six ordinary ground bodies in `SpawnId` order on screen in water ripple too, silently and at most every 0.5 s each (`PuddleSteps`, permanent scratch, keyed by slot so no component grows). It draws no rng, touches no entity and changes no simulated number — the rat is **not** slowed — so no simulated number moves and no replay can see it. The puddles are drawn right after the floor stains and before the boss ground layer, under `render::lighting::pool_pen()`, so lamps reflect in them. While the lighting effects run at Full or Hard (the buffer keeps materials) the art draws the **glossy** sheet (`art_puddle::draw_puddle_among_with`, `GLOSS_DEEPEN` 12 % darker, with a smooth interior) and `render/lighting/water.rs` lights it: sparse glints (the rat's own aura included), lamp mirrors and upside-down body reflections and reflected laser bars. With the effects off the surface has fixed painted highlights. Splash ripples expand and fade in both looks.

## The fifteen-minute timeline

- **Blackouts** (`render/lighting/blackout.rs`). The director's curve clock cuts indoor fixture power at 5:00 and 11:00. The Lab trades its second outage for The Lights Go at 7:30. The lamps fade down over 0.6 s, stay dark for 8 s (18 s for The Lights Go), and fade back over 1 s. The Flatbed skips the event. The same factor dims the fixture lenses, pools, washes and fixture-derived effects, and `PictureKey` tracks it for frozen frames. The rat's aura, rim glints and hostile layer stay visible. The App shows `BLACKOUT` / `LAMPS OUT` and plays existing sounds as the clock crosses the shutdown and recovery edges. The event only changes presentation. For a frozen lighting capture, use `RATRUN_DUMP_AT=<seconds>` with `RATRUN_DUMP=lit-<scene>-<floor>`.

`game/director.rs` is time-curve based, not fixed waves: spawn rate, live budget, hp, elite cadence and speed all read `curve_clock(elapsed)`. **Which** body spawns is the floor's roster (`game/roster.rs`, the contract is `WAVE4_ROSTERS.md`): every floor has eight role slots — A ground fodder (0:00), B flying fodder (0:45), C chaser (1:15), I first trick (2:00), R shooter (3:35, cap 4), II second trick (4:30, cap 4), H heavy (6:35, cap 8; the floor's elite wears this body), III third trick (9:45, cap 3; I caps at 5, the Big Snake at 2) — and four fixed minibosses. `roster::pick_kind(theme, clock, caps, rng)` is **one** weighted draw over the slots in table order: a locked or capped slot has zero mass and its share goes back to fodder, so caps cost no retry and no extra rng. The spawn pulse counts live bodies per slot (`spawn::live_slot_counts`; elites and minibosses excluded, a Lilliputian squad counts once). All 56 roster kinds are registered (`EnemyKind::all()` is 59 including the legacy `Boss` body, the Drake and the Shore Crab) and no kind appears on two floors, so no slot holds a stand-in (`RosterSlot::stand_in_for` is `None` everywhere; the field stays for a future floor). **The archetype seam:** `EnemyKind::archetype()` names the existing body whose steering, attack, nav size class and behaviour systems a kind reuses. Every *behavioural* decision in the simulation keys on `archetype()`; stats, name, colour, gold, XP, Library identity and art tint key on the real kind. The 33 wave-four registrations each name a base there until their floor's batch gives them their own rule (`roster.rs`'s module docs list which are pending). `RUN_SECONDS = BOSS_TIME = 900.0`. At `BOSS_TIME` the director raises `BossDue`; the boss **arrives where the rat is** (`boss_spawn_system`: the fight rectangle is `Level::fight_rect_around(rat)`, the nominal `BOSS_FIGHT_TILES` 34 × 28 cells clamped to the map; the body lands on the horde's own out-of-sight reachable ring, about 195 px off, drawn from the boss's rng; measured first damage 1–8 s later) and the horde drops to cleanup pace (1 body/s, budget 35) while the curve clock freezes. Shipped live budgets, pulse intervals and elite intervals have separate rows for each campaign sector (`tuning::Director`). Contact damage ramps to about ×0.61 / ×1.03 / ×1.23 / ×2.02 before surge modifiers, and the speed ramp tops out at ×1.0 / ×1.08 / ×1.15 / ×1.2 on top of the global ordinary enemy speed multiplier (about ×0.86). Ordinary HP carries the `LEVEL_HP_EXTRA` ramp (×1.2 / ×1.45 / ×1.7 / ×1.9, starting at 3:00). The horde and boss pools both use the character-level HP correction (×1.0 at 0:00 → ×1.19 at 3:00 → ×1.55 at the boss) and the build HP correction. Round three adjusts the sector build HP multipliers to about 0.63 / 2.63 / 3.60 / 2.27. Bosses have their own sector correction and a global HP multiplier of about 0.76. Round four ships the owner's fresh-start playtest: the rat keeps one HP number (`79.477`), one regen set and one armour set on every sector — **no rat stat, heal, passive or splice may read the sector**; the later floors' softening lives on the attackers instead, where every enemy hit is created (`[enemies] sector_damage_mult = [1.0, 0.5, 0.5, 0.5]`, covering ordinary and elite contact, enemy bullets and lobs, floor-roster attacks, the Drake, the crab, miniboss strikes, boss contact/hazards/projectiles and the floors' own traps and hazards; `director::sector_damage_mult` is the one helper). Ordinary HP is ×2.45 in the Sewer and ×0.87 on the facility floors (`[enemies] sector_hp_mult`). Both enemy rows key on `DifficultyLevel`, like every other sector table, so a practice run on a later floor plays sector one's row (`resources::SectorDamage`, `Enemy::apply_spawn_tuning`); a Termite Horde's split half keeps its parent's pool and skips the HP row. The fresh-sector build/horde/boss rows are `0.6144/0.6204/0.6256`, `1.15/1.17/1.18` and `1.1308/1.0340/1.0096`, and `director.power_scaling` is on by default (exponent `0.45`, `18 s` memory, ×`0.9–1.15` clamp, fresh references `16.0/19.5/19.0`). A level ends when the boss or the rat dies — the clock is not a win condition. The boss warning starts 25 s early (`render::overlay::BOSS_WARNING_SECS`) and reads `▸ <BOSS> IN <n>s · STAND YOUR GROUND ◂`; there is no arena bearing or compass to one, only the living boss's off-screen arrow. If the rat walks more than half a rectangle away, the rectangle is rebuilt around it on the boss's next neutral beat (`rat_left_the_fight`).

- **Horde surges** (`director::PressureState`). Default runs have two surges on each floor, starting at about 3:19 and 11:34 on the floor clock. The `HORDE WARNING` callout gives a floor-specific message and plays the warning sound 5 s before each surge. For about 104 s and 101 s respectively, ordinary spawns pulse more often, their live cap rises and their contact damage increases. The following recovery windows last about 268 s and 69 s, with a lower live cap and more Medkits among rare finds. The Sewer also cuts ordinary contact damage by 26.2% through the first 167.6 s while the opening pulses feed the first cards. See [TUNING.md](TUNING.md) for sector scaling and overrides.
- **Named minibosses** (`systems/miniboss.rs`, `systems/miniboss_behaviour.rs`): the same four appointments on each floor at 3:00, 6:00, 9:00 and 12:00 (`roster::appointments`). There are 28 bodies with individual temperaments. The original 24 have two attacks each. The Outfall four have one each. Some alternate from the first strike. Others start switching with the secondary once HP falls below their threshold. Each tell tracks for 0.5 s and locks for 0.5 s, and the body stays planted through the tell, strike and one second of exposed recovery. The next tell waits for the body's own 1.6–3.4 s gap from the strike's end and for the body to be in reach. Between strikes it stalks, lines up a contact lunge from about 70 px, orbits at its attack range, anchors on arrival, dives to a warned spot about 40 px from the rat, or summons three local slot-A bodies at recovery. Summons are capped at nine per owner and yield no progression credit. Movement and summon placement use `SpawnId` and the floor's navigation with no run RNG draws. The shape evaluators include Annulus, Tide, Return, Overlap, Comb, Shear, Wake, Drip, Umbra and False. The rat is drawn at `GIANT_SCALE` 5× (`World::draw_scaled_rat`, full-detail art with a 0.4 s grow-in and an ordinary-size live lash). The scaled animation advances its trot and swim strokes by distance divided by draw scale and advances idle motion by time divided by scale. Its art clock eases back into the normal pose. At equal speed, the full giant's stride takes five times as long as the normal rat's. The collision body grows to 6.5 px wherever clearance permits, the hurt radius grows to 15 px, and tight rat-holes reject the larger body. The rat can leave a constricted spot before resuming growth. The view eases out to the widest rung and back (`zoom::giant_target`, render-only: the simulation reads neither zoom). Every `GIANT_STOMP_INTERVAL` 0.25 s `giant_stomp_system` crushes ordinary bodies inside `GIANT_STOMP_RADIUS` 30 px outright and deals `GIANT_ELITE_DAMAGE` 60 to an elite and `GIANT_BOSS_DAMAGE` 40 to a miniboss or a grounded boss (through the boss's own state and shell multipliers), credited to the Gnaw column; the giant takes half damage (`GIANT_DAMAGE_TAKEN`) and walks at ×0.9. **Weapons read on a giant.** Every weapon still fires; the effects are scaled and re-anchored so the five-times sprite and the stomp disc cannot hide them. Origins follow the drawn pose (`Player::weapon_pose_scale`, the eased `draw_scale`): the Gnaw jaw's snap anchor sits at `GNAW_MOUTH_OFFSET` × pose in front of the rat, the Cheese Spray wedges and Fondue tines, the Acid Spit lob and the Glass Beads leave the same mouth (their offset grows from the centre, so the ordinary rat's geometry is untouched), the Lava Breath globs leave `LAVA_MOUTH_OFFSET` × pose, and the Laser Eyes beam leaves the giant's eyes at `LASER_EYE_OFFSET` × pose. Damage is unchanged and no new rng is drawn.   **Control and pursuit (batch 13, `boss/mod.rs`).** A player weapon can never take a boss out of its fight. A stagger is *control* and is paid from a shared budget: `Boss::grant_control(secs)` grants at most `CONTROL_BUDGET_SECS` 0.30 s per `CONTROL_WINDOW_SECS` 4 s (nothing under `CONTROL_MIN_SECS` 0.12), and **never inside a committed beat** (`Boss::committed`: any state that is not the kind's neutral, stagger or death state), so a wind-up always fires. `Boss::shove` moves a neutral boss at most `SHOVE_PER_HIT_PX` 4 a hit and `SHOVE_PER_SEC_PX` 12 a second and refuses a committed one. `pursue` runs before the controller: `Boss::out_of_reach` counts every second the rat is beyond `BossKind::engage_range()` (in any state; only a rat back in range resets it), and from `OUT_OF_REACH_SECS` 3.0 a neutral boss leaps (`LEAP_SPEED` 300 px/s for `LEAP_SECS` 0.30, `LEAP_COOLDOWN` 3 s, a body-passable straight line only) or sprints the flow field at `PURSUIT_SPEED` 132. The Jaguar closes with its own pounce instead (`own_gap_closer`; `CLOSING_POUNCE_MAX` 220 px), and the mower's lidar locks a rat it has *seen* during the scan even if it has backed out of `SCAN_CONE_RANGE` 72 by the snap (patrol band 45–64 px, a pursuit leap goes straight to the scan). No rng is drawn by any of it. **The rejoin is a call, never a placement:** a boss that is beyond `REJOIN_DIST` 260 px, without a line to the rat, or stuck for `RELOCATE_AFTER_SECS` 5 s is called back for `RECALL_SECS` 12 s — `Boss::out_of_reach` is lifted to `OUT_OF_REACH_SECS` and `Boss::leap_cd` cleared, so the shared pursuit rule above sprints and leaps the body home, and the siege's `near` gate lifts so a wall in the way can be smashed from any distance. There is no `boss.pos = …` relocation and no arrival flash; the old `rejoin_spot` ring search is gone. `boss::tests`' scripted fights (`ScriptedFight`, one per weapon script) pin that every kind starts and completes attacks under the heaviest build.

  `BossController::tick` owns only transitions; `Boss`, `BossOutput`, `BossHazard`, `BossProjectile`, `move_boss`, `BossContext` (player state, arena, `TileMap` queries, large-class flow field) and the index-window rules are in `boss/mod.rs` — read it before touching a boss.

  **The Lantern** (`boss/lantern.rs`, `art_boss_lantern.rs`) has a 264 px top-down body and a 54 px hittable head. The 168 px resting lure leads up to 216 px on arrival. Scheduled placement uses a map-bounded ring outside the widest view. The head swims, sprints and leaps directly toward the rat across terrain, with no flow field, siege or relocation. Its contact and weapon hit shapes stay active in their usual states. The mouth anchors the jaw snap, trenches, Gape cone and stamp. The attack footprints cross terrain. The Gape pull still clips rat and gem displacement against the floor. The opaque hull and attached lure float above wall overhangs and receive lighting. A detached seabed shadow provides the height cue while the visible mouth and attack marks share one world position. Planted bulbs, decoys and attack footprints retain their world positions. The Lantern opens distance between attacks and submerges for 4.5 s between phases. Dark attacks and the submerged hull use their own opaque palettes. The campaign HP multiplier is 2.7, or 5.3 if two of Squeak Nova, Spore Orbit and Acid Rain are at max rank when the boss arrives. The bare-practice row uses 4.5. Head contact can deal 2 damage once every 2.25 s.

### Level one's opening

The Sewer opening runs on campaign index 0 and in Sewer practice. The hazard placement stage picks a reachable room nearest the start and draws one Drip Shaft tile with a dry route around it. The shaft arms within 48 px, outlines its tile and drops for 0.5 s, splashes for 0.3 s and deals 6 damage once to the rat on that tile, then rests for 2.5 s. Two Pillbugs are due at 0:22 in the same room. The director reserves two places within the horde budget until the pair arrives. If both cannot spawn outside the widest view, the pair waits for a clear tick before the floor boss is due. They stay curled until approached. A Bottle Cap appears at 1:30, 24 px beyond the start-room doorway nearest the map centre with a clear landing. A completed Corkscrew trench leaves 25 s of standing water that reflects light and splashes underfoot.

The scripted placements draw no simulation rng. The map pin includes the generated opening layout. Rare enemy pickup rolls start after the guaranteed Bottle Cap is placed. The opening changes both Sewer gameplay traces through the early drop-roll gate and authored encounters. The Bottle Cap entity and Corkscrew are beyond their 60 s window.

## Progression

- **16 weapons** (`WeaponKind::all`, `WEAPON_SLOTS = 16`): Gnaw, Cheese Spray, Squeak Nova, Spore Orbit, Tail Whip, Acid Spit, Tail Thrash (ACTIVE), Sonic Squeak (ACTIVE), Laser Eyes, Super Dash (DASH), Acid Rain, Hantavirus, Spiked Tail, Lava Breath, Glass Bead, Plumb Bob. **Super Dash is hold-to-charge**: with the weapon owned, holding the dash input fills a meter (`SUPER_DASH_CHARGE_SECS` 0.90 s at L1, −0.04 s a level) and the release fires — up to 2× the dash duration, +50 % swept radius and ×2.5 crossing damage at full; a release inside `SUPER_DASH_TAP_SECS` (0.15 s) is the ordinary dash, and without the weapon the dash is press-to-dash with no added latency. The App feeds the edges through `World::update_with_dash_hold` (`DashHold`); `update`/`update_with` pass `DashHold::NONE` and charge 0, where the charge multipliers are ×1. Ordinary dashes use 0.32 s of boosted travel and full charge uses 0.64 s. A partial final tick uses the remaining travel time and both forms retain a 20 ms immunity pad. Doubling the ordinary travel changed all six goldens because both scripts dash. Damage/cooldown/projectile-count scale with level in `game/weapon.rs`; firing patterns live in the weapon systems. **Batch twelve gave each weapon its own shape.** Gnaw is a **bite**: no projectile, the nearest body within `GNAW_BITE_REACH` 34–40 px (it was 20–24; same damage and cooldown) (any direction on auto-aim, a 48° cone when aimed), both old darts' damage from level 4. Cheese Spray throws a short fan of slowing wedges. Squeak Nova is **one expanding ring** (`weapons::nova_ring`, `ActiveFx::nova_*`): each body is cut once as the front passes, Echo Chamber brings it back in for a second pass. Tail Whip is a **160° rear swipe** centred opposite the rat’s facing or aim (`WHIP_REACH` 30–42 px). Ratchet Tail throws the closest surviving light foe hit by the swipe along the rat’s facing and strikes light foes along the path. Sonic Squeak is a **forward cone** (`SQUEAK_CONE_HALF`) that lands on the press tick. Laser Eyes is **two beams closing inward like scissors** (batch 13): at every rank a pair starts on the two outer edges of the arc (60°–110°) and sweeps in over 0.26–0.34 s (`LASER_SWEEP_SECS`), meeting on the aim line at ranks 1–3 and crossing through to the opposite edges from rank 4 (`LaserFx::twin` now means "the pair crosses"). Its one-pixel red-white cores and faint shoulders reach the edge of the widest simulation view (`Viewport` × `MAX_ZOOM_OUT`), stopping at the first wall. The muzzle follows the rat's current eye position on each tick while the cast angle stays fixed. Both beams share one hit set. A body takes one pulse (6–10) per sweep, with inverse-square falloff from the eyes beyond the rank's full-damage radius (28 / 34 / 40 / 48 / 58 px). Hits under 1 HP skip the floating number. Carbon Copy replays from the recorded cast origin with the same falloff at half damage. The art and lighting read the same wall- and view-stopped lengths as the hit tests (`LaserFx::beam`/`beam_b` and `copy_beams`). Acid Rain lands as teal ripples, never a pool. **Lava Breath** throws ballistic globs in a fixed fan. The globs splash on landing and leave damaging pools. Caldera adds a pool under the rat and merges overlapping pools. Adding Lava Breath to the upgrade pool can move scripted traces through card shuffling. **Hantavirus is deployed by droppings** (owner's rule): every cycle the rat leaves one on the floor 5 px behind its facing (under it inside a wall) — `DROPPING_CAP` 4→8 live, `DROPPING_LIFE` 14 s, armed after `DROPPING_ARM` 0.25 s, the oldest `SpawnId` evicted first — and the first unmarked body that steps in one takes the same three ticks, jumps, visit history and Dead Letter seal the old ranged tag planted; a grounded boss on one takes the `BossVirus` mark. A dark matte pellet sits inside a steady green floor halo. Ground-light radius by rank is 49.5 / 60.5 / 71.5 / 85.25 / 99 px and armed energy is 8 / 10.5 / 13.5 / 16.5 / 20. The 1.7× geometric tail uses the small-light falloff. The green-only light is half strength while arming and fades during the final 2 s. Local bloom grows from a 6 px to a 10 px ellipse. The drop is silent (`Sfx::Infect` plays on the infection) and needs no target, and the weapon ignores `TickInput.aim`, so Classic and MouseAim behave identically. The Spiked Tail's mechanic is unchanged (one targeted lash, a burst where it lands) with `LASH_REACH` 80–120 px, which is past the edge of a 120-column view at 1×. A lash target must sit inside the unzoomed `Viewport` rectangle (inset 4 px, `weapon_spiketail::LASH_VIEW_INSET`) as well as inside the reach. Like Laser Eyes, Spiked Tail uses the per-tick `Viewport`. The lash is drawn as a **render-only Verlet whip** (`art_rat::WhipChain`, 16 nodes joined by lines, fixed sub-steps, the tip pinned on the target through the crack). A floor-level melee, cone or ring only hits a boss that has a grounded hit shape. The Laser's beam, muzzle and sparks share one red-white palette (`vfx::LASER_CORE`/`LASER_GLOW`). The dash arc under the rat is gone (`art_rat::draw_dash_charge` draws only the Super Dash charge ring, and only while charging; the ink pass no longer stamps one); the HUD's dash module is the readout.
- **Glass Bead and Plumb Bob** (`weapons_wave5`). Glass Bead reflects off projectile colliders at 120 px/s for up to 1.8 s. A repeated tile or an 80 px leg with no wall spends two bounces. The fourth bounce ends the shot and triggers Last Bounce. Plumb Bob sweeps a cosine-eased 150° arc in 0.55 s each way, then starts its cooldown. A fixed-step Verlet chain trails the same endpoint the sweep uses. Shed Bob rolls out along the tangent and reels back at the turn. These effects use SpawnId order and consume no RNG. The two additional cards widen the upgrade pool and can move scripted traces after a draft. The map generator is unaffected.
- **12 passives** (`PassiveKind::all`): MaxHp, MoveSpeed, Damage, FireRate, Magnet, Regen, Armor, SpringHeel, Counterweight, LongFuse, SecondScent, LensCap. `loadout::apply_passive_stack` is the single source of truth for a stack (the carried-loadout rebuild replays it).
- **16 evolutions** (`WeaponKind::evolution`): a chest evolves a max-level weapon whose partner passive the build owns (≥1 stack). An evolution keeps the kind, timing family and damage-ledger column and changes what the attack does: Milk Teeth (Gnaw), Fondue Fork (Cheese Spray), Echo Chamber (Squeak Nova), Fairy Ring (Spore Orbit), Ratchet Tail (Tail Whip), Drain Cleaner (Acid Spit), Flywheel (Tail Thrash), Roll Call (Sonic Squeak), Downspout (Acid Rain + Long Fuse), Dead Letter (Hantavirus + Second Scent), Carbon Copy (Laser Eyes + Lens Cap), Ripcord (Super Dash + Spring Heel), Barbed Wire (Spiked Tail + Counterweight), Caldera (Lava Breath + Long Fuse), Last Bounce (Glass Bead + Lens Cap), Shed Bob (Plumb Bob + Counterweight). Every weapon has a row. Behaviour lives in `systems/evolutions.rs` and the matching weapon systems; damage always credits the base weapon.
- **Milk Teeth** (`systems/evolutions.rs`). A successful evolved Gnaw bite lobs a tooth in a repeating 0 / −4 / +4 px lateral pattern. The lob travels above intervening masonry and shifts a blocked landing back to open floor. It bites one eligible target within 9 px at touchdown if cover permits, lodges for 1 s, then returns in a straight line and bites each body it crosses once.
- **Slots**: distinct-kind caps `MIN_SLOTS = 4` … `MAX_SLOTS = 8` per rack, carried on `Loadout`. Read them through `Loadout::max_weapons`/`max_passives`/`loadout::slot_caps`, never the constants (`--caps` overrides them for a batch).
- **XP**: the fine curve is `player::base_xp_for_level(l) = round(XP_BASE × 1.10^(l-1))`, with `XP_BASE` about 4.85, and since batch twelve one character level costs **four** of those steps (`xp_for_level`) after a three-card opening ramp of one, two and three steps (`OPENING_OLD_LEVELS`), so level-ups come a quarter as often: 5, 11, 21, then 39, 59, 85, … with no cap; the first card lands at about 17-19 s (it was 77 s on level one), about level 7 at 3:00, 10.5 at 6:00, 13 at 9:00, 15 at 12:00 and 16 at the boss, i.e. about 15 cards a floor where there were 55. **Every character level above 1 adds +4 % weapon damage** (`player::LEVEL_DAMAGE_PER_LEVEL`, no cap: level 14 is ×1.52, what level 53 was), composed with the build's `Stats::damage_mult` in one place, `Player::damage_mult`, which every weapon pass reads when it fires (pools, marks and evolved effects carry the damage they were fired with). The level restarts at 1 on every floor (`carried_player`), and so does the bonus; the level-up header and the pause readout print it. Builds are smaller on purpose (three or four weapons at low rank and two or three passive stacks by the boss); the pools were cut to match (`director::BUILD_HP`), and level one from a bare Gnaw is the hard part of a run (see the batch-twelve measurement in the bot section).
- **Level-up cards** (`Loadout::generate_choices`): up to three distinct cards — one owned rank-up, one new kind (the first level-up always offers a second weapon; later the evolution partner of an owned L4/L5 weapon is promoted), one anything-legal. Fallbacks, at most one each: `Bandage` (25 % max HP, hidden at full health) and `Purse` (`PURSE_GOLD`, 3 gold). Fewer than three cards is a legal answer. Auto-pick (`U`, persisted) takes each card with 0.4 s toast spacing; the first lands on the frame a manual screen would have opened, so the simulation and its rng see the same thing.
- **Gold**: coins drop from a per-kind chance × value table plus `ELITE_GOLD` (2), `MINIBOSS_GOLD` (12), `BOSS_GOLD` (30). A floor pays about 650 (measured: ~350 coins, ~150 elites, ~65 Purse cards, 48 minibosses, 30 boss); the per-kind chances in `shop::gold_row` are the design's cut to a third (batch six) and by a further ×0.72 (batch seven).
- **The in-run shop** (`game/shop.rs`, "the blind spot / gene splice shelf"): behind the mouse holes. Ten splices in two sockets (`MAX_SPLICES = 2`; they are neither weapons nor passives and never count against a cap, and **they last for the floor they were bought on** — `campaign::next_loadout` carries the weapons and the passive stacks and deliberately does not copy `splices`, so every new level starts with both sockets empty and its stats rebuilt without them). A shelf is three of them, rolled from `(floor seed, hole index, rerolls)` on its own rng. Services: Stitch (20¢, heal 35 %), Turn the Shelf (14¢, then 28¢), Molt (40¢, replace an upgrade with a fresh Lv1 of the same type). Splices cost 48–76¢ (`SpliceKind::price`; batch seven took a third off batch six's tripled prices) and apply *after* passives in `apply_splices`.
- **The nest** (`meta.rs`): 15 permanent tracks bought with banked gold (weapon/passive slots 4→8, move speed, pickup range, fire rate, max HP, regen, armor, damage, dash cooldown, XP gain, gold gain, luck, carry-over 3→5, one revive). Every number and price is in `Track`/`Track::prices` — retune there (the measured median run banks about 2,000¢, so the cheapest step, 240¢, is one run, the median track 6,600¢ is three to four, and the full Nest, 108,420¢, about 54; the batch report's `Nest:` lines print those three figures for any table). The profile is a field on `ScoreTable`, so it lives in the same save file. **Banking rule** (`meta::bank`): unspent gold plus `FLOOR_BONUS` 25 per cleared floor, `APEX_BONUS` 6 per boss/miniboss killed and `WIN_BONUS` 75 for the clear; a practice run banks half (rounded down); a run that used the console banks nothing; saturating throughout.
- **Campaign** (`game/campaign.rs`): **four levels**, Sewer → (Kitchen | Laundry | Outfall) → (Lab | Printworks) → the Flatbed (`LEVEL_COUNT` 4; the ride's boss wins the run). A level completes when its boss dies. The transfer screen selects the next route and starts a fresh build in each sector by default. Setting `campaign.carry = true` restores the keep-three plate, which lists upgrades in a stable order and allows `keep_limit(loadout)` carried entries (three base, up to two more from the Nest). `level_seed(run_seed, index, theme)` derives each floor's map, so a campaign replays exactly. Practice runs play one floor alone on level one's scalars (`difficulty_override = Some(0)`; the Flatbed is always open for practice, `ScoreTable::floor_unlocked`) and do not advance the campaign. A three-level save migrates (`migrate_legacy`).

## Controls

`input.rs` is the raw layer, `controls.rs` the remappable layer over it, `gamepad.rs` the pad poller.

- **Three schemes** (`Scheme`): Classic, MouseAim, Gamepad. Each carries `Bindings` — a keyboard/mouse primary + alternate per action, and pad slots. `Controls` owns the active scheme, dead zone, rumble flag and cached legends, persisted beside the scores. `input.rs` resolves every action through `Controls::active()`, so a rebind takes effect everywhere.
- **27 actions** (`Action`, indexed by array position — the table is append-only): MoveUp/Down/Left/Right, Dash, FireActives, Pause, Map, MinimapSize, ZoomIn, ZoomOut, ResetZoom, ToggleCursor, Mute, MusicDown/Up, EffectsDown/Up, Options, Confirm, Back, AutoPick, Library, Nest, Quit, Reset, Graphics. A save written before an action existed loads it at its default unless the player already gave that key to another action, in which case it starts unbound (`Controls::from_saved`).
- **Defaults** (`Bindings::defaults`): `WASD` moves (the arrow keys also steer, as a raw `KeyCode` fallback rather than a binding), `Esc` (alt `P`) pause, `Tab` map, `N` minimap size, `Z`/`X` zoom, middle click reset zoom, `C` cursor, `M` mute, `[`/`]` music, `-`/`=` effects, `O` options, `Enter` confirm, `U` auto-pick, `L` story/library, `B` the Nest (pause, incident report, victory), `Q` quit / back to the menu, `R` refund the Nest / reset a scheme, `G` graphics (play/pause, keyboard only by default). Every chip and legend that names one of these reads the live binding (`Controls::action_label`); screens without a `&Controls` are handed the key name. Classic and Gamepad: Ctrl dashes (alt left click), Space fires actives (alt **right click**; a save still holding the old left/left pairing is migrated unless the right click is already bound). **A right click is Back in every menu and on the open map** and never pauses play; closing the map with it does not also fire or dash that frame. MouseAim: right click dashes (alt Ctrl), left click fires actives (alt Space). Pad: d-pad/stick move, `RB` dash, `X` actives, Start pause, View map, `Y` cursor, `LB` mute, `RT`/`LT` zoom, `R3` reset zoom, `L3` minimap. **A right click is also Back in every menu and overlay** (`InputState::back_pressed` = the Back action *or* a right click), the expanded map included; it only ever activates a menu row as a *left* press, and in Classic/MouseAim play it is the actives/dash binding instead. **The dash has no read-out on the rat**: `art_rat::draw_dash_charge` draws only the Super Dash charge ring while a charge is held (the lane preview is under the rat, the cooldown/READY/refusal live in the HUD's dash module), and the ink pass stamps only the rat's two-pixel core — `render::ink` no longer draws a dash arc at any zoom.
- **The Ctrl caveat.** A lone modifier only reports under the Kitty protocol with `REPORT_ALL_KEYS_AS_ESCAPE_CODES`; `KeyboardMode::lone_ctrl` records whether it stuck. Without it Space dashes *and* fires actives (the old mapping) and the legends say so. The same limit decides who can **hold** the dash to charge a Super Dash: a key only where the terminal reports its release (otherwise a key press is always a tap), the mouse and the pad everywhere. Focus loss or a pad unplug cancels a held charge and never fires it. Held movement uses real key releases when the protocol answers, else a short auto-repeat grace window.
- **Gamepad** is behind the `gamepad` feature and read only while the terminal has focus (a pad in someone's lap must not drive a game nobody is watching). Tests inject `PadEvent`s, so no controller is needed.
- **Aim** is deterministic: `TickInput.aim` is an `Option<Vec2>` in world pixels from the pointer (MouseAim) or the right stick (Gamepad) when deflected. Classic passes `None`, so weapons keep nearest-enemy targeting. **The pointer is the cheese wedge in every scheme** (`render/cursor.rs`; there is no reticle): its tip is the pointer cell, which is the cell `App::aim_point` samples, it carries a dark keyline on its two exposed edges so it survives a bright effect, and in MouseAim play it does not fade while the keyboard moves the rat (`CursorInput::mouse_aims`). It is stamped in screen space after everything else and is not in `PictureKey`.
- The **Controls** screen (from Options) captures a key/pad/mouse press, swaps conflicts, unbinds and resets a scheme; `KeyBind::from_event` refuses Cmd/Super, most Fn combinations and `Ctrl+C`.

Prices and the bank print the gold mark `¢`. Wiping it lives in Options and takes two presses.

Feature-gated on `console` and switchable off with `RATRUN_CONSOLE=0`. **Every state-changing command flags the run "CONSOLE USED"** (so does any run the console starts), which blocks high scores, campaign records, library counters and nest banking. `boss` and `miniboss` take display names as well as kind names, case and punctuation ignored and the article optional (`boss jaguar`, `boss apex-jaguar`, `spawn mudlark`; `boss_names`/`miniboss_names`, with Tab completion); `boss [kind] here` starts the fight beside the rat in the floor's arena rectangle recentred on it (`World::force_boss_here`, which shares `boss::open_fight` with the scheduled arrival) and refuses while a boss is on the floor; `spawn` also accepts a miniboss name. `pause` freezes the simulation only (menus still answer, the HUD shows a PAUSED chip) and ends when the console closes; `bank` and `nest` edit the saved profile and need a trailing `confirm`.

## Audio

`audio.rs` is fully procedural — no asset files. `AudioEngine::new()` returns `None` when there is no device and everything no-ops silently. The simulation never calls audio: systems push `Sfx` variants into `SfxQueue`, and the App drains and de-duplicates them per frame (a 16-shot nova is one sound) and sets music intensity. **Floor music is seven songs** (`src/music/`), each a file of `(delta, midi, gate, velocity)` note tables plus a `Style` (`music::song_for(theme)` is the one theme → song table). **The tracks are hand-arranged.** The original six follow the owner’s audio stems: Sewer "Silent Return" (24 bars), Kitchen "The Great Dash" (24), Laundry "A Minor Waltz" (64 bars in 3/4), Lab "B–C–D♯ Warning" (16), Printworks "Platen Pace" (28), Flatbed "Rat on the Flatbed" (32). Outfall plays "Return Current" at 100 BPM. Its five eight-bar sections form a 96 s loop with electric piano, walking bass, flute, harp and soft strings. Edit those files directly and never regenerate them: `tools/midi2music.py` is the original MIDI converter, kept only as a tool, and its output would overwrite the arrangements. `Style` carries the per-song voice: the original mix/filter fields plus ten with neutral defaults in `Style::base()` (`pad_attack_ms`, `pad_decay_ms`, `pad_hp_hz`, `bass_decay_ms`, `lead_tri`, `lead_decay_ms`, `lead_bright_ms`, `lead_vib_depth`, `stab_decay_ms`, `enhanced_drums` — the last switches on band-passed drums, the open hat, woodblock/timpani and the one-pole bright voices). **`pad_detune` is a frequency ratio** on the pad's second oscillator, not cents: every song is ≤ 0.0045 (about 7 cents; 0.06 is a semitone, and the first tables shipped 0.07–0.20), pinned by `sewer_and_kitchen_have_v2_brightness_and_clear_pad_detune`. `SongSynth` sequences them on a 16th-note clock into procedural voices (24 voices, per-role caps, a limiter and a 0.50 soft ceiling before the DC blocker and song master gain) as an infinite `rodio::Source`. **It plays a 16-bit palette by default** (`Style::patches`/`drum_kit`/`mix_16`: 2- and 4-operator FM, wavetables, Karplus-Strong plucks, seven sampled-style drum kits, an echo send and a master low-pass; all buffers are allocated in the constructor; `Style::base()` is all `Patch::Chip`). `RATRUN_MUSIC` picks the backend (`AudioEngine::music_selection_for_env`): unset or `16bit` the 16-bit palette, `chip` the old chip oscillators on the same songs (bit-identical to the previous build), `classic` the pre-MIDI `MusicSynth`. About 5 ms of CPU per second of audio (it was 2). The `Arc<AtomicU32>` intensity (0..=3) gates layers: calm is bass, pad and light percussion; 1 adds drums and the arpeggio; 2 the lead; 3 everything plus an octave bass pulse on the beats the bass rests. The title and menus play the selected floor's song at the calm tier with a soft entry (`AudioEngine::play_menu_music` → `SongSynth::new_menu`: a 300 ms fade-in and two bars of bass and pad); the Victory plate plays the Flatbed song at tier 3; `RATRUN_MUSIC=classic` keeps `MusicSynth` everywhere. `--music-render <floor> <secs> <out.wav> [--intensity N]` writes a preview without a terminal, a device or the save (with `RATRUN_MUSIC=classic`, the classic synth). Volumes are 0..=100 in steps of 5 and persisted; `RATRUN_MUSIC_VOLUME`/`RATRUN_SFX_VOLUME` pin them for a session.

## Bot and batch tooling

- **Balance files** (`src/tuning.rs`, [TUNING.md](TUNING.md)). Pass `--tuning file.toml` or set `RATRUN_TUNING` before launch. Use `--tuning-dump defaults.toml` to get the commented schema and shipped values. The App, wall, and batch pass an immutable shared tuning into each world's ECS. Effective changes mark the run TUNED and void records and discoveries. Batch reports include the effective hash, file path, and changed fields.

- **`ratrun --ai [N]`** (`spectate.rs`): a wall of N (default 16, max 32) self-playing games on worker threads, each rendering a real `World::draw` into its own pixel buffer, with captions, outcome plates and a summary strip. No audio is ever constructed. Keys: `+`/`-` speed, Space pause, `1`–`9` or a click zoom a game, `Esc` unzoom, `R` restart the wall, `Q` quit. Flags: `--seed S`, `--skill expert|casual`, `--level 1|2|3`, `--once`.
- **`ratrun --bot-batch N`** (`autoplay/batch.rs`): headless seeded campaigns at full speed on `--threads` workers, no terminal, no render, no audio; prints win/clear rates with Wilson intervals, death causes, boss fight lengths, damage by source, boss DPS and timings (`--json` for the machine form). Flags that exist: `--seed`, `--level`, `--practice`, `--carry none|typical`, `--route <floor>` (a campaign takes that floor at its own stage, so `--route laundry` is Sewer → Laundry → Lab; with `--practice` it is the floor played, and `--practice --route flatbed` is the ride), `--skill expert|skilled|casual`, `--cycle-skills`, `--seed-exact`, `--max-sim-seconds`, `--threads`, `--analyze`, `--json`, `--trace`, `--caps W:P`, `--meta none|mid|max`. Companions: `--bot-compare a.json b.json`, `--bot-render a.json`. The report also splits gold by source, counts each miniboss's signatures started and landed, breaks each boss fight down by controller state (share of time, dps landed, distance), and `--json` carries every run's levels (`run_summaries[].levels`) so a mixed-skill batch can be split by skill. Determinism: by default the batch hashes the base seed and run index. With `--seed-exact`, run `i` uses `base + i`. Aggregates are built in run order.
- **`--caps` / `--probe` / `--glyph-card` / `--color <v>` / `--glyphs <v>`** are the terminal-capability flags (`term.rs`; see `TERMINALS.md`). `--bot-batch` is parsed *before* `--caps`, so the batch's `--caps W:P` never collides.
- **The bot** (`game/bot.rs`) is a test instrument: it reads the simulation (enemies, bullets, telegraphed boss hazards, trap pads, the tile map) and feeds `move_dir`/`dash` into `World::update`. Two layers — a 2.4–3.2 s waypoint plan and a per-tick 16-heading danger-field steer — with a per-skill reaction delay. Expert and Skilled look 0.48 s ahead; **Casual's horizon is 0.19 s** and its read of the crowd weaker (`CASUAL_HORIZON`, `CASUAL_CROWD`), and it reads a miniboss tell through its own coarse timer, so it leaves a warned shape late. A shop leg follows the bot's own flow field to the threshold (`shop_flow`), with a stronger goal pull than a waypoint's. It claims chests and picks upgrades through the same paths as the App. Measured ladder (48 campaigns a skill, batch seven): about 92 / 85 / 38 % wins. **Batch twelve (four levels, 16 campaigns a skill, seed 1000): 63 / 31 / 6 %.** Nearly every loss is on level one between 3:30 and 8:00: the bot kites, the starting Gnaw is a 20 px bite, and a rat that has taken eight cards has three low-rank weapons and no defensive stacks. Levels two to four clear at 91 / 86 / 89 % with kill counts and fight lengths on the old targets. Hit points cannot fix level one (its bodies are one or two bites each by 5:00); the levers left are the bite's reach, the first cards' cost, or teaching the bot to stand and bite. `--practice` on the bare loadout plays level one's scalars, as the App does.
- **Balance record** ([`docs/balance/README.md`](docs/balance/README.md)): the campaign balance studies, solved overlays, confirmation data, and the headless 5-run tweak-testing protocol.

## Where to add content

Every item has exhaustive `match`es that must be touched or the build fails. Grep the type name; do not guess.

- **Weapon**: `WeaponKind` (`game/weapon.rs`, append-only `all()`; `WEAPON_SLOTS` is asserted in tests) with stats, flavor, desc; a firing pattern in the matching `systems/weapons*.rs` (tag the bullet's `weapon`, emit `vfx::emit_weapon_fire`/`emit_weapon_hit`, pick an `Sfx`); the damage-ledger column is the kind index; an `art_icons` icon; the Library ARSENAL row.
- **Enemy**: `EnemyKind` (`game/enemy.rs`, append-only) — `base_hp`, `speed`, contact damage, xp, `gold_row` (`game/shop.rs`), radius/size class, `steer`, and its arm in `archetype` (the base body it behaves as; return `self` once it has its own state machine); behaviour in `systems/enemy_move.rs`/`enemy_wave3.rs`/`enemy_wave4.rs`; art in `art_enemy` (a kind without a row in `bespoke_body`/`bespoke_lod` draws its archetype recoloured through `recolor_body`); the death cue in `game/vfx.rs`; glue-board weight in `systems/traps.rs::enemy_units`; the bot's hazard knowledge in `game/bot.rs`; the damage-cause label and kind name in `autoplay.rs`; the Library BESTIARY row; and that kind's one row in its floor's `slots` table in `game/roster.rs`. Selection is `roster::pick_kind` (`director::pick_kind_for_theme` wraps it); the roster's module docs list the remaining exhaustive arms a new kind must satisfy.
- **Miniboss**: `MinibossKind` (`systems/miniboss.rs`) with `name`, `body_radius`, `active_duration`, one row in `miniboss_behaviour.rs` for its temperament and two signatures, its row in `MinibossKind::all` and art in `art_miniboss`; its floor's `appointments` row in `game/roster.rs`; `MINIBOSS_TIMES` if the schedule changes; the console completion table; the Library row.
- **Boss**: `BossKind` (append-only) with `base_hp`, `pool_for_theme` (plus the `*_POOL` const — a second exhaustive match), `for_theme`, the `art_boss_*` module (its view structs/state enums are the spec), a controller in `systems/boss/<name>.rs`, the controller dispatch, the `BossState` enum, smoke hooks in `game/smoke.rs`, name/`all`, console `boss` completion and the Library row.
- **Pickup**: `PickupKind` (`game/gem.rs`, append-only, with 12 kinds ending in Headlamp) — `color`, `name`, art in `art_floor::draw_pickup`, effect in `systems/powerups.rs` + `systems/loot.rs`, the HUD callout, the STYLE glossary and the Library FIELD GUIDE row.
- **Floor/theme**: `Theme` (`game/level.rs`) — `stage`, `palette`, `all`/`playable`, boss pool, `levelgen::layout` furnishing, `levelgen/lights` and hazard placement, `art_floor`/`art_walls`/`art_props`, `lore::map_intro` + victory lines, the audio key/scale, `lighting::theme_ambient` and `lighting::fixtures::colors` (both exhaustive), the `render::campaign` plates, the Library FLOORS row.
- **Passive**: `PassiveKind` (append-only `all()`, asserted `[_; 12]`) — `name`, flavor, desc, `apply_passive_stack`, icon, card/keep rendering, Library row.
- **Splice**: `SpliceKind` (`game/shop.rs`, append-only `ALL`), price/bargain, `apply_splices`, the reader-only multiplier hooks, shelf/reroll logic, art, Library ARSENAL row.
- **Nest track**: `Track` in `meta.rs` (the level table and `Track::prices`), `RunModifiers` + its `apply`, the nest screen rows, and the profile's serde default.
- **Console command**: one `CommandSpec` row in `COMMANDS` plus a handler; set `read_only: false` if it mutates or the cheat flag will not fire. Arg kinds drive Tab completion.
- **Library entry**: a `Key` variant, one `all_rows()` row, and the `Key::category`/`Key::kind_index`/group `facts`/`dossier` arms — `registry_is_complete` fails until they exist.
- **New system**: `fn x_system(…)` in the matching `systems/` file, chained in `schedule.rs` at the exact slot (and added to the module-doc order map), plus a narrow test in the same file. **New resource**: define it in `game/ecs/resources.rs`; insert it permanently in `World::new` (scratch), or give it a spare twin and round-trip it in `begin_tick`/`end_tick` if the facade exposes it.

## Testing strategy

Everything runs without audio or a TTY (`cargo test`; the dev profile's `opt-level = 1` keeps the tick-heavy tests fast). The layers:

1. **Pure-logic unit tests** — math, collision, nav, director, loadout, scores, shop, meta, audio synthesis, damage numbers, term/palette.
2. **Per-system narrow tests** in each `systems/*.rs`: `begin_tick` → `ecs.run_system_cached(…)` → `end_tick`, then assert on facade caches or entity state.
3. **The ported suite** (`game/ecs/tests.rs`): headless ticks across themes and viewports, plus spawn/wall/cap/nuke/tie-order regressions.
4. **`TestBackend` end-to-end** tests (`app.rs`, `render/*`): the full App and render stack with simulated keystrokes, clicks and pad events.
5. **Gates**: `levelgen::tests::map_trace_pin` (map pin), `ecs::tests::the_same_seed_plays_the_same_run` (the twin-run sweep) and the generator's cost and statistics measurements.

### The suite's budget rules

The suite is CPU-bound (~0.5 s of one core per test before the trim), so a test's *span* is the thing to keep small. These are rules, not preferences:

- **No test simulates a full level, and none runs 15 minutes of game time.** If a rule needs the late curve or the boss window, move the clock with the existing setters (`w.elapsed = director::BOSS_TIME - 25.0`) and play only that window, as `ecs::tests::enemy_cap_holds_at_the_top_of_the_curve` and `...::enemy_index_is_fresh_at_every_reader` do. Board them at roughly 20 s of game time per case; 100 s is the ceiling for one `headless_run_does_not_panic` theme.
- **Curve tables are sampled, not walked.** `director::live_budget_at`, `pulse_count_at`, `spawn_rate_at`, `elite_chance_at` and friends are pure functions of the curve clock: assert on them at their knots (see `spawn::tests::the_live_budget_curve_holds_its_shape`). When the *director* has to be driven to prove it fills a budget, jump the clock and run a window of 60 s at most (`spawn::tests::the_pulse_respects_the_roster_caps` plays the curve's last 60 s instead of its whole 840).
- **Exhaustive shape, sampled behaviour.** The Library's card scenes follow the same split: `every_registry_row_has_a_scene_or_a_reason` *builds* a scene for every registry row (cheap, and a row cannot ship without an answer), while the three-loop survival run steps a sample — every fifth scene plus every boss and miniboss.
- **No bot runs in the suite.** `game/bot.rs` is a test *instrument* and its unit tests (a decision, a shop leg, a read) are cheap and stay; whole fights, campaigns and batches are run on request with the binary (`--bot-batch`, `--ai`), never inside `cargo test`. The measurement tests already `#[ignore]`d there stay that way (`cargo test <name> -- --ignored --nocapture`).
- **Determinism is proven once, in one place.** `ecs::tests::the_same_seed_plays_the_same_run` is a table-driven twin-run sweep: one row per floor plus the miniboss and boss windows and a weapons row, each at most 20 s, compared on a whole-state fingerprint. Add a row there instead of writing a new twin test. Three named tests keep their own replay because they pin something else on top of it: `world::zoom_tests::the_same_seed_plays_out_identically_at_every_zoom` (zoom is render-only), `systems::fog::tests::fog_never_moves_the_simulation` (fog is render-only) and `campaign::tests::a_four_level_campaign_replays_exactly_from_a_seed` (the per-level seed derivation). Tests that compare two renderings of *one* world (`a still scene draws identically twice`, frozen-frame and bit-identical pose tests) are render-stability tests, not twin runs — they stay.
- **Whole-song audio renders are `#[ignore]`d** (`music::synth`: the two-loop mix targets, the bit-for-bit song render and the per-tier finiteness sweep). A song render is a measurement; the short-slice synth tests gate correctness.

### `debug_assert_enemy_index` is opt-in

Every reader of `EnemyIndex` calls `resources::debug_assert_enemy_index`, which re-sorts the live enemy list and compares it slot by slot. That is ~6 µs at 100 enemies and ~20 µs at 600, 4-8 live calls per tick, so it is **off unless `RATRUN_CHECK_ENEMY_INDEX=1`** (read once and cached, so a normal run pays one relaxed atomic load per call site):

```sh
RATRUN_CHECK_ENEMY_INDEX=1 cargo test --locked        # turn on the guard
RATRUN_CHECK_ENEMY_INDEX=1 cargo test enemy_index     # just the crowd proof
```

Set it when you change spawn/despawn/reap order, the grid rebuild or a reader's window. `ecs::tests::enemy_index_is_fresh_at_every_reader` forces the guard on for its own duration, so the window still has a test that exercises it in CI.

Construct `App::with_options(false, None, ScoreTable::default(), false, Some(seed))` (the test module's `test_app()`) / `World::new(theme, seed)` to stay silent and deterministic. **Never `App::new` in a test**: it loads and persists the player's real save. `ScoreTable::load`/`save` are additionally inert under `cfg(test)` unless `RATRUN_DATA_DIR` names a directory. Never assert on the map pin whose failure output you have not read.

### CI

`.github/workflows/ci.yml` runs the full `cargo test` and `cargo clippy --all-targets -- -D warnings` on `ubuntu-22.04` only, and `cargo check --locked` on macOS and Windows (those runners are there for `cfg(unix)`/`cfg(windows)` compilation, which `check` finds without building every test target). Each job caches `~/.cargo` and `target` with `Swatinem/rust-cache` (pinned); the wasm pass lives in `web/build.sh`, not in CI.

## Spinning up workers

When spinning up workers, use `/orchestration` to split the work across parallel child agents. They must show up under the **same workspace in Orca** as the coordinator, so the owner can tab-tile them in one window.

## Standing rules for workers in this repo

- **Feature workers do not compile or run tests.** Do not run `cargo` (build, check, test, clippy, run, fmt), `rustc` or `rustfmt` in a worker checkout. The coordinator or a designated integration worker builds and verifies the batch in the integration checkout. Write the tests you would have run and say what is unverified.
- **Integration builds bump the patch version.** Every integration bumps the patch number (`0.4.3` → `0.4.4` → …), adds its `CHANGELOG.md` section under `## <version> (<YYYY-MM-DD>, playtest build)` with a fresh empty `## Unreleased` above, names the build number in its commit message and report, and installs `/Users/joe/dev/ratrun/target/playtest/ratrun`; releases are tagged only when the owner asks.
- **Finished workers are cleared from Orca.** Once a worker reports `worker_done` its subtask is deleted so the workspace stays readable. Do not leave work un-reported, and do not start new work after reporting.
