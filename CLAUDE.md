# CLAUDE.md

Guidance for coding agents working in this repository: the architecture, the commands, the rules that bind every change, and how to test. Where this file and the code disagree, **trust the code** and fix this file.

Rat Run is a terminal **bullet-hell horde survivor** (Vampire-Survivors-shaped) in Rust on `ratatui`. The player only moves; weapons auto-fire; kills drop XP that pays a 1-of-3 upgrade loop; a floor builds from a fifteen-minute difficulty curve into a boss fight. The simulation is a `bevy_ecs` world behind a `World` facade; the world is drawn into a half-block pixel buffer, lit in 2D, and composited under ratatui HUDs and menus. Read `STYLE.md` before writing any player-visible string.

## Commands

```sh
cargo run --release                 # play (needs a real TTY)
cargo run --release -- --ai 16      # wall of 16 self-playing games
cargo run --release -- --bot-batch 30 --seed 1000 --json > batch.json
cargo build
cargo test                          # full suite (see Testing strategy)
cargo test <name>
cargo clippy --all-targets          # lint (keep clean)
cargo run --release -- --caps       # resolved terminal caps, then exit
cargo run --release -- --probe      # caps + this terminal's keyboard-protocol answer
cargo run --release -- --glyph-card # test card: half / quadrant / sextant / octant blocks, then exit
cargo run --release -- --prof-bench --color truecolor --floor sewer --at 300 \
    --mode app --cfg 120x40:1.0:full:600   # dev only: headless frame-cost benchmark
cargo run --release -- --music-render sewer 60 /tmp/sewer.wav --intensity 3   # dev only: a floor's song as a WAV
```

**Profiling (dev only):** `--prof-bench` (`src/profbench.rs`, stage timers in `src/prof.rs`) plays one floor forward with the bot and prints one JSON line per `--cfg COLSxROWS:ZOOM:TIER:FRAMES[:free]`. `--mode direct` times `World::draw` stage by stage and prints a `frame_hash` of every pixel (the proof that a render change is bit-identical); `--mode app` runs the real update/render/present path against a counting sink (frame p50, present cost, bytes and `write` calls per frame); `--mode title` / `--mode paused` measure the idle screens; `--mode encode` and `--mode audio` are micro-benchmarks. `--still`, `--horde N`, `--nolight` and `--sample FILE:SECS` shape a run. The stage scopes cost one relaxed atomic load when the bench is off. `RATRUN_PROF_NO_AUDIO=1` keeps a PTY harness from opening an audio device. Not a player-facing flag: it never touches the terminal or the save.

**Toolchain:** `rust-toolchain.toml` pins `1.100.0` (`bevy_ecs` 0.20 declares `rust-version = 1.95` and the machine default is older). rustup installs it on demand — never touch the global default.

**Build prerequisites:** `rodio`/`cpal` link ALSA, so Linux needs `libasound2-dev` (the runtime `libasound.so.2` alone is not enough). The default `gamepad` feature pulls `gilrs`, which links `libudev` on Linux (`libudev-dev`); `--no-default-features` builds without gamepad *and* without the console.

**Features** (`Cargo.toml`): `default = ["console", "gamepad"]`. `console` is the backtick admin console (also switchable off at runtime with `RATRUN_CONSOLE=0`).

**Screenshots:** `RATRUN_DUMP=<target> cargo test dump_frame_ppm` writes `/tmp/ratrun_<target>.ppm` (each cell → fg-top/bg-bottom pixels) plus `ratrun_<target>.txt` (cell text); with `RATRUN_DUMP_DIR=<dir>` all three land there, including `<W>x<H>-<target>.ansi` (the frame as truecolor SGR, which is what the README images are rasterised from). No-op unless `RATRUN_DUMP` is set. Targets include `title`, `story`, `select[-N]`, `library[-arsenal|-field|-floors]`, `library-boss[-N]` (boss `N` of `BossKind::all()`, selected by key), `nest`, `nest-started`, `nest-max`, `pause-nest`, `end-bank`, `options`, `graphics`, `controls`, `console`, `map`, `map-early`, `levelup`, `autopick`, `chest`, `chest-evo`, `shop`, `floor-<name>` (15 s of play on sewer/kitchen/lab/laundry/printworks/flatbed), `bossfight-<N>`, `miniboss-*`, `cobra*`, `trailer*`, `laundry`, `printworks`, `superdash`, `superdash-charge`, `superdash-release`, `firelit` and per-evolution captures (`evo*`, `downspout`, `ripcord`, …); anything unrecognised plays ~15 s of the Sewer and dumps a gameplay frame. `RATRUN_DUMP_SIZE` (default `120x46`), `RATRUN_DUMP_FLOOR` (for `select`), `RATRUN_DUMP_ZOOM` (re-frames any in-run capture), `RATRUN_DUMP_FRAMES` (for `bossfight`) and `RATRUN_DUMP_CTRL` tune it. The HUD scenes (`hud-boss`, `pause`, …) come from `RATRUN_HUD_DIR=<dir> cargo test capture_hud_neon`. The Library's animated cards come as filmstrips: `RATRUN_LIBANIM_DIR=<dir> RATRUN_LIBANIM=<names|tab|group|all> [RATRUN_LIBANIM_SHEET=8] cargo test capture_library_filmstrips` (8 frames a loop; `RATRUN_LIBANIM_TIMINGS=1 cargo test library_scene_timings -- --nocapture` prints a card frame's cost). A `library*` dump shows the posed plate, because it captures inside the card's rest window.

**Headless without a TTY:** `cargo run` needs an attached terminal; piped input makes `enable_raw_mode` fail with `os error 6`, which the app handles cleanly (no panic, terminal restored). To drive the binary headlessly you must allocate a PTY *with* a window size (`script` leaves winsize 0×0 → empty render); prefer `TestBackend` for deterministic rendering tests.

## Worker rules (this repo, all agents)

- **No compiling and no running.** Workers do not build, test, clippy, fmt or run the game. The coordinator merges the batch into the main checkout, compiles **once**, and fixes the breakage there. Write the code and the tests you would have run, and report what is unverified.
- **Finished workers are cleared from Orca.** Subtasks are deleted once they report, so do not leave work un-reported and do not start new work after reporting.

## Architecture

`main.rs` (terminal + 60 FPS loop) → `app.rs` (state machine) → `game/world.rs` (facade) → `game/ecs/` (one chained schedule) → `render/` (pixels, HUD).

| path | owns |
| --- | --- |
| `main.rs` | terminal lifecycle, input thread, frame loop |
| `app.rs` | screen state machine, run/overlay state, audio bridge |
| `present.rs` | the frame writer, the cell diff + escape encoder, frame pacing |
| `term.rs` | capability detection, colour folding, glyph sanitising |
| `prof.rs`, `profbench.rs` | dev-only stage timers and the `--prof-bench` harness |
| `input.rs`, `controls.rs`, `gamepad.rs` | keys → actions, remapping, pad |
| `scores.rs`, `meta.rs`, `config.rs` | save file, the nest, data paths |
| `lore.rs`, `titleart.rs`, `console.rs` | story text, the rat plate, admin console |
| `audio.rs` | procedural SFX, the classic music synth, the engine |
| `music/` | the six floor songs (all arranged by hand from the audio stems), `SongSynth`, `--music-render` |
| `autoplay/`, `spectate.rs` | bot, batch runner, `--ai` wall |
| `game/world.rs` | facade: fields, one tick, one frame |
| `game/ecs/` | schedules, resources, components, `systems/`, `harness.rs` |
| `game/levelgen/` | the map generator and its validator |
| `game/` (rest) | data + rules: `level`, `enemy`, `weapon`, `loadout`, `director`, `shop`, `campaign`, `library`, `bot`, `nav`, `collision`, `fog`, `hazards`, `particle`, `smoke`, `vfx`, `art_*` |
| `render/` | framebuffer, lighting, HUD, menus, minimap, overlays, ink |

- **`main.rs`** enables raw mode first (then arms a `TerminalGuard` drop guard), enters the alternate screen with mouse capture + focus reporting, asks the terminal for its keyboard protocol (`term::query_keyboard_enhancement`, a 300 ms budget; crossterm's own helper waits 2 s), pushes `REPORT_EVENT_TYPES | REPORT_ALL_KEYS_AS_ESCAPE_CODES` when it answers, and re-queries to learn whether a **lone** Ctrl reports (that decides Ctrl-dash vs Space-dash). It reads crossterm events on a joined reader thread, coalesces mouse motion, caps work at `MAX_EVENTS_PER_FRAME`, computes `dt` (capped at 50 ms), calls `app.update(dt)` every iteration (60 Hz), and hands the frame to `present::FrameLoop`, which presents inside a DEC 2026 synchronized update. `FocusLost` releases every held key. Restore is idempotent and runs on every exit path including panics.
- **`present.rs`** owns everything between a rendered `Buffer` and the terminal:
  - `FrameOut` — the backend's writer. A frame is collected in memory and sent in **one** `write`; it never flushes on drop, so a panic mid-frame cannot spill cells onto the restored terminal. Setup and restore write straight to stdout.
  - `Presenter` — `Terminal::draw` taken apart. It owns the previous frame, so an unchanged frame sends **zero bytes**, and `invalidate()` (focus regained) or a new size clears and repaints everything. `PresentMode::Direct` (the default) diffs the two buffers in one pass and writes cursor moves, SGR and glyph bytes by hand — a run of adjacent cells in the same colours is one move and one SGR; `RATRUN_PRESENT=ratatui` (and `NO_COLOR`, which crossterm honours) selects ratatui's `Buffer::diff` + crossterm's `Backend::draw` instead. A frame holding a wide glyph or a cell with a diff option goes through ratatui's diff (its trailing-cell rules) with the direct encoder. The two paths are pinned equal by `present::tests::a_scripted_session_looks_the_same_through_both_paths_at_every_colour_depth`, which replays both byte streams into a small VT cell model across play, pause, level-up, map, options, console and resizes at truecolor, 256 and 16 colours. The presenter runs **after** `term::sanitize`, so colour folding stays in `term.rs`.
  - `FramePacer` — whether to render at all. `Screen::Playing` renders every frame (`App::frame_demand`). Every other screen renders at 30 Hz, and at once when `App::repaint_urgent` says so (any input event incl. pointer motion and pad, a resize, focus, a screen change, an open console, the zoom ease, the volume/zoom read-outs, auto-pick spacing). A screen whose last 45 rendered frames changed no cell is treated as still and only probed every 250 ms; a probe that changes a cell returns it to 30 Hz. So stillness is measured, not declared per screen — but **a new animation on a menu screen that can start without input after 1.5 s of stillness should be added to `repaint_urgent`**, or it starts up to 250 ms late.
  - `SizePoll` — the terminal's size is asked for on `Event::Resize` and once a second, not every frame (`crossterm::terminal::size` opens `/dev/tty`).
  - The `--ai` wall keeps `present::synchronized_frame` (ratatui's own draw through `FrameOut`).
- **`app.rs`** is the only module that knows about screens. The real `Screen` enum: `Title`, `SectorSelect`, `Story`, `MapIntro`, `LevelIntro`, `Playing`, `LevelUp`, `Paused`, `Options`, `LevelComplete`, `KeepThree`, `Victory`, `End`, `Chest`, `Shop`, `Library`, `Controls`, `Graphics`, `Nest`. The title rows are START RUN, the sector row, OPTIONS, LIBRARY, THE NEST, QUIT. It drives the world during `Playing`, freezes it under overlays (an open map pauses too), owns menu/level-up/shop/keep state, finalizes scores, banks the nest and bridges audio.
- **`game/world.rs`** keeps the legacy public fields as real fields (`player`, `level`, `elapsed`, `kills`, `score`, `gold`, `pending_levelups`, `pending_chests`, `pending_shop`, `game_over`, `won`, `level_complete`, `sfx`, `rng`, `cam`, `viewport`, `particles`, `damage_numbers`, `fog`, …) so callers between ticks keep working, plus read-only HUD accessors (`boss_hp`, `boss_offset`, `enemy_count`, `last_pickups`) that walk the ECS world for `&self`, and allocating `SpawnId`-ordered snapshots (`enemies()`, `bullets()`, `gems()`, `pickups()`, `pools()`) for tests only. `update()` runs one tick; `draw(&mut PixelBuffer)` runs one frame.

### The facade round-trip (`game/ecs/resources.rs`)

Singleton state is authoritative on `World` *between* ticks and in the ECS world *during* one:

1. `begin_tick` inserts the per-tick resources (`TickInput` — `dt`, `move_dir`, `dash`, `active`, `aim`, the dash hold edges `dash_down`/`dash_held`/`dash_released` and a scripted `charge` —, `Viewport`, `NukeTick`, `LevelIndex`, `DifficultyLevel`, `DebugFlags`, `Cvars`, `BossOverride`, `RunCounters`, `Shake`, `SfxQueue`, `NextEnemyId`, `LastPickups`) and **moves** `rng` (via `RngRes`), `level`, `player`, `particles`, `damage_numbers`, `director`, `flow` and `fog` in with `swap_in`. Every round-tripped type has a spare twin built at `World::new`, so the round trip allocates nothing.
2. `schedule.run(&mut world.ecs)` — one thread, one chain.
3. `end_tick` swaps them back with `swap_out` and copies the counters out.

Nothing is copied out per tick: entity components live in the ECS world for the whole run, so `Entity`/`SpawnId` are stable. Writes between ticks (`world.player.hp = …`, `world.pending_levelups = 1`, app tests) reach the next tick, and reads right after `update()` see its results. `begin_tick`/`end_tick` are public — that *is* the per-system test harness. Never touch a facade singleton while a tick is open; use `world.ecs.resource_mut::<T>()`.

### Components and resources

- Components are **coarse**: one legacy struct per component (`Enemy`, `Bullet`, `Gem`, `Pickup`, `Gold`, `Chest`, `Pool`, `Boss`) plus `SpawnId(u64)`, a monotonic spawn-order tag, and wave-3/4 markers (`Miniboss`, `Infection`, `Wick`, `AcidDrop`, `MilkTooth`, `CheeseString`, `FairyRing`, `CorrosiveChannel`, `DeadLetterPacket`, `EchoSpoke`, `Lash`, `TrapSlow`, `InkSlow`, … — see `game/ecs/components.rs`). Do **not** split them into Position/Health: art and behaviour take `&Enemy` and friends.
- Resources are the per-tick singletons above plus permanent scratch (`NextSpawnId`, `SpatialGrid`, `EnemyIndex`, `GridScratch`, `NeighborScratch`, `PickupScratch`, `DamageLedger`, `ActiveFx`, `LaserFx`, `LaserCopy`, `DashTrack`, `EvoRuntime`, `MeleeNudge`, `XpBank`, `BossDue`, `BossVirus`) and the wave-3 runtimes (`TrapRuntime`, `GateRuntime`, `MinibossSchedule`, `ShopBook`, …).
- `EnemyIndex` caches the `SpawnId`-ordered enemy list the spatial grid's buckets address (the legacy `self.enemies[j]`). It is valid only while no enemy has spawned or despawned since the grid was built; every reader calls `resources::debug_assert_enemy_index` (compiled out in release). See *Determinism*.
- `Enemy::id` (damage-number identity) comes from `NextEnemyId`, never a `Vec` index. Systems push `Sfx` into `SfxQueue`; **there is no audio system** — the App drains and plays.
- Systems spawn with `commands.spawn((component, next_id.take()))` and despawn with `commands.entity(e).despawn()`. `World::spawn_*`/`clear_*` are for tests and setup only.

### The tick schedule — order *is* behaviour (`game/ecs/schedule.rs`)

ONE `Schedule`, one thread, `multi_threaded` off. `chain()` inserts `ApplyDeferred` after any system that took `Commands`, so an entity spawned by one system exists for the next. The real order (the module doc carries the full table):

```text
powerups → traps → hazards → floor_sewer_slow → player → puddles → fog::reveal
  → [gates: passage, cache, door, shop::threshold]
  → flow_refresh → director → miniboss → boss_spawn → boss::megarat::boss_summon
  → enemy_steering → enemy_fire → grid_build → separation → wall_resolve
  → grid_refresh → fire_weapons → active_weapons
  → [spiked_tail] → [laser_eyes, super_dash, melee_nudge]
  → acid_rain → hantavirus → bullets → pools
  → boss_damage → boss_update → [cobra::coil_block]
  → player_bullet_hits → enemy_bullet_hits → contact
  → [giant_stomp, milk_teeth, fondue_tines, fondue_string] → fairy_ring → drain_cleaner
  → roll_call → dead_letter → ripcord → wave3 → wave4
  → [floor_sewer, floor_kitchen, floor_lab, floor_laundry, floor_printworks, floor_flatbed]
  → approach_sfx → trailer
  → hantavirus_death → reap_enemies → gems → treasure → pickups
  → nuke_reap → particles → damage_numbers → shake → outcome
```

Load-bearing adjacencies (each is commented in the file):

- `traps`/`hazards` run **before** `player` so a glue/ink slow folds into this tick's `TickInput` throttle, and their damage lands before the reap (a trap kill takes the normal loot path).
- `gates`/`shop::threshold` sit after the fog reveal and before the flow refresh, so all three see the rat's post-move cell.
- Boss spawns are before `grid_build`; `megarat::boss_summon` exists because a boss controller cannot take `Commands` and may only add `Enemy`s in that slot.
- Every weapon/melee/area damage pass sits between `grid_build` and `reap_enemies`, so a kill this tick is reaped this tick (and loots this tick).
- The six per-floor roster systems (`systems/floor_<floor>.rs`, one per `Theme`, each a no-op off its own floor) run right after `wave4`, then `approach::approach_sfx_system` (writes only `SfxQueue`); `floor_sewer_slow` sits with `hazards` before `player` so the Sump Leech's tongue slow folds into this tick's throttle. Their tells are drawn on the hostile layer from the same geometry the hit tests read (`World::floor_tell_reach`/`draw_floor_tell`, `art_roster_*.rs`).
- `powerups::giant_stomp_system` (the Growth Serum) heads the nested chain right after `contact`: a body touching the giant is stomped on the same tick, before every evolved-weapon pass, the Hantavirus death jump and the reap, so a crushed body jumps, is reaped and loots this tick. It spawns nothing and draws no rng.
- `reap_enemies` right before `gems` (drops collect the same tick); `pickups` right before `nuke_reap` (a Nuke re-reaps); `outcome` last (loss beats win).
- The chain is split into several tuples only because `IntoScheduleConfigs` stops at 20 entries; later groups are explicitly anchored `.after(...)`. Keep the module-doc order map in sync.
- `build_settle_schedule()` is the legacy `finished()` path: particles and damage numbers only. `damage_numbers_system` lives in `schedule.rs` because that file owns tick order.

## Determinism rules

Single-threaded, and **query iteration order must never decide anything**. Wherever the old code meant "first / next / in-`Vec`-order", iterate sorted by `SpawnId`:

```rust
for (id, mut e) in enemies.iter_mut().sort_by_key::<&SpawnId, _>(|id| id.0) { … }
```

That covers nearest-enemy ties, separation nudges, per-enemy rng draws, drop order, bullet spawn order and draw order. The **number and order of rng draws** are part of the spec: draw only where the old code drew. A boss owns its own stream (`BossRng`, seeded from the run seed + a per-kind salt) so boss behaviour never perturbs the main one; the shop rolls its shelf from its own `StdRng`, never the simulation's.

**The simulation viewport is App state, not a render side effect.** `App::render` writes `world.viewport` on a resize because the viewport drives spawn rings and offscreen placement; `World::draw` never touches it (it sets its own `render_viewport`). So a run drawn at a resized terminal — or at any zoom, or never drawn at all — simulates identically; pinned by `world::zoom_tests::the_same_seed_plays_out_identically_at_every_zoom`. Everything render-only (zoom, lighting, smoke, fog reveal, the ink pass, the Library survey) must stay render-only.

**Spawns land out of sight at every zoom** (`systems/spawn.rs`). "Out of sight" is the **widest** view: the simulation viewport × `MAX_ZOOM_OUT` (2.0, a plain number pinned equal to `render::zoom::MAX`; the current zoom is never read, so every zoom still simulates identically). The ring is that view's half-diagonal + 16 px (157 px at 120×74, 195 px at 160×80; it was 120), and `off_screen`, the flank members, the room waves and the miniboss arrival all test the same rectangle. `sample_ring` is a fixed four-pass ladder (ring → 1.5× outward → the 1.0-view ring → any legal ring point), then a staging room outside the 1.0 view, any staging room, the nearest clear cell, and finally a skip; `SpawnScratch::fallbacks` counts the rungs. Measured in bot play (six floors × two viewports, 4 min each): 57 % of placements were inside the 2× view before, 0 of 5,870 after (5 through the arena-clamped camera, on a large terminal near a map edge), no skips. **The approach boost** pays the longer walk back: an ordinary body outside the *unzoomed* view moves at `APPROACH_BOOST_GROUND` ×2.0 (flyers ×1.3; never a named body, an elite, or a kind at ≥ 40 px/s) and is restored to exactly its spawn scale on entering it (`Director::approach` is the registry; no rng). **The opening pulse** is ×0.7 the interval for the first 12 s (`director::OPENING_SECS`/`OPENING_INTERVAL_MULT`: ten single bodies instead of seven), because bodies now die further from the rat and the first card came ~3 s late. Two ignored measurement tests print the tables: `spawns_inside_the_widest_view_in_bot_play` and `opening_pace_in_bot_play` (`cargo test <name> -- --ignored --nocapture`).

**`EnemyIndex` validity window.** `enemy_move::grid_build_system` and `grid_refresh_system` build the `SpawnId`-ordered cache once per tick with the `SpatialGrid`. It may be read *instead of* sorting only while nothing has spawned or despawned since the build: `separation`, `wall_resolve`, `grid_refresh`, then (after the refresh) `fire_weapons`, the active and wave-3 weapon passes, `bullets`/`pools`, the boss passes, `player_bullet_hits`, `enemy_bullet_hits` and `contact` — nothing at or after `reap_enemies`. It is stale in `enemy_steering`/`enemy_fire` (the director may have queued spawns) and after `reap_enemies`/`nuke_reap`/`clear_enemies`. `debug_assert_enemy_index` compares the cache with a fresh `SpawnId` sort *including contents*, so `cargo test` verifies the window on every tick of a full run.

**Goldens (`game/ecs/harness.rs`).** Six scripted seeded games (Wander and Evade × Sewer/Kitchen/Lab seeds) at 60 ticks/s for 60 s; the whole state is folded into an FNV trace hash every half second and compared with `CASES`. Any change in a simulated number, an rng draw or its order, or an iteration rule moves a hash. Failure prints **every** moved row already formatted for `CASES` — paste the whole list in the change that deliberately moved them, never hand-edit one row. `same_seed_same_run` also proves the weaker property directly. **Never edit a hash to make an accidental change pass.**

**The map pin (`game/levelgen/mod.rs` `TRACE_HASHES`).** Pins the exact output of `generate_once` — every tile's kind and neighbour mask plus every placed object — for 20 seeds × the five campaign `Theme`s. Regenerate only when a layout/maze/placement stage changes output on purpose: `RATRUN_LEVEL_TRACE=1 cargo test map_trace_pin -- --nocapture` prints the new table.

## Rendering

`render/framebuffer.rs`: `PixelBuffer` is a `width × (height*2)` RGB grid, blitted into ratatui one `▀` per cell (foreground = top pixel, background = bottom). World coordinates are world-pixel `Vec2`; `world.cam` + `w2s()` map to screen. The camera follows the rat clamped to the arena, plus a decaying shake offset, of which the camera takes `World::shake_scale` (`world::SHAKE_SCALE`, 0.65, is the default; the Graphics page's SCREEN SHAKE row sets it to 0 / 50 / 65 / 100 %). Every effect's amplitude is cut in that one place, durations are untouched, and nothing simulated reads the camera.

**`World::draw_scene` order (real):** floor → floor marks → floor stains → boss ground layer → wall ground layer → boss thresholds → object ground layer → wall bodies → props → light fixtures + ambience → pools → evolved ground effects (channels, fairy rings) → Acid Rain drops → gems → gold → chests → pickups (with halos) → the Wind-up Mouse decoy → enemies (crowd LOD by visible count) → boss bodies (ground) → friendly bullets → cheese strings and milk teeth → the rat → airborne boss bodies → wall overhangs + thresholds + object foreground layer (lintels over the rat) → smoke → particles/shockwaves → Super Dash comb → Roll Call quotes → **the lighting pass** → **the hostile layer** → (debug) hitboxes.

Sprite art lives in `game/art_*.rs`, one module per subject (`art_floor`, `art_walls`, `art_props`, `art_enemy`, `art_miniboss`, `art_traps`, `art_rat`, `art_trailer`, `art_wave3a`, `art_icons`, one `art_boss_*` per boss). **Do not edit art modules to fix gameplay**: their view structs and documented constants are the spec where art and gameplay disagree (`CONTENT_PLAN.md` §9).

**Zoom** (`render/zoom.rs`): ladder `0.5, 0.75, 1.0, 1.25, 1.5, 2.0`, eased over ~0.15 s, stepped by wheel, `Z`/`X`, the options row, or middle click/`R3` to reset. `z > 1` shows more world. Zoomed out, each screen pixel owns a box of world pixels and `PixelBuffer::resample_to` writes **one** source pixel per box, unblended — the most salient pixel if the box holds a feature, else the first — so thin things survive at full contrast instead of blurring; zoomed in the box is a single source pixel (nearest neighbour). Integer arithmetic throughout, so 1:1 is bit-identical.

**Sub-cell detail** (`render/subcell.rs`; **always on** where the terminal has the glyphs — there is no option and nothing is saved; `subcell::resolve(env, term::block_set())`). Zoomed out (eased zoom > 1.05), `World::draw` resamples the world buffer a second time onto a `2·cols × k·rows` grid and `App::draw_game` blits `World::detail()` instead of the half-block buffer: quadrants (k = 2) at 1.25×, sextants (k = 3) from 1.375×, octants (k = 4) from 1.75× — at 2× the octant grid is the world buffer 1:1. `subcell::encode` gives each cell two colours by a two-means split (integer, salient sub-pixels weighted up) and the pattern glyph between them; a cell without contrast (`FLAT_SPREAD`) is the plain `▀` it always was. The half-block picture is still drawn in full, because the damage digits and the ink pass stamp it: `DetailFrame::overlay` carries every pixel they changed onto the sub-pixels that half covers and flags it, so a mark is never smaller than today and its colour is exact. The pattern → glyph tables (`subcell/tables.rs`) are **generated** from Unicode character names by `subcell/gen_tables.py`; do not hand-edit them. Which set may be used is `term::BlockSet` (`--glyphs quad|sextant|octant|half`, `RATRUN_GLYPHS`, else Ghostty/Kitty/WezTerm → sextant and everything else, a multiplexer and the safe glyph set → half); `RATRUN_SUBCELL=off|quad|sextant|octant|auto` pins a set for a session (captures), and octants are only ever reached by asking. The resolved set is in `PictureKey`. Render-only.

**1× smoothing and antialiasing** (`subcell::Smooth { Off, Epx, Strong, Xbr, Wedge, XbrCrisp }`, default `Xbr`; `RATRUN_SMOOTH=0|1|2|3|4|5`, console `smooth [off|on|strong|xbr|wedge|crisp]`, read-only). At zoom ≤ 1.0 the sub-cell frame is built from the half-block picture. **Xbr** (`subcell/xbr.rs`, through `DetailFrame::xbr_from`) is FFmpeg's `xbr=2` filter (`FILT2`) ported to integers: each corner of a pixel weighs the two diagonals through it over a radius-two neighbourhood (YUV distances) and leans toward its nearer axial neighbour by 1/2, or 3/4 with a 1/4 spill on a 2:1 slope. A cell's 2 × 4 block of blended sub-pixels is then fitted in **two colours that may be blends**: a two-means split (`xbr::split`, `encode`'s seeds and refinement) on quadrants, sextants (block rows weighed 3:1, 2:2, 1:3) and octants as the terminal allows, least squared error wins, and the cell as it was is the first candidate and wins every tie (a recoloured `▀` is a legal answer). Any corner the filter leans is used, a rectangle's included. Its one departure from the reference is the gate: a corner is read only where the pixel differs from both neighbours beside it by `GATE` (6) in some channel, chosen so the pass changes within 6 % as many cells as the approved prototype on the lit reference captures (570–1,250 of 5,520). A cell holding a bright or saturated isolated sample or a pixel of a one-pixel line is frozen and never lends its colour (`xbr::View::feature`). A cell in which no corner leaned is the plain `▀` with its own colours, byte-identical to `Off`. **XbrCrisp** (`smooth crisp`, kept for A/B) reads the same filter conservatively: the `EDGE` test instead of equality, stairs only (a rectangle keeps its corners), sub-pixels kept as weights and fitted by majority, so a cell only ever shows two colours the picture held; it reshapes 60–190 cells on the same captures. `xbr_sim.py` beside it is both passes in Python (dev tool; run it on a `RATRUN_DUMP` PPM to see a rule change before compiling). **Epx** (`smooth_into`) is an EPX/Scale2x upscale: a corner takes its neighbour's own colour (never a blend) where two adjacent neighbours agree across an edge of at least `EDGE` (48, summed channel difference). **Strong** (`subcell::antialias`, through `DetailFrame::antialias_from`) reads stair treads instead: an edge run that ends in a one-pixel step is cut along the straight line through it, each cell becomes an 8 × 8 coverage mask, and the glyph is the nearest of the **eighth blocks** (`U+2581–2587`, `U+2589–258F`, both polarities), quadrants, sextants or octants the terminal has (`subcell/tables.rs` `EIGHTHS` and the `*_MASKS` tables, generated by `gen_tables.py`). A straight wall stays on the cell boundary, a rectangle keeps its corners, and a candidate must be strictly closer than the half block or the cell is left alone. **Wedge** (built, off by default; `DetailFrame::antialias_with`) is Strong plus the 28 wedge and triangle shapes of `tables::WEDGES` (`U+1FB3C–1FB6F`, `U+25E2–25E5`, one polarity each) as further candidates, and `cut_diagonal`: a one-pixel diagonal stroke that is not a bright isolated mark gives up its two off-stroke corners and its neighbours take the corner at each joint, so a tail or a whisker is a band of wedges; it needs sextants or better and is exactly Strong on a lesser terminal. In Epx and Strong a thin pixel (both horizontal or both vertical neighbours differ) is never modified and never a source, so whiskers, telegraph lines, pellet rims and 1 px sprite outlines keep their size; in every level the digits and the ink pass are stamped after and carried exact. `subcell::grid_for_frame` picks the grid: for Epx octant terminals get the full 2×2 per world pixel and quadrant **and sextant** terminals (Ghostty) `Grid::Quad`; Strong and Wedge always `Grid::Quad`; for Xbr and XbrCrisp it is the grid the block is fitted to (the terminal's own, `Grid::Sextant` on Ghostty) while the frame under it stays on the quad grid, so a stamped mark covers exactly its half cell. `App.smooth` → `World.smooth`, in `PictureKey`. With `Off` a 1× frame is byte-identical to the plain half-block blit. Measured at 120×40 (sextant): Off → Strong is +0.15–0.19 ms a frame and +0.3 % bytes; at 200×60 +0.26–0.30 ms; **Xbr, XbrCrisp and Wedge are not measured yet** (Xbr's target is ≤ 0.5 ms at 120×40; it reads 960–2,090 cells a frame on the reference captures, so measure it before trusting that, and raise `GATE` if it is over). In an ordinary 1× scene Strong changes about as many cells as Epx (200–450 of 4,800) and reaches for an eighth block in only a handful; its effect is clearest zoomed in (0.75×). Render-only.

**Lighting** (`render/lighting.rs` + `render/lighting/`): world-resolution, render-only, applied over world pixels before the resample so lights line up at every zoom. `engine` (`LightMap`, `Light`, `LightShape`, falloff, flicker, layer masks, `LightingMode` + the cost-driven quality controller); `fixtures` (per-theme palette/housing for `LightFixture`s: Pendant, Passage, Arena, Broken, Sun, Sconce); `sources` (`LightZone`s — Corridor, Room, Start, Arena, Blackout, Maze — decide ambient and add the rat's aura and dynamic emitters); `shadow` (occluder outlines, prop height → shadow profiles, static vs moving bodies, softness); `ambience` (analytic emitters: Fire, Steam, Drip, Cable, Dust, Fog, Exhaust, Pilot, Fumes, Insects, reconstructed from `(seed, elapsed)`, never from a particle pool); `gallery`/`tests` (captures, assertions). Fixtures are placed by `game/levelgen/lights.rs` by room role; prop/pool/pickup art marks emissive rects so they stay bright. **Small lights** (`Falloff::Small`: every point light of radius ≤ 52 that is not a hard-pool theme light, the `emit` halos, Passage and Broken fixtures off the hard-pool themes, Fire/Pilot/Cable embers) keep the smooth core and add a faint tail (`TAIL_SHARE` 0.19) out to `TAIL_REACH` 1.7 × the stated radius; the tail is not flickered and is painted in flat steps of `MIN_GAIN` (7.0 `Q8.8` units, chosen by measured bytes a frame — its doc comment carries the table), so a dim halo keeps its old size and only the brighter ones throw a skirt. Every consumer of a light's size reads `Light::extent()`. The base level of every floor and zone is `AMBIENT_SCALE` 0.60 of the theme tint (never under `AMBIENT_FLOOR`), and every living enemy takes a 1 px self-lit rim glint in its own colour (`gather_rim`, at most 512 a frame) so a body cannot vanish on the darker floor. `apply_lighting` measures its own cost and drops a tier past budget (`LightingMode::LIVE = [Full, Hard, Coarse, Compact]`, chosen from colour depth: Truecolor→Full, Ansi256→Hard, Ansi16→Coarse). Lighting only shades the playfield: a distant lamp cannot reveal a route (fog and the minimap keep their own rules).

**The lighting effects** (batch 13; `render/lighting/{fx,material,upsample,air,surface,specular,softshadow,motes,overhead}.rs`, contract in `.review/handoff/lighting/CONTRACT.md`; on by default, `RATRUN_FX=0`, console `fx [on|off]`, `World::lighting_fx`). With them **off the lighting pass is byte-identical to batch 12's**. With them on the grid keeps a `fx::LightInfo` beside every sample (the dominant light's direction, colour and contribution, the specular energy, air and fog) and the composite becomes a chain of pixel stages: `surface` (bump relief from the art's own luminance, per material) → `upsample::composite` (a tone curve and a **bilinear** shade instead of 4 px blocks, never blended across a wall face; `upsample::bounce` adds coloured bounce light on the grid first) → `softshadow::entity_shadows` (bodies shadowed by the two strongest lamps that can see them) → `specular` (sheen by material and a directional rim on creatures) → `softshadow::reflections` (lamp streaks on wet floors) → `air::composite` (shafts from fixtures, a small bloom, distance fog) → `motes` (dust in beams at 8 Hz, caustics). `overhead` is rasterised in the scene draw and multiplied into the **lit** picture right after the body shadows (`overhead::draw_deferred` → `apply_lit`; Coarse still darkens the albedo in place): an elliptical ground shadow under every body from an imaginary light over the map's centre, about the body's own width, core 42 % (`OVERHEAD_DARKEN`), kept attached (a ground body's shadow slides at most `GROUND_SLIDE` 0.8 of its half-width + 2 px away from the centre, a flyer's up to 20 px). In the albedo it moved a dark floor by a few levels and its edge was embossed by the bump stage. `softshadow::bake`/`visibility` give Full a soft penumbra. **Materials** ride a second plane of the pixel buffer (`PixelBuffer::set_pen`; `specular::{enemy,boss,rat,giant_rat,prop,pool}_pen`): a pen is a `MaterialKind`, a creature bit and a height class, and an untagged pixel resolves to the theme's floor or wall material (`material::resolve`); a sprite's own cast shadow is stamped with pen 0. Every strength is one constant in `fx::strength`, in units of the concept plates' bold. **Batch 13b brought the faint ones up**: tone, bounce, fog and soft shadow 0.5, rim 0.5, bloom 0.30 (the one the owner wants kept low), long shadow 0.7, specular 0.75, bump, shafts, reflections and motes 1.0. With them: shafts weigh `core²` (the scatter gathers at the lens) and are banded by still, per-lamp rays (`air::rays`); a slime's glint is pulled to white (`specular::WET_WHITE`); motes (30–80 levels, 40 in a 120×80 view) retry two other homes when theirs is dark, so most float in a beam; reflections mirror **fixtures only** (never the rat's aura or a halo); bump normals are steeper (`surface::SLOPE_FULL` 112). Full runs everything, Hard drops the penumbra and the matte materials' sheen, Coarse/Compact keep only the tone and the flat composite. Rules that keep it quiet: a moving halo (gem, projectile, spark: `Falloff::Small` + `LightTag::Moving`) is never a sample's dominant light and casts no body shadow; a flat untagged face takes no sheen; nothing flickers air or bloom (`FxLight::steady`); nothing but the motes reads the clock, and with the effects on the rat's aura breathes in 4 Hz steps. **Bytes are the budget**: a smooth gradient gives every cell its own colour, so `upsample::PAIR_X` shares one horizontal weight per cell pair (only where the two taps are within `PAIR_STEEP` 28: a steep gradient, the aura's rim, showed 2-cell columns), taps within `NEAR_MUL` 20 shade as flat blocks, and air and fog are stepped (the table is on `NEAR_MUL`'s doc comment). Measured at 120×40 in bot play **before batch 13b**: +0.25–0.35 ms a frame, bytes +29 % (Sewer) and +21 % (Kitchen); 13b's release cost and bytes are not measured yet (a dev-build proxy, `RATRUN_DUMP_CHURN`, estimated +7–10 % bytes walking); the cost controller's budget is widened by `fx::FX_BUDGET_PER_PX` while they run, and tests never feed it the wall clock. `RATRUN_DUMP=lit-<sconce|pendant|wet|corner>-<floor>` stages a frozen scene for judging them, and in test builds `RATRUN_FX_SKIP=overhead,body,bump,spec,reflect,air,motes` leaves stages out of a dump. Known: zoomed out to 2×, grout glints under a pendant resample into thin lines. Render-only; `lighting_fx` is in `PictureKey`.

**Graphics settings are a menu page** (`Screen::Graphics`, `render/graphics.rs`, opened from Options): LIGHTING, LIGHT EFFECTS, SMOOTHING (cycles `Smooth::ALL`), FOREGROUND, GLYPH PARTICLES and SCREEN SHAKE (`World::shake_scale`, render-only, in `PictureKey`). They are saved in the save file's `graphics` object (`scores.rs` `GraphicsFile`, serde defaults); the console commands set and persist the same values; an environment pin (`RATRUN_FX`, `RATRUN_SMOOTH`, `RATRUN_FOREGROUND`, `RATRUN_GLYPHFX`) wins for the session and is not written back until the player changes that row.

**The foreground layer** (v2; `render/foreground.rs`, art in `game/art_foreground.rs`; on by default, the Graphics page's FOREGROUND row and the console `foreground [on|off]` (both persisted), `RATRUN_FOREGROUND=0` pins a session, in `PictureKey`; switched off on Library plates). Few, **huge**, dark overhead silhouettes between the camera and the floor, drawn after the lighting pass and before the hostile layer. Eighteen `ForeKind`s, three a floor (`kinds_for`): Sewer MainPipe, CatwalkGrating, ChainHoist; Kitchen ExtractorHood, PotRail, HangingLamp; Lab CableTray, VentDuct, ArticulatedArm; Laundry Clothesline, SteamPipe, DryingRack; Printworks PaperWeb, RollerBeam, HangingProofs; Flatbed TreeBranch, Cloud, PowerLine. **Nothing floats**: every item has an `Attach` and its art shows it. A `Span` runs wall to wall (`span_across` measures the solid walls on the tile grid, `len` bites `SPAN_BITE_PX` 6 px into each, collars at both ends), an `Edge(side)` is rooted on a wall face and reaches `EDGE_LEN_*` 44–90 px into the open, a `Drop` hangs on a chain or cord drawn `DROP_TAIL` 400 px up the screen, and `Sky` is the Flatbed's movers. Draw size is `scale` 2.0–3.4 (a pipe 17–29 px thick in a 120 x 84 px view; the contract's 3.0–6.0 filled the view and read as nothing), parallax is `depth` 1.8–3.0, and **parallax keeps the attachment**: a Span slides only across its long axis and an Edge only along its wall (the other axis rides the world 1:1, so ends stay in walls); a Drop and the sky movers slide on both. Each item's floor shadow stays with the world at (+10, +14) px, up to 0.35 (`SHADOW_MAX` 1.0, not counted as coverage). `generate` places from `(level seed, GEN_SALT)` on its own splitmix stream: corridors of 5+ tiles, one in two, get cross-spans (minimum `CORRIDOR_SPAN_MIN` 28 px), rooms of 12 x 9+ up to three items of a rolled class (`SPAN_MIN_PX` 64 … `SPAN_MAX_PX` 420); never within `START_CLEAR_PX` 96 px of the start, 80 px of a shop hole, 48 px of a rat-hole, door or cache, or `MIN_SPACING` 220 px of another; `MAX_ITEMS` 60. **Sky movers** (`sky_items`, a pure function of `(seed, elapsed)` quantised to 1/30 s, pinned to the view): two clouds drifting 12 px/s whose shadow is the effect (body alpha at most 60), three wires that slide against the camera's cross-bed movement and wrap out of view, a pole passing every 4 s at 300 px/s, and a branch every 5–9 s sweeping tail-ward at 220 px/s from the view's N or S edge, reaching 55–80 % across it. It cannot hide the fight: `blend` clamps to `ALPHA_MAX` 215 and darkens by `DARKEN`; a whole item fades to `ALPHA_FLOOR_RAT` 150 within `FADE_RAT_PX` 56 px of the rat (measured to its body rect; sky movers take a flat `SKY_ALPHA` 185 instead) and to `ALPHA_FLOOR` 28 within `FADE_THREAT_PX` 48 px of a boss or miniboss; the per-pixel **clear disc** cuts every write to `CLEAR_DISC_MIN` 0.25 inside 14 px of the rat, back to full at 30 px; and when the items' body rects would cover more than `COVERAGE_PCT` 30 % of the view every alpha is scaled down (to `COVERAGE_ALPHA_MIN` 0.5 at most) so a big item is seen through, never cut off, with a hard writer cap at `COVERAGE_SKIP_PCT` 60 %. Kinds that sway do so in held steps (`SWAY_HZ` 3), so a still scene repaints nothing. Measured at 120x40: no cost with nothing in view, +0.08 ms p50 and +6.5 % bytes on the Flatbed (movers always in view). Captures: `RATRUN_DUMP=floor-<name>` with `RATRUN_DUMP_FORE=n` (`RATRUN_DUMP_FORE_KIND=span|room-span|corridor-span|edge|drop|<kind>`, `RATRUN_DUMP_FORE_RAT=dx,dy`, `RATRUN_DUMP_FORE_HORDE=n`), `RATRUN_DUMP_SKY=branch|pole|cloud`, `RATRUN_DUMP_NAME`. Render-only; the ink pass and the hostile layer are above it.

**Round-glyph particles** (`render/glyphfx.rs`; on by default, the Graphics page's GLYPH PARTICLES row and the console `glyphfx [on|off]` (both persisted), `RATRUN_GLYPHFX=0` pins a session, **not** in `PictureKey`). The owner's mock-up (`.review/glyphs/`) found three round glyphs worth drawing inside a half-block picture, and this is exactly those three in the restrained strength: dust motes (`·` `∙` `◦`) on lit floor cells, hit sparks and cooling embers (`✦` `✧` `•`) for 0.35 s around a `damage_numbers` hit, and bubbles/drips/steam (`°` `◦` `○` `◌`) rising from the level's `EmitterKind` Steam/Drip/Fumes emitters and from a steam grate mid-plume. Glyph pickups and stippled light-pool edges are **not** built: the mock showed both lose to the pixel art. It writes **whole cells** (`cell.set_char`, fg = the cell's mean colour mixed toward the particle's tint, bg = the mean of the two colours the cell already had) into the ratatui `Buffer` in `App::draw_game` *after* the world picture is blitted and *before* the overlays, HUD, minimap and cursor. The guard is the mock's: only a cell still showing the plain `▀`, whose two pixels are within `EDGE_GUARD` 40 summed RGB, no cell within 2 of the rat's, and for motes a mean luma over 70 — a wall border, a plank seam or a digit is never collapsed into one flat cell. Motion is analytic in [`STEP_HZ`] 8 held steps off `World::elapsed` (motes are anchored to world cells and drift one cell sideways every 1.5 s and at most one up every 4 s; sparks move outward; bubbles rise a cell every 2 steps), from a hash of `(level seed, slot, step)`: no rng, no pool, no per-frame allocation, and exactly `MAX_GLYPHS` 48 cells a frame at most (`20` motes + `16` sparks + `12` bubbles, halved past 1.5× zoom). Nothing here touches the simulation, so no golden or map pin can see it; a frozen plate is bit-identical frame to frame. Drawn over the live or frozen playfield only — never over the Library, the title, or the `--ai` wall (which never comes through `draw_game`). Render-only.

**Hostile layer + ink pass.** Hostile pellets, telegraphs, tells, miniboss shapes and status pips are drawn **after** the lighting pass (self-lit, above every friendly effect) by `draw_hostile_layer`. Then `render/ink.rs` re-stamps gameplay-critical geometry **in screen space after the resample** with a minimum on-screen size: hostile marks only when zoomed out (`scale > 1.05`), loot markers at every zoom (square = coin, diamond = gem, bracket = pocket find, halo = chest), never doubled at 1×. Damage digits sit between the resample and the ink pass so they keep their pixel size. Both are render-only.

**The world picture is cached.** `App::draw_game` keys the pixel buffer with `PictureKey` (the run, `World::ticks`, the buffer size, the eased zoom and its target, the lighting setting/tier/depth, the hitbox and smoke toggles, the subcell set, the 1× smoothing, the foreground and light-effects switches and the camera's shake share) and calls `World::draw` only when the key moved or `picture_dirty` is set (discrete input, an open console, a screen change — things the key cannot see). The frozen field under the pause, level-up, options, Library, chest, shop and open-map plates is therefore drawn once, not once per frame. **Anything new that `World::draw` reads and that can change while the world is not ticking must go in `PictureKey` (or set `picture_dirty`)**; `app::tests::everything_that_changes_the_frozen_picture_redraws_it` is where to pin it. `World::ticks` is render-side bookkeeping: no system reads it.

`render/hud.rs`, `render/overlay.rs` (boss bar/warning/compass, low-health cue, callouts), `render/menu.rs` and the other screen modules are ratatui widgets drawn over/around the pixel viewport. Each screen's `layout()` is the single source of truth for its pointer hit rectangles.

## Levels

A level is a **200 × 160** lattice of 16 px tiles (3200 × 2560 world px) plus rooms, maze sections, level objects (traps, doors, rat-holes, shop holes, maze rewards, light fixtures, ambient emitters) and legacy props. `Level::tiles` is the **only** wall geometry: player, enemies, bullets, lobs, spawn checks and `art_walls::wall_colliders` all query the tile grid, so what is drawn and what blocks cannot disagree (`game/collision.rs::TileMap`). `game/nav.rs` keeps the fine window field and coarse block graph per size class.

**Six floors** (`Theme`): Sewer, Kitchen, Lab (the original route), Laundry and Printworks (side routes at stages 2 and 3), and the Flatbed trailer, the getaway ride, which is the campaign's **fourth and last level** (and always open as a practice floor). `Theme::all()` is the five generated floors; `Theme::playable()` is all six in route order.

`game/levelgen/`: `layout::build_layout` (rooms, corridors, halls, the far hall, start room) → `layout::furnish` (props) → `maze::carve_mazes` (at most one, ~1 map in 8, reward + one-way door at the end) → `placement::place_rat_holes` → `placement::place_traps` → `placement::place_shop_holes` → lights/emitters (separate salted rng over the finished tiles) → `validate` proves the map playable, and `generate` retries with a salted seed if it is not (a safety net, not a routine path). Deterministic from `(theme, seed, attempt)`, ~3 ms median in the dev profile (`RATRUN_LEVEL_TIMINGS=100 cargo test level_stage_timings`); distributions under `RATRUN_LEVEL_STATS`.

**There are no boss arenas** (batch twelve). The room the arena used to take is an ordinary far `Hall` (`FAR_HALL_*`), `strip_boss_arena` normalises the Flatbed's cab hold the same way, and `Level::boss_room()` is always `None` on a generated level (`BossArena`, `RoomKind::Boss`, `LightZoneKind::Arena` and the minimap's bearing art survive as inert seams). `Level::largest_hall()` is the "big open room" tests and captures use instead. The retry net still matters: about 1 first attempt in 3,000 fails validation (a furnishing over a two-cell corridor; it was 5 in 3,000 before).

- **Hazards**: `systems/traps.rs` — sticky glue boards (20 % speed, a limited glue budget, `Used` when spent; a body the board lets go is immune until it has walked off the pad — `StickySlot::freed` — so a crowd jamming it there cannot spend the budget twice) and baited mousetraps (`Armed` → `Triggered` 0.18 s → `Snapping` 0.20 s → `Sprung`; a **hair trigger** skips the warning and resolves on the touch tick). `systems/hazards.rs` — steam grates (Resting 4.0 s → Warning 1.0 s → Plume 0.7 s) in the Laundry, ink pads (permanent 75 % ground speed) in the Printworks.
- **Light fixtures** (`LightFixtureKind`) and ambient emitters (`EmitterKind`) are placed by `levelgen/lights.rs`; the renderer reads the same structs. **Sconces** (`LightFixtureKind::Sconce`, `place_wall_lamps`, run after every earlier draw of the stage so the hanging lamps and emitters are unmoved) are wall lamps: each sits half a pixel inside the floor cell in front of a `WallKind::Solid` face with at least two cells of floor before it, never on a rat-hole, door, shop hole or within three cells of a doorway or a hanging lamp, four cells from another sconce. `LightFixture::wall_facing` re-derives the mount from the grid (no stored facing), and the light is a 150° fan (`SCONCE_HALF_ANGLE` 1.31 rad) of 110 px into the room at `SCONCE_ENERGY` 2.35 (three times batch nine's) on the cached static path, so the wall behind it stays dark; a second small radial **wash** (`fixtures::sconce_wash`, `SCONCE_WASH_RADIUS` 26, sharing the fan's baked shadow, without the fan's flicker) lights the face it hangs on so the lamp reads as the source. `SCONCE_CAP` is 40; the order is the budget: the start room, corridors (their own rule: a straight wall of `SCONCE_CORRIDOR_RUN` 4 cells, two cells from a doorway), every other room/hall, then the rooms between. There is no arena ring any more. One in eight is spent (dark, sputtering); the rest flicker 3 % in held steps (`SCONCE_FLICKER_HZ` 3) because a continuous flicker repainted the pool every frame. The Flatbed gets up to `RAIL_LAMP_CAP` (8) rail markers instead. The map pin does not fold fixtures.
- **Shop holes**: two per level in structural wall faces; touching a threshold raises `pending_shop` and opens the shop screen.
- **Interactive objects** (`systems/gates.rs`): rat-holes (an 8 px gap the rat fits and a Cat/Brute does not; the rat is centred laterally), the maze cache (one free level-up + the fog/minimap claim), one-way doors and the exit slam. Enemies never pass a gate.
- **The Flatbed** (`systems/trailer.rs`, `levelgen::trailer`, `art_trailer`): pits in the bed (rat: 8 damage, i-frames, replaced on the nearest plank; horde: 35 % of max HP + stun), sliding cargo, the slipstream that drags small bodies and gems tailward, expansion-joint bumps, and the Magpie's gust wind.
- **Fog** (`game/fog.rs`, `systems/fog.rs`): a `Fog` resource round-tripped like the rest, flooded from the rat's cell through open floor and open doorways, stopped by solid walls, maze partitions, closed one-way doors and rat-hole faces (a hole is revealed by sight or by having stood in it). The minimap draws only seen cells; never-seen territory is the dim **red veil**.
- **Standing water** (`Level::puddles`, `levelgen::puddles`, `systems/puddles.rs`, `art_puddle`): the owner's "the sewer especially should be very wet, and the rat should make little splashing sounds when walking over". A `Puddle` is decoration with one gameplay hook — `Level::wet_at` — and never a tile: it cannot block, slow, route or be seen by the bot, the fog or the minimap. `Puddle::contains` is one shared irregular blob (`(dx/rx)² + (dy/ry)² <= edge(angle)²`, `edge = 0.78 + 0.22 ×` an eight-lobe integer-hash wobble) read by gameplay, art and lighting alike; `depth` ramps 0→1 over the outer 6 px for the soft edge. `levelgen::puddles` runs **last**, after the lights and emitters, on its own salted rng (`level_seed ^ PUDDLE_SALT`) over the finished grid, and writes only `Level::puddles` — which the map pin does not fold — so no earlier stage can move. Counts a map: Sewer 26–34 (large, biased 4:1 to corridors and wall edges, so a run of them merges into one long wet stretch; coverage is measured, aimed at ~18 % of the floor), Laundry 10–14, Kitchen 4–6 small spills; the Lab, the Printworks and the Flatbed have none. A centre is always an open floor cell, 40 px clear of the start and off every rat-hole face, door, shop threshold and trap pad. `systems/puddles.rs` (`puddle_steps_system`, chained right after `player`) pushes one `Sfx::Splash` per `STEP_PX` 11 px of **wet** travel plus one on entering water from dry, one `Sfx::SplashBig` per dash that touches water, nothing while standing still, and starts the ripples (life 0.45 s, at most eight) the renderer draws; the first six ordinary ground bodies in `SpawnId` order on screen in water ripple too, silently and at most every 0.5 s each (`PuddleSteps`, permanent scratch, keyed by slot so no component grows). It draws no rng, touches no entity and changes no simulated number — the rat is **not** slowed — so the goldens cannot move. The puddles are drawn right after the floor stains and before the boss ground layer, under `render::lighting::pool_pen()`, so lamps reflect in them.

## The fifteen-minute timeline

`game/director.rs` is time-curve based, not fixed waves: spawn rate, live budget, hp, elite cadence and speed all read `curve_clock(elapsed)`. **Which** body spawns is the floor's roster (`game/roster.rs`, the contract is `WAVE4_ROSTERS.md`): every floor has eight role slots — A ground fodder (0:00), B flying fodder (0:45), C chaser (1:15), I first trick (2:00), R shooter (3:35, cap 4), II second trick (4:30, cap 4), H heavy (6:35, cap 8; the floor's elite wears this body), III third trick (9:45, cap 3; I caps at 5, the Big Snake at 2) — and four fixed minibosses. `roster::pick_kind(theme, clock, caps, rng)` is **one** weighted draw over the slots in table order: a locked or capped slot has zero mass and its share goes back to fodder, so caps cost no retry and no extra rng. The spawn pulse counts live bodies per slot (`spawn::live_slot_counts`; elites and minibosses excluded, a Lilliputian squad counts once). All 48 ordinary kinds are registered (`EnemyKind::all()` is 49 with the legacy `Boss` body) and no kind appears on two floors, so no slot holds a stand-in (`RosterSlot::stand_in_for` is `None` everywhere; the field stays for a future floor). **The archetype seam:** `EnemyKind::archetype()` names the existing body whose steering, attack, nav size class and behaviour systems a kind reuses. Every *behavioural* decision in the simulation keys on `archetype()`; stats, name, colour, gold, XP, Library identity and art tint key on the real kind. The 33 wave-four registrations each name a base there until their floor's batch gives them their own rule (`roster.rs`'s module docs list which are pending). `RUN_SECONDS = BOSS_TIME = 900.0`. At `BOSS_TIME` the director raises `BossDue`; the boss **arrives where the rat is** (`boss_spawn_system`: the fight rectangle is `Level::fight_rect_around(rat)`, the nominal `BOSS_FIGHT_TILES` 34 × 28 cells clamped to the map; the body lands on the horde's own out-of-sight reachable ring, about 195 px off, drawn from the boss's rng; measured first damage 1–8 s later) and the horde drops to cleanup pace (1 body/s, budget 35) while the curve clock freezes. The live budget steps 18 / 42 / 72 / 115 / 150 / 185; per campaign level the horde's contact damage ramps to ×1.0 / ×1.6 / ×1.9 and its speed to ×1.0 / ×1.08 / ×1.15 by the boss (`LEVEL_DAMAGE_TOP`, `LEVEL_SPEED_TOP`), and ordinary hp carries `LEVEL_HP_EXTRA` ×1.2 / ×1.45 / ×1.7 from 3:00 (the boss pool does not). Horde and boss pools are also multiplied by `director::level_bonus_hp_at` (×1.0 at 0:00 → ×1.19 at 3:00 → ×1.55 at the boss): the weapon damage a typical rat's character level is worth at that minute, so the per-level bonus does not shorten a fight. **Batch twelve's build correction** sits on top: `director::BUILD_HP` (×0.60 at 0:00, 0.45 at 1:00, 0.30 at 3:00, 0.20 at 5:00, 0.16 at 8:00, 0.20 at 11:00, 0.28 at the boss) because builds hold a quarter of the cards, times `BUILD_HP_LEVEL` [0.8, 2.2, 2.4, 2.6] per campaign level (levels two to four arrive with a carried build), and the boss pool also takes `BOSS_BUILD_LEVEL` [0.75, 0.78, 0.57, 0.68]. The per-level tables have four rows (`LEVEL_HP_EXTRA` 1.2 / 1.45 / 1.7 / 1.9, damage top ×1.0 / 1.6 / 1.9 / 2.1, speed ×1.0 / 1.08 / 1.15 / 1.2). A level ends when the boss or the rat dies — the clock is not a win condition. The boss warning starts 25 s early (`render::overlay::BOSS_WARNING_SECS`) and reads `▸ <BOSS> IN <n>s · STAND YOUR GROUND ◂`; there is no arena bearing or compass to one, only the living boss's off-screen arrow. If the rat walks more than half a rectangle away, the rectangle is rebuilt around it on the boss's next neutral beat (`rat_left_the_fight`).

- **Named minibosses** (`systems/miniboss.rs`): four appointments at 3:00, 6:00, 9:00 and 12:00, the same four on a given floor every run (`roster::appointments(theme)`, read by `miniboss::schedule_for`). Twenty-four kinds (`MinibossKind::all()`), four per floor and none shared: the wave-3 six (Corkscrew, Sister Snip, Bobbin, Bell Diver, The Foreman, Milk Carton) plus eighteen from wave 4. HP by appointment is `miniboss::appointment_hp_for(level, slot)`: the full-build pools 4500 / 10700 / 14400 / 18100 times `APPOINTMENT_BUILD_SCALE` by campaign level and slot (level one 270 / 1498 / 2736 / 4163; levels two to four meet a carried build and are about half the full pools), measured 24 / 32 / 40 / 43 s by slot, signature damage 18 / 22 / 26 / 30, body contact `MINIBOSS_CONTACT_DAMAGE` 7.5 at `MINIBOSS_SPEED_SCALE` 3.0 (48 px/s), and a body-anchored row starts its tell from 0.7 × its own reach (`MinibossKind::engage_range`), never from farther than `ENGAGE_RANGE` 70 px. A cord row's tell is the whole swept sector (a `Cone`). Each has one signature (`MinibossKind::signature()`, a `MinibossShape` with its own numbers), a 1 s tell, an exposed recovery and a cooldown (`SIGNATURE_GAP` 2.6 s from strike to next tell). **The tell tracks, then locks**: until `TELL_LOCK` (0.5 s) the body keeps walking and the outline follows it, aimed at where the rat is heading (`aim_signature` leads by the frozen half of the tell); from the lock to the end of the recovery the body is planted (`Miniboss::holds`). A tell that locked on its first frame was outrun by any rat that kept moving. Eight shapes: Trench, Cone, Cord, RingGap, Stamps and Spill are shared evaluators that most kinds reuse with different dimensions; `Pincer` (The Mudlark's closing claws) and `Lane` (The Wringer Boy's paired rollers with an uncovered seam) are the new geometry. A miniboss is an ordinary `Enemy` (a `Brute` body) with a `Miniboss` component, so every damage pass treats it as one and the reap drops **exactly one chest plus `MINIBOSS_GOLD`** at a reachable non-pit cell, whatever killed it (the Nuke's re-reap included). A survivor retreats without loot when the next appointment arrives, so only one is ever on the floor.
- **The Growth Serum** (`PickupKind::GrowthSerum`, batch 13; `systems/powerups.rs`): a rare pocket find (4 in 100 of the pickup roll, one mousetrap bait in 13) that makes the rat a giant for `GROWTH_SECS` 20 s. The rat is drawn at `GIANT_SCALE` 5× (`World::draw_giant_rat`: the ordinary art rasterised 1:1 into a kept scratch buffer and blitted nearest-neighbour, growing over 0.4 s and blinking at 4.5× for its last 3 s; a live Spiked Tail lash keeps its ordinary size) and the view eases out to the widest rung and back (`zoom::giant_target`, render-only: the simulation reads neither zoom). Every `GIANT_STOMP_INTERVAL` 0.25 s `giant_stomp_system` crushes ordinary bodies inside `GIANT_STOMP_RADIUS` 30 px outright and deals `GIANT_ELITE_DAMAGE` 60 to an elite and `GIANT_BOSS_DAMAGE` 40 to a miniboss or a grounded boss (through the boss's own state and shell multipliers), credited to the Gnaw column; the giant takes half damage (`GIANT_DAMAGE_TAKEN`) and walks at ×0.9. `RATRUN_DUMP=giant` captures it.
- **Chests** (`loadout::open_chest`): evolve the earliest eligible weapon, else grant a free rank, else pay gold. No rng draw.
- **Bosses** (`systems/boss/`): one shared tick drives per-floor controllers. Ten kinds, pooled per floor and picked from a stable splitmix64 hash of the level seed (`BossKind::pool_pick`):

| floor | pool |
| --- | --- |
| Sewer | The Jungle Cat (Apex Jaguar), The Horseshoe (horseshoe crab) |
| Kitchen | The Sweeper (broom), SUBJECT R-01 (MegaRat) |
| Lab | TURF-REAPER MK.IV (mower), KING COBRA |
| Laundry | The Mangle (wringer) |
| Printworks | THE NIGHT EDITION (offset press) |
| Flatbed | The Magpie, The Redtail (hawk) |

  **Control and pursuit (batch 13, `boss/mod.rs`).** A player weapon can never take a boss out of its fight. A stagger is *control* and is paid from a shared budget: `Boss::grant_control(secs)` grants at most `CONTROL_BUDGET_SECS` 0.30 s per `CONTROL_WINDOW_SECS` 4 s (nothing under `CONTROL_MIN_SECS` 0.12), and **never inside a committed beat** (`Boss::committed`: any state that is not the kind's neutral, stagger or death state), so a wind-up always fires. `Boss::shove` moves a neutral boss at most `SHOVE_PER_HIT_PX` 4 a hit and `SHOVE_PER_SEC_PX` 12 a second and refuses a committed one. `pursue` runs before the controller: `Boss::out_of_reach` counts every second the rat is beyond `BossKind::engage_range()` (in any state; only a rat back in range resets it), and from `OUT_OF_REACH_SECS` 3.0 a neutral boss leaps (`LEAP_SPEED` 300 px/s for `LEAP_SECS` 0.30, `LEAP_COOLDOWN` 3 s, a body-passable straight line only) or sprints the flow field at `PURSUIT_SPEED` 132. The Jaguar closes with its own pounce instead (`own_gap_closer`; `CLOSING_POUNCE_MAX` 220 px), and the mower's lidar locks a rat it has *seen* during the scan even if it has backed out of `SCAN_CONE_RANGE` 72 by the snap (patrol band 45–64 px, a pursuit leap goes straight to the scan). No rng is drawn by any of it. `boss::tests`' scripted fights (`ScriptedFight`, one per weapon script) pin that every kind starts and completes attacks under the heaviest build.

  `BossController::tick` owns only transitions; `Boss`, `BossOutput`, `BossHazard`, `BossProjectile`, `move_boss`, `BossContext` (player state, arena, `TileMap` queries, large-class flow field) and the index-window rules are in `boss/mod.rs` — read it before touching a boss.

## Progression

- **13 weapons** (`WeaponKind::all`, `WEAPON_SLOTS = 13`): Gnaw, Cheese Spray, Squeak Nova, Spore Orbit, Tail Whip, Acid Spit, Tail Thrash (ACTIVE), Sonic Squeak (ACTIVE), Laser Eyes, Super Dash (DASH), Acid Rain, Hantavirus, Spiked Tail. **Super Dash is hold-to-charge**: with the weapon owned, holding the dash input fills a meter (`SUPER_DASH_CHARGE_SECS` 0.90 s at L1, −0.04 s a level) and the release fires — up to 2× the dash duration, +50 % swept radius and ×2.5 crossing damage at full; a release inside `SUPER_DASH_TAP_SECS` (0.15 s) is the ordinary dash, and without the weapon the dash is press-to-dash with no added latency. The App feeds the edges through `World::update_with_dash_hold` (`DashHold`); `update`/`update_with` pass `DashHold::NONE` and charge 0, where every multiplier is exactly ×1, so the goldens cannot see the feature. Damage/cooldown/projectile-count scale with level in `game/weapon.rs`; firing patterns live in the weapon systems. **Batch twelve gave each weapon its own shape.** Gnaw is a **bite**: no projectile, the nearest body within `GNAW_BITE_REACH` 34–40 px (it was 20–24; same damage and cooldown) (any direction on auto-aim, a 48° cone when aimed), both old darts' damage from level 4. Cheese Spray throws a short fan of slowing wedges. Squeak Nova is **one expanding ring** (`weapons::nova_ring`, `ActiveFx::nova_*`): each body is cut once as the front passes, Echo Chamber brings it back in for a second pass. Tail Whip is a **180° swipe in front** of the rat (`WHIP_REACH` 30–42). Sonic Squeak is a **forward cone** (`SQUEAK_CONE_HALF`) that lands on the press tick. Laser Eyes is **two beams closing inward like scissors** (batch 13): at every rank a pair starts on the two outer edges of the arc (60°–110°) and sweeps in over 0.26–0.34 s (`LASER_SWEEP_SECS`), meeting on the aim line at ranks 1–3 and crossing through to the opposite edges from rank 4 (`LaserFx::twin` now means "the pair crosses"); reach is the design row × `LASER_REACH_SCALE` 1.6 (54–86 px), clipped to the unzoomed screen's edge (see the Spiked Tail below). Both beams share one hit set, so a body still takes one pulse's damage (6–10) once per sweep, and Carbon Copy replays the same closing pair from the recorded place at half. Acid Rain lands as teal ripples, never a pool. The Spiked Tail's mechanic is unchanged (one targeted lash, a burst where it lands) with `LASH_REACH` 80–120 px, which is past the edge of a 120-column view at 1× — so both it and Laser Eyes are **capped to the unzoomed screen**: a lash target must sit inside the `Viewport` rectangle (inset 4 px, `weapon_spiketail::LASH_VIEW_INSET`) as well as inside the reach, and each laser beam is clipped where its ray leaves the same rectangle from its own origin (`approach::sim_view_ray_exit`), so `LaserFx::beam`/`beam_b` — what the art and the lighting draw — are the lengths the hit test used. Both read the per-tick `Viewport`, never the render zoom; it is drawn as a **render-only Verlet whip** (`art_rat::WhipChain`, 16 nodes joined by lines, fixed sub-steps, the tip pinned on the target through the crack). A floor-level melee, cone or ring only hits a boss that has a grounded hit shape. The Laser's beam, muzzle and sparks share one red-white palette (`vfx::LASER_CORE`/`LASER_GLOW`). The dash arc under the rat is gone (`art_rat::draw_dash_charge` draws only the Super Dash charge ring, and only while charging; the ink pass no longer stamps one); the HUD's dash module is the readout.
- **12 passives** (`PassiveKind::all`): MaxHp, MoveSpeed, Damage, FireRate, Magnet, Regen, Armor, SpringHeel, Counterweight, LongFuse, SecondScent, LensCap. `loadout::apply_passive_stack` is the single source of truth for a stack (the carried-loadout rebuild replays it).
- **13 evolutions** (`WeaponKind::evolution`): a chest evolves a max-level weapon whose partner passive the build owns (≥1 stack). An evolution keeps the kind, timing family and damage-ledger column and changes what the attack does: Milk Teeth (Gnaw), Fondue Fork (Cheese Spray), Echo Chamber (Squeak Nova), Fairy Ring (Spore Orbit), Ratchet Tail (Tail Whip), Drain Cleaner (Acid Spit), Flywheel (Tail Thrash), Roll Call (Sonic Squeak), Downspout (Acid Rain + Long Fuse), Dead Letter (Hantavirus + Second Scent), Carbon Copy (Laser Eyes + Lens Cap), Ripcord (Super Dash + Spring Heel), Barbed Wire (Spiked Tail + Counterweight). Every weapon has a row. Behaviour lives in `systems/evolutions.rs`; damage always credits the base weapon.
- **Slots**: distinct-kind caps `MIN_SLOTS = 4` … `MAX_SLOTS = 8` per rack, carried on `Loadout`. Read them through `Loadout::max_weapons`/`max_passives`/`loadout::slot_caps`, never the constants (`--caps` overrides them for a batch).
- **XP**: the fine curve is `player::base_xp_for_level(l) = round(6 × 1.10^(l-1))`, and since batch twelve one character level costs **four** of those steps (`xp_for_level`) after a three-card opening ramp of one, two and three steps (`OPENING_OLD_LEVELS`), so level-ups come a quarter as often: 6, 14, 27, then 50, 73, 106, … with no cap; the first card lands at about 17-19 s (it was 77 s on level one), about level 7 at 3:00, 10.5 at 6:00, 13 at 9:00, 15 at 12:00 and 16 at the boss, i.e. about 15 cards a floor where there were 55. **Every character level above 1 adds +4 % weapon damage** (`player::LEVEL_DAMAGE_PER_LEVEL`, no cap: level 14 is ×1.52, what level 53 was), composed with the build's `Stats::damage_mult` in one place, `Player::damage_mult`, which every weapon pass reads when it fires (pools, marks and evolved effects carry the damage they were fired with). The level restarts at 1 on every floor (`carried_player`), and so does the bonus; the level-up header and the pause readout print it. Builds are smaller on purpose (three or four weapons at low rank and two or three passive stacks by the boss); the pools were cut to match (`director::BUILD_HP`), and level one from a bare Gnaw is the hard part of a run (see the batch-twelve measurement in the bot section).
- **Level-up cards** (`Loadout::generate_choices`): up to three distinct cards — one owned rank-up, one new kind (the first level-up always offers a second weapon; later the evolution partner of an owned L4/L5 weapon is promoted), one anything-legal. Fallbacks, at most one each: `Bandage` (25 % max HP, hidden at full health) and `Purse` (`PURSE_GOLD`, 3 gold). Fewer than three cards is a legal answer. Auto-pick (`U`, persisted) takes each card with 0.4 s toast spacing; the first lands on the frame a manual screen would have opened, so the simulation and its rng see the same thing.
- **Gold**: coins drop from a per-kind chance × value table plus `ELITE_GOLD` (2), `MINIBOSS_GOLD` (12), `BOSS_GOLD` (30). A floor pays about 650 (measured: ~350 coins, ~150 elites, ~65 Purse cards, 48 minibosses, 30 boss); the per-kind chances in `shop::gold_row` are the design's cut to a third (batch six) and by a further ×0.72 (batch seven).
- **The in-run shop** (`game/shop.rs`, "the blind spot / gene splice shelf"): behind the mouse holes. Ten splices in two sockets (`MAX_SPLICES = 2`; they are neither weapons nor passives and never count against a cap, and **they last for the floor they were bought on** — `campaign::next_loadout` carries the weapons and the passive stacks and deliberately does not copy `splices`, so every new level starts with both sockets empty and its stats rebuilt without them). A shelf is three of them, rolled from `(floor seed, hole index, rerolls)` on its own rng. Services: Stitch (20¢, heal 35 %), Turn the Shelf (14¢, then 28¢), Molt (40¢, replace an upgrade with a fresh Lv1 of the same type). Splices cost 48–76¢ (`SpliceKind::price`; batch seven took a third off batch six's tripled prices) and apply *after* passives in `apply_splices`.
- **The nest** (`meta.rs`): 15 permanent tracks bought with banked gold (weapon/passive slots 4→8, move speed, pickup range, fire rate, max HP, regen, armor, damage, dash cooldown, XP gain, gold gain, luck, carry-over 3→5, one revive). Every number and price is in `Track`/`Track::prices` — retune there (the measured median run banks about 2,000¢, so the cheapest step, 240¢, is one run, the median track 6,600¢ is three to four, and the full Nest, 108,420¢, about 54; the batch report's `Nest:` lines print those three figures for any table). The profile is a field on `ScoreTable`, so it lives in the same save file. **Banking rule** (`meta::bank`): unspent gold plus `FLOOR_BONUS` 25 per cleared floor, `APEX_BONUS` 6 per boss/miniboss killed and `WIN_BONUS` 75 for the clear; a practice run banks half (rounded down); a run that used the console banks nothing; saturating throughout.
- **Campaign** (`game/campaign.rs`): **four levels**, Sewer → (Kitchen | Laundry) → (Lab | Printworks) → the Flatbed (`LEVEL_COUNT` 4; the ride's boss wins the run). A level completes when its boss dies. Between levels the keep-three plate lists the build in a stable order and lets the player carry up to `keep_limit(loadout)` (3 by default, +2 from the nest's carry track); `Tab` or a click picks the next stage's route. `level_seed(run_seed, index, theme)` derives each floor's map, so a campaign replays exactly. Practice runs play one floor alone on level one's scalars (`difficulty_override = Some(0)`; the Flatbed is always open for practice, `ScoreTable::floor_unlocked`) and do not advance the campaign. A three-level save migrates (`migrate_legacy`).

## Controls

`input.rs` is the raw layer, `controls.rs` the remappable layer over it, `gamepad.rs` the pad poller.

- **Three schemes** (`Scheme`): Classic, MouseAim, Gamepad. Each carries `Bindings` — a keyboard/mouse primary + alternate per action, and pad slots. `Controls` owns the active scheme, dead zone, rumble flag and cached legends, persisted beside the scores. `input.rs` resolves every action through `Controls::active()`, so a rebind takes effect everywhere.
- **26 actions** (`Action`, indexed by array position — the table is append-only): MoveUp/Down/Left/Right, Dash, FireActives, Pause, Map, MinimapSize, ZoomIn, ZoomOut, ResetZoom, ToggleCursor, Mute, MusicDown/Up, EffectsDown/Up, Options, Confirm, Back, AutoPick, Library, Nest, Quit, Reset. A save written before an action existed loads it at its default unless the player already gave that key to another action, in which case it starts unbound (`Controls::from_saved`).
- **Defaults** (`Bindings::defaults`): `WASD` moves (the arrow keys also steer, as a raw `KeyCode` fallback rather than a binding), `Esc` (alt `P`) pause, `Tab` map, `N` minimap size, `Z`/`X` zoom, middle click reset zoom, `C` cursor, `M` mute, `[`/`]` music, `-`/`=` effects, `O` options, `Enter` confirm, `U` auto-pick, `L` story/library, `B` the Nest (pause, incident report, victory), `Q` quit / back to the menu, `R` refund the Nest / reset a scheme. Every chip and legend that names one of these reads the live binding (`Controls::action_label`); screens without a `&Controls` are handed the key name. Classic and Gamepad: Ctrl dashes (alt left click), Space fires actives (alt **right click**; a save still holding the old left/left pairing is migrated unless the right click is already bound). **A right click is Back in every menu and on the open map** and never pauses play; closing the map with it does not also fire or dash that frame. MouseAim: right click dashes (alt Ctrl), left click fires actives (alt Space). Pad: d-pad/stick move, `RB` dash, `X` actives, Start pause, View map, `Y` cursor, `LB` mute, `RT`/`LT` zoom, `R3` reset zoom, `L3` minimap. **A right click is also Back in every menu and overlay** (`InputState::back_pressed` = the Back action *or* a right click), the expanded map included; it only ever activates a menu row as a *left* press, and in Classic/MouseAim play it is the actives/dash binding instead. **The dash has no read-out on the rat**: `art_rat::draw_dash_charge` draws only the Super Dash charge ring while a charge is held (the lane preview is under the rat, the cooldown/READY/refusal live in the HUD's dash module), and the ink pass stamps only the rat's two-pixel core — `render::ink` no longer draws a dash arc at any zoom.
- **The Ctrl caveat.** A lone modifier only reports under the Kitty protocol with `REPORT_ALL_KEYS_AS_ESCAPE_CODES`; `KeyboardMode::lone_ctrl` records whether it stuck. Without it Space dashes *and* fires actives (the old mapping) and the legends say so. The same limit decides who can **hold** the dash to charge a Super Dash: a key only where the terminal reports its release (otherwise a key press is always a tap), the mouse and the pad everywhere. Focus loss or a pad unplug cancels a held charge and never fires it. Held movement uses real key releases when the protocol answers, else a short auto-repeat grace window.
- **Gamepad** is behind the `gamepad` feature and read only while the terminal has focus (a pad in someone's lap must not drive a game nobody is watching). Tests inject `PadEvent`s, so no controller is needed.
- **Aim** is deterministic: `TickInput.aim` is an `Option<Vec2>` in world pixels from the pointer (MouseAim) or the right stick (Gamepad) when deflected. Classic passes `None`, so weapons keep nearest-enemy targeting. **The pointer is the cheese wedge in every scheme** (`render/cursor.rs`; there is no reticle): its tip is the pointer cell, which is the cell `App::aim_point` samples, it carries a dark keyline on its two exposed edges so it survives a bright effect, and in MouseAim play it does not fade while the keyboard moves the rat (`CursorInput::mouse_aims`). It is stamped in screen space after everything else and is not in `PictureKey`.
- The **Controls** screen (from Options) captures a key/pad/mouse press, swaps conflicts, unbinds and resets a scheme; `KeyBind::from_event` refuses Cmd/Super, most Fn combinations and `Ctrl+C`.

## UI screens

- **Title**: rat plate, START RUN, the sector row (all six floors), OPTIONS, LIBRARY, THE NEST, QUIT, plus a controls legend that names the live dash key. `Story` (the intro crawl) opens from `L`.
- **Sector select**: one card per floor with cleared/open/locked state and per-floor bests; picking a later floor starts a labelled **practice** run.
- **Intros**: `MapIntro` is level 1's access-route card; `LevelIntro` is the plate for later levels.
- **Playing**: the pixel viewport between a top and bottom HUD row, with the minimap (`MinimapSize`: Normal/Small/Hidden), the boss bar/warning/compass and the low-health cue from `HudState`. `Tab` opens the expanded full-level map (and pauses the simulation).
- **LevelUp**: 1-of-3 cards with icon, stat line and flavor line; `1`/`2`/`3`, arrows + `Enter`, or a click. Auto-pick skips it with a toast.
- **Paused**, **Options** (music, effects, minimap, cursor, mute, zoom, auto-pick, scheme, controls, dead zone, rumble, wipe the nest, graphics, back), **Controls**, **Graphics** (`render/graphics.rs`: the render-only picture settings, opened from Options' GRAPHICS row the way CONTROLS is — LIGHTING (the `lights` modes), LIGHT EFFECTS (`fx`), SMOOTHING (`smooth`), FOREGROUND, GLYPH PARTICLES (`glyphfx`) and SCREEN SHAKE (0 / 50 / 65 / 100 %, `World::shake_scale`). Every row cycles on ←/→, Enter, the wheel or a click, each goes through the same `App` method its console command uses, and all six are saved in `scores.json`'s `graphics` object — an old file loads today's defaults, and a `RATRUN_*` pin wins for the session without being written back until the player changes that row; stepping them never flags the run as console-used), **Chest**, **Shop**, **LevelComplete**, **KeepThree**, **Victory**, **End** (defeat or a finished practice run, with the incident report and bank tally).
- **Library** (`game/library.rs`, `render/library.rs`): four tabs — BESTIARY, ARSENAL, FIELD GUIDE, FLOORS — over one registry of `Row`s built from exhaustive matches over the game's enums, so a new variant cannot ship without an entry (`registry_is_complete` fails otherwise). Facts are read from the real tables, never retyped. Discovery is render-side (`Library::survey` reads the ECS world and the fog, writes only the Library), so it cannot move a golden. Locked entries show as `???`; `RATRUN_LIBRARY_ALL=1` unveils the index for captures. **The selected card is alive** (`render/library/scene.rs`): once the cursor has rested `REST_SECS` (0.15 s) on a catalogued entry, `LibraryUi::tick_card` builds a `LibraryScene` — a second, sandboxed `World` on a small walled patch with a god-mode rat, its own rng, a drained `SfxQueue` and cleared `pending_*` — steps it at a fixed dt from a per-entry script (`plan(Key)`: `Plan::Sandbox`, or `Plan::Still(reason)` for entries one plate cannot show: most passives, every splice and prop) and draws its real `World::draw` into the art plate; the loop restarts every few seconds. **Bestiary plates are portraits, not chases**: every plate is `flat_lit`, the rat is simulated but not drawn (`World::hide_rat`, render-only, also passed to the ink pass as `InkView::hide_rat`; only `scene.rs` sets it) and the card paints its own cork practice dummy where the rat stands. A body is staged on its home floor (`home_floor`/`miniboss_floor`, so the per-floor behaviour systems run) and by roster slot: A/B a pack crossing the plate after a hidden waypoint, C one chaser lapping a pipe stub or pressing at a rat-hole, R a shooter strafing at `SHOT_LANE` whose pellets end at the dummy, I/II/III the trick's own tell and strike on the dummy, H (and the Elite) the heavy lumbering in, minibosses one tell → strike cycle on a **fitted** plate (`Script::fit`: the camera centres on body + live footprint from `shape_bounds` and takes its zoom from them; past the ladder's 2.0, which `World::draw` clamps to, the plate is drawn oversized and box-filtered down like a boss plate), bosses their controller states. The dummy is painted **under** the picture: `floor_plate` re-renders the bare floor and `BareFloor` masks the cork to pixels the world's pass left as floor (a mask, not a colour test — The Mudlark's shell is the cork's colour). Flatbed cards stand on `deck_patch` (the real 200×160 map with only the bed open, because the deck art is map-anchored; its boss card adds a Boss room there so the arrival spawns on the card). Arsenal plates show the weapon at max rank with the rat left of three standing fodder targets 30 px in front (`ARSENAL_RING`, outside the 26 px radius that hides hit digits; `Script::lean` keeps them off the plate's edge), and the active weapons are held charged (`arsenal_cue`) so they fire several times a loop; an arsenal card only animates for a weapon the profile has **owned** (`render::library::catalogued`), `RATRUN_LIBRARY_ALL` alone shows the silhouette; glue board, mousetrap, steam grate, ink pad and slipstream are sprung by fodder, while the pit, cargo, rat-hole, doors, shop and cache keep the rat. `App::repaint_urgent` carries the card clock (`LibraryUi::frame_due`), so an animated card holds 30 Hz and a still, locked or silhouetted one lets the screen go idle. `RATRUN_LIBRARY_STILL=1` freezes every card. A scene is render-only: nothing in it can reach the run, a golden or the save.
- **The Nest** (`render/nest.rs`): the permanent-upgrade board, opened from the title row and — with the Nest action, `B` by default — from the incident report and the victory plate, read-only from the pause screen (no buying mid-run). Prices and the bank print the gold mark `¢`. Wiping it lives in Options and takes two presses.
- **Console** (`console.rs` + `render/console.rs`): backtick/tilde drop-down with line editing, history, Tab completion and 800 lines of scrollback; the `COMMANDS` registry (`help`, `god`, `noclip`, `give`, `spawn`, `boss`, `floor`, `seed`, `zoom`, `fps`, `hitboxes`, `lights`, `bank`, `nest`, …). Feature-gated on `console` and switchable off with `RATRUN_CONSOLE=0`. **Every state-changing command flags the run "CONSOLE USED"** (so does any run the console starts), which blocks high scores, campaign records, library counters and nest banking. `boss` and `miniboss` take display names as well as kind names, case and punctuation ignored and the article optional (`boss jaguar`, `boss apex-jaguar`, `spawn mudlark`; `boss_names`/`miniboss_names`, with Tab completion); `boss [kind] here` starts the fight beside the rat in the floor's arena rectangle recentred on it (`World::force_boss_here`, which shares `boss::open_fight` with the scheduled arrival) and refuses while a boss is on the floor; `spawn` also accepts a miniboss name. `pause` freezes the simulation only (menus still answer, the HUD shows a PAUSED chip) and ends when the console closes; `bank` and `nest` edit the saved profile and need a trailing `confirm`.

## Audio

`audio.rs` is fully procedural — no asset files. `AudioEngine::new()` returns `None` when there is no device and everything no-ops silently. The simulation never calls audio: systems push `Sfx` variants into `SfxQueue`, and the App drains and de-duplicates them per frame (a 16-shot nova is one sound) and sets music intensity. **Floor music is six songs** (`src/music/`), each a file of `(delta, midi, gate, velocity)` note tables plus a `Style` (`music::song_for(theme)` is the one theme → song table). **All six are arranged by hand from the owner's audio stems** (by a music worker working by ear, checked against the stems with a numpy copy of the synth): Sewer "Silent Return" (24 bars), Kitchen "The Great Dash" (24), Laundry "A Minor Waltz" (64 bars in 3/4), Lab "B–C–D♯ Warning" (16), Printworks "Platen Pace" (28), Flatbed "Rat on the Flatbed" (32). Edit those files directly and never regenerate them: `tools/midi2music.py` is the original MIDI converter, kept only as a tool, and its output would overwrite the arrangements. `Style` carries the per-song voice: the original mix/filter fields plus ten with neutral defaults in `Style::base()` (`pad_attack_ms`, `pad_decay_ms`, `pad_hp_hz`, `bass_decay_ms`, `lead_tri`, `lead_decay_ms`, `lead_bright_ms`, `lead_vib_depth`, `stab_decay_ms`, `enhanced_drums` — the last switches on band-passed drums, the open hat, woodblock/timpani and the one-pole bright voices). **`pad_detune` is a frequency ratio** on the pad's second oscillator, not cents: every song is ≤ 0.0045 (about 7 cents; 0.06 is a semitone, and the first tables shipped 0.07–0.20), pinned by `sewer_and_kitchen_have_v2_brightness_and_clear_pad_detune`. `SongSynth` sequences them on a 16th-note clock into procedural voices (24 voices, per-role caps, a limiter and a 0.50 ceiling) as an infinite `rodio::Source`. **It plays a 16-bit palette by default** (`Style::patches`/`drum_kit`/`mix_16`: 2- and 4-operator FM, wavetables, Karplus-Strong plucks, seven sampled-style drum kits, an echo send and a master low-pass; all buffers are allocated in the constructor; `Style::base()` is all `Patch::Chip`). `RATRUN_MUSIC` picks the backend (`AudioEngine::music_selection_for_env`): unset or `16bit` the 16-bit palette, `chip` the old chip oscillators on the same songs (bit-identical to the previous build), `classic` the pre-MIDI `MusicSynth`. About 5 ms of CPU per second of audio (it was 2). The `Arc<AtomicU32>` intensity (0..=3) gates layers: calm is bass, pad and light percussion; 1 adds drums and the arpeggio; 2 the lead; 3 everything plus an octave bass pulse on the beats the bass rests. The title and menus play the selected floor's song at the calm tier with a soft entry (`AudioEngine::play_menu_music` → `SongSynth::new_menu`: a 300 ms fade-in and two bars of bass and pad); the Victory plate plays the Flatbed song at tier 3; `RATRUN_MUSIC=classic` keeps `MusicSynth` everywhere. `--music-render <floor> <secs> <out.wav> [--intensity N]` writes a preview without a terminal, a device or the save (with `RATRUN_MUSIC=classic`, the classic synth). Volumes are 0..=100 in steps of 5 and persisted; `RATRUN_MUSIC_VOLUME`/`RATRUN_SFX_VOLUME` pin them for a session.

## Bot and batch tooling

- **`ratrun --ai [N]`** (`spectate.rs`): a wall of N (default 16, max 32) self-playing games on worker threads, each rendering a real `World::draw` into its own pixel buffer, with captions, outcome plates and a summary strip. No audio is ever constructed. Keys: `+`/`-` speed, Space pause, `1`–`9` or a click zoom a game, `Esc` unzoom, `R` restart the wall, `Q` quit. Flags: `--seed S`, `--skill expert|casual`, `--level 1|2|3`, `--once`.
- **`ratrun --bot-batch N`** (`autoplay/batch.rs`): headless seeded campaigns at full speed on `--threads` workers, no terminal, no render, no audio; prints win/clear rates with Wilson intervals, death causes, boss fight lengths, damage by source, boss DPS and timings (`--json` for the machine form). Flags that exist: `--seed`, `--level`, `--practice`, `--carry none|typical`, `--route <floor>` (a campaign takes that floor at its own stage, so `--route laundry` is Sewer → Laundry → Lab; with `--practice` it is the floor played, and `--practice --route flatbed` is the ride), `--skill expert|skilled|casual`, `--cycle-skills`, `--seed-exact`, `--max-sim-seconds`, `--threads`, `--analyze`, `--json`, `--trace`, `--caps W:P`, `--meta none|mid|max`. Companions: `--bot-compare a.json b.json`, `--bot-render a.json`. The report also splits gold by source, counts each miniboss's signatures started and landed, breaks each boss fight down by controller state (share of time, dps landed, distance), and `--json` carries every run's levels (`run_summaries[].levels`) so a mixed-skill batch can be split by skill. Determinism: run `i` uses seed `base + i` and the aggregate is built in run order, so identical batches print identically whatever the thread count.
- **`--caps` / `--probe` / `--glyph-card` / `--color <v>` / `--glyphs <v>`** are the terminal-capability flags (`term.rs`; see `TERMINALS.md`). `--bot-batch` is parsed *before* `--caps`, so the batch's `--caps W:P` never collides.
- **The bot** (`game/bot.rs`) is a test instrument: it reads the simulation (enemies, bullets, telegraphed boss hazards, trap pads, the tile map) and feeds `move_dir`/`dash` into `World::update`. Two layers — a 2.4–3.2 s waypoint plan and a per-tick 16-heading danger-field steer — with a per-skill reaction delay. Expert and Skilled look 0.48 s ahead; **Casual's horizon is 0.19 s** and its read of the crowd weaker (`CASUAL_HORIZON`, `CASUAL_CROWD`), and it reads a miniboss tell through its own coarse timer, so it leaves a warned shape late. A shop leg follows the bot's own flow field to the threshold (`shop_flow`), with a stronger goal pull than a waypoint's. It claims chests and picks upgrades through the same paths as the App. Measured ladder (48 campaigns a skill, batch seven): about 92 / 85 / 38 % wins. **Batch twelve (four levels, 16 campaigns a skill, seed 1000): 63 / 31 / 6 %.** Nearly every loss is on level one between 3:30 and 8:00: the bot kites, the starting Gnaw is a 20 px bite, and a rat that has taken eight cards has three low-rank weapons and no defensive stacks. Levels two to four clear at 91 / 86 / 89 % with kill counts and fight lengths on the old targets. Hit points cannot fix level one (its bodies are one or two bites each by 5:00); the levers left are the bite's reach, the first cards' cost, or teaching the bot to stand and bite. `--practice` on the bare loadout plays level one's scalars, as the App does.

## Where to add content

Every item has exhaustive `match`es that must be touched or the build fails. Grep the type name; do not guess.

- **Weapon**: `WeaponKind` (`game/weapon.rs`, append-only `all()`; `WEAPON_SLOTS` is asserted in tests) with stats, flavor, desc; a firing pattern in the matching `systems/weapons*.rs` (tag the bullet's `weapon`, emit `vfx::emit_weapon_fire`/`emit_weapon_hit`, pick an `Sfx`); the damage-ledger column is the kind index; an `art_icons` icon; the Library ARSENAL row.
- **Enemy**: `EnemyKind` (`game/enemy.rs`, append-only) — `base_hp`, `speed`, contact damage, xp, `gold_row` (`game/shop.rs`), radius/size class, `steer`, and its arm in `archetype` (the base body it behaves as; return `self` once it has its own state machine); behaviour in `systems/enemy_move.rs`/`enemy_wave3.rs`/`enemy_wave4.rs`; art in `art_enemy` (a kind without a row in `bespoke_body`/`bespoke_lod` draws its archetype recoloured through `recolor_body`); the death cue in `game/vfx.rs`; glue-board weight in `systems/traps.rs::enemy_units`; the bot's hazard knowledge in `game/bot.rs`; the damage-cause label and kind name in `autoplay.rs`; the Library BESTIARY row; and that kind's one row in its floor's `slots` table in `game/roster.rs`. Selection is `roster::pick_kind` (`director::pick_kind_for_theme` wraps it); the roster's module docs list the remaining exhaustive arms a new kind must satisfy.
- **Miniboss**: `MinibossKind` (`systems/miniboss.rs`) with `name`, `body_radius`, `active_duration`, one `signature()` row (a shared shape evaluator with its own numbers, or a new `MinibossShape`), its row in `MinibossKind::all` and art in `art_miniboss`; its floor's `appointments` row in `game/roster.rs`; `MINIBOSS_TIMES` if the schedule changes; the console completion table; the Library row.
- **Boss**: `BossKind` (append-only) with `base_hp`, `pool_for_theme` (plus the `*_POOL` const — a second exhaustive match), `for_theme`, the `art_boss_*` module (its view structs/state enums are the spec), a controller in `systems/boss/<name>.rs`, the controller dispatch, the `BossState` enum, smoke hooks in `game/smoke.rs`, name/`all`, console `boss` completion and the Library row.
- **Pickup**: `PickupKind` (`game/gem.rs`, appended after the three legacy kinds; eight today, the Growth Serum last) — `color`, `name`, art in `art_floor::draw_pickup`, effect in `systems/powerups.rs` + `systems/loot.rs`, the HUD callout, the STYLE glossary and the Library FIELD GUIDE row.
- **Floor/theme**: `Theme` (`game/level.rs`) — `stage`, `palette`, `all`/`playable`, boss pool, `levelgen::layout` furnishing, `levelgen/lights` and hazard placement, `art_floor`/`art_walls`/`art_props`, `lore::map_intro` + victory lines, the audio key/scale, `lighting::theme_ambient` and `lighting::fixtures::colors` (both exhaustive), the `render::campaign` plates, the Library FLOORS row.
- **Passive**: `PassiveKind` (append-only `all()`, asserted `[_; 12]`) — `name`, flavor, desc, `apply_passive_stack`, icon, card/keep rendering, Library row.
- **Splice**: `SpliceKind` (`game/shop.rs`, append-only `ALL`), price/bargain, `apply_splices`, the reader-only multiplier hooks, shelf/reroll logic, art, Library ARSENAL row.
- **Nest track**: `Track` in `meta.rs` (the level table and `Track::prices`), `RunModifiers` + its `apply`, the nest screen rows, and the profile's serde default.
- **Console command**: one `CommandSpec` row in `COMMANDS` plus a handler; set `read_only: false` if it mutates or the cheat flag will not fire. Arg kinds drive Tab completion.
- **Library entry**: a `Key` variant, one `all_rows()` row, and the `Key::category`/`Key::kind_index`/group `facts`/`dossier` arms — `registry_is_complete` fails until they exist.
- **New system**: `fn x_system(…)` in the matching `systems/` file, chained in `schedule.rs` at the exact slot (and added to the module-doc order map), plus a narrow test in the same file. **New resource**: define it in `game/ecs/resources.rs`; insert it permanently in `World::new` (scratch), or give it a spare twin and round-trip it in `begin_tick`/`end_tick` if the facade exposes it.

## Testing strategy

Everything runs without audio or a TTY (`cargo test`; the dev profile's `opt-level = 1` keeps full-run tests fast). The layers:

1. **Pure-logic unit tests** — math, collision, nav, director, loadout, scores, shop, meta, audio synthesis, damage numbers, term/palette.
2. **Per-system narrow tests** in each `systems/*.rs`: `begin_tick` → `ecs.run_system_cached(…)` → `end_tick`, then assert on facade caches or entity state.
3. **The ported suite** (`game/ecs/tests.rs`): thousands of headless ticks across themes and viewports, plus spawn/wall/cap/nuke/tie-order regressions.
4. **`TestBackend` end-to-end** tests (`app.rs`, `render/*`): the full App and render stack with simulated keystrokes, clicks and pad events.
5. **Gates**: `ecs/harness.rs` (determinism goldens) and `levelgen::tests::map_trace_pin` (map pin), plus the generator's cost and statistics measurements.

Construct `App::with_options(false, None, ScoreTable::default(), false, Some(seed))` (the test module's `test_app()`) / `World::new(theme, seed)` to stay silent and deterministic. **Never `App::new` in a test**: it loads and persists the player's real save. `ScoreTable::load`/`save` are additionally inert under `cfg(test)` unless `RATRUN_DATA_DIR` names a directory. Never assert on a golden whose failure output you have not read.

## Spinning up workers

When spinning up workers, use `/orchestration` to split the work across parallel child agents. They must show up under the **same workspace in Orca** as the coordinator, so the owner can tab-tile them in one window.

## Standing rules for workers in this repo

- **Workers do not compile or run tests.** Do not run `cargo` (build, check, test, clippy, run, fmt), `rustc` or `rustfmt` in a worker checkout. The coordinator merges the batch into the main checkout, compiles **once**, and fixes the breakage there. Write the tests you would have run and say what is unverified.
- **Finished workers are cleared from Orca.** Once a worker reports `worker_done` its subtask is deleted so the workspace stays readable. Do not leave work un-reported, and do not start new work after reporting.
