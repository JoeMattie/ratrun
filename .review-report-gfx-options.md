## Decisions I made

1. **`Screen::Graphics`** rather than an Options page flag (fewer exhaustive arms, no
   branching in the existing Options paths).
2. **The page sits over the title / frozen field** exactly as Options does, and
   `options_return` is inherited: Back here → Options → wherever Options came from.
3. **Labels are player-facing** (`STYLE.md`): `OFF`/`SOFT`/`SHARP` for the smoothing
   levels; the lighting tiers keep the console's names in caps because the task asked for
   the same values; percentages print without a space (`65%`).
4. **Enter opens the sub-page rows** (CONTROLS *and* GRAPHICS) and **cycles** a value row
   on the Graphics page — the task asks for Enter cycling, and the plate's legend already
   said `Enter open`.
5. **`SHAKE_SCALE` stays** as the default constant; `World::shake_scale` is the setting,
   and `PictureKey` carries it (a frozen picture can carry a live shake offset).
6. **The lighting preference is stored as a word** (`"full"`…) and `null` when the player
   never chose one, so a save round-trips to "the terminal's default" rather than pinning
   the depth of the terminal it was written on. `LightingMode` itself is untouched (no
   serde derive added to `render/lighting`).
7. **A `RATRUN_*` pin survives until the player changes that row**; changing any *other*
   row keeps the pinned field's saved value intact.

## Unverified / most likely not to compile

I could not compile, test, clippy or fmt (worker rules). Everything below is unverified:

- **`src/app.rs:4412-4431` (`save_graphics`)**: I moved `let lighting = self.lighting_mode();`
  above `let graphics = &mut self.scores.graphics;` because `lighting_mode()` borrows all
  of `self`. If the coordinator changes that order back it will not borrow-check. The
  remaining field reads inside (`self.smooth_env`, `self.glyphfx.enabled()`) are
  field-disjoint and should be fine.
- **`App::with_options`** now builds the glyph layer with
  `GlyphFx::default()` + `set_enabled(...)`; if the field order or names changed on the
  merged branch, that initialiser needs a look.
- **The 19-row Options note** is a rendering behaviour change (a row was added); the test
  was updated to match. Worth eyeballing `RATRUN_DUMP=options` at `57x20`.
- **Formatting**: no `cargo fmt` was run. The long signature of
  `render::graphics::step_lighting` and a few assert lines are hand-wrapped; `cargo fmt`
  will reflow them.
- **New tests may need timing/behaviour tweaks** — in particular
  `the_graphics_page_answers_the_pointer` (a right click while a row is selected: my page
  treats `back_pressed` before the click, which I believe matches `update_options`), and
  the env-pin test, which mutates process environment under its own
  `GRAPHICS_ENV_LOCK` (other tests read these variables in `App::with_options`; that is
  the same exposure the existing volume-env test already has).
- The dump arm uses `options::GRAPHICS_ROW`; if another agent reorders the Options rows,
  the `graphics` capture follows the constant (not a hard-coded 12).
