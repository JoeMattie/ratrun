## Decisions I made (all render-only)

1. **No `world.rs` edit.** `World::draw_scene` already passes `elapsed` in
   `ForeScene`, so the single call site is unchanged.
2. **Sky items are not world-anchored in the vertical axis.** A `depth` of
   1.8–3.0 on a map-anchored y is off screen unless the camera is at that edge,
   so the wires/pole/branch are *pinned to the view* (`SKY_PINNED_DEPTH` 1.0,
   world pos derived from the camera) and clouds are distant
   (`SKY_CLOUD_DEPTH` 0.15) in bed space — which also gives their floor shadow
   the offset the depth cue needs. This is a deliberate departure from the
   `1.8..=3.0` depth band for `Attach::Sky` only; placed items use 1.8..=3.0.
   The sky's *event schedule* is still a pure function of `(seed, elapsed)`.
3. **Coverage** is enforced with the hard writer budget at 30 % (`COVERAGE_SKIP_PCT`)
   and the 22 % line as the full-alpha threshold, i.e. the grace band is real and
   no single huge item can blow past 30 %. `COVERAGE_PCT` is still 22.
4. **Flatbed room placement.** `Cloud` never fits a room (its class is `Sky`),
   and Flatbed has no `Drop` kind, so outdoors only `Span` (PowerLine) and
   `Edge` (TreeBranch) fit a room; the sky tracks add the movers on top.
5. **Corridors have their own span minimum (coordinator's decision, applied).**
   A room Span must measure `SPAN_MIN_PX` 64 px, but a corridor cross-span is
   measured against `CORRIDOR_SPAN_MIN` 28 px (`span_across` now takes the
   minimum as an argument: corridors pass 28, rooms pass 64). The generator's
   corridors are 1–3 cells across, so a 1-cell corridor gives exactly
   8 + 8 + 12 = 28 px and a 2-cell one 44 px; without this the corridor rule
   placed nothing at all. A fat pipe/beam crossing the passage overhead is the
   look asked for. `every_span_ends_inside_a_solid_wall` still holds for the
   short spans (a 28 px span ends 6 px inside each 16 px wall).
6. Sway is on `PotRail`, `HangingLamp`, `Clothesline`, `HangingProofs` (the
   ones the kind list annotates `(sway)`) plus `TreeBranch` (leaf flutter).
7. `MAX_ITEMS`/`MIN_SPACING`/keep-outs are private consts; the tuning constants
   the contract names are `pub`.

## What is unverified / likeliest not to compile

- **Everything**: no `cargo`/`rustc`/`rustfmt` was run (blocked here).
- **Cross-file, blocking until merged**: this worktree still has v1's
  `src/game/art_foreground.rs`, which matches on the deleted v1 kinds
  (`PipeRun`, `Grate`, …). The crate will **not** compile until the art
  worker's v2 file lands; the two files must be merged together.
- Cross-file assumptions the art must honour (if the art worker read the
  contract differently these break at runtime, not at compile time):
  `extent()` is the half-extent in world px **already including `scale`** and
  must **not** multiply `len` (a span's long axis is drawn as measured, so its
  ends land inside the walls); `draw` paints the floor shadow at `d.shadow`
  first (the code no longer draws shadows itself); a Drop draws its cord
  `DROP_TAIL` = 400 px up-screen; clouds cap their own body alpha at 60 (the
  code also caps `d.alpha` there); the rim uses `d.toward_centre`.
- Risk of a red test if the art's `extent` for `MainPipe` is short: the fade
  test asserts the body's half-length > 96 px for `len` 400.
- `corridor_cross_spans_use_the_smaller_minimum` asserts that at least one
  corridor cross-span shorter than 64 px exists over 12 Sewer seeds; if a level
  batch ever lost its narrow corridors that assertion (not the code) is what
  would go red.
- `sway_of`'s quantisation is unchanged; if the v2 art ignores `sway`, the
  still-frame test's "the sway step moved nothing" assertion would fail.
